# 判据设计法则

> 这一页不是"风格建议" ✗ —— 它记的是**今年真实翻过的车** ✓。每条都有实例、都在代码注释里指得出。
> 读它的收益：**写新判据时不重犯** ✓；看别人的判据时**知道该问什么** ✓。

---

## 一、总法则

> **判据说的、判据看的、判据喂的，必须同指一件事。**

它有三个面，各有真实事故：

### 面① 读入参 vs 读环境

| 实例 | 病灶 |
|---|---|
| `readKey` 丢 `pc` | 从**环境**取当前角色 ✗，而不是用**调用方入参** ⇒ 换档/合成角色时判据判的是别人 ✓ |
| 写侧 `applyYields`/`applyGrants`/`applySets` 无视入参 | 同族：效果落到**当前档**而不是**被驱动的档** ✗ |
| `Game.Social?.asks` 环境回落 | 引擎在**契约不可得**时回落到环境 ⇒ "两宿主同源"这条主张被悄悄破坏 ✗ |

**问法**：这个判据/函数的输入，是**参数**还是**它自己摸到的全局**？两者不一致时，它相信谁？

### 面② 声称 vs 覆盖

| 实例 | 病灶 |
|---|---|
| `#806` 声称"静态＋动态 import 都挡"，实只挡静态 | 声称 > 覆盖 ⇒ **下一个人按声称去信它** ✗ |
| K6 ② 声称"壳不许写故事文件"，只扫两个文件 | 覆盖小于声称 |
| K6 ③ 声称"浏览器安全"，只挡 Node 侧 | 同一件事的另一半没人守 |
| L1 旧口径只扫 `cli＋host` | 同上：**覆盖小于声称** ⇒ 改成扫全部 `editor/**` 后**不再依赖路径形状** ✓ |

**问法**：判据的名字/报文里承诺了几件事？代码真的查了几件？**声称与代码不符，比漏一个形更坏** —— 漏形是"没守到"，声称错是"以为守到了" ✗。

### 面③ 观测对象 vs 遮蔽口径

**这是最容易撞的一面** —— 因为**同一个文件里可以有多种相反设置，而且都对** ✓：

| 判据 | 观测对象 | 遮蔽口径 | 为什么 |
|---|---|---|---|
| **L1** 原语写只许在 `lib/host/**` | **代码里的调用** | **遮字符串** | 字符串里写 `writeFileSync(…)` 只是**片段**（本门自证用例正是如此 ✓）⇒ 不遮会**自咬** ✗ |
| **L1′** 删除原语不许落 `stories/**` | **调用参数里的字符串** | **不遮** ＋ 查"调用位置在引号外" | 参数**就是**字符串 ⇒ 遮了就把**观测对象自己**遮掉 ✗；而"字符串里的提及"用 `outsideQuotes` 排除 ✓ |
| **③a** 内核不许 import 宿主模块 | **说明符**（`'node:fs'`） | **不遮** | 说明符住在字符串里 ⇒ 遮了什么都看不见 ✗ |
| **③b** 内核不许碰宿主全局 | **标识符用法** | **遮字符串** ＋ 只看用法（`名(`／`名.`） | 提及≠用法：core 会**合法地**在字符串与正则里提 `window.` ✓ |

**判法**：先写清"**这个判据要看的对象是什么**" ✓，再选遮蔽口径 ✓ —— **口径服从观测对象** ✓，不是"统一口径" ✗。

## 二、由总法则推出的操作纪律

1. **判据的边界由理由定，不由"看起来像"定。**
   > **判据只判它该判的** ✓ —— 范围**窄**不是缺陷 ✓，**宽到理由之外才是** ✗。
   - 例：L1 的理由是"故事文件的**写**只有一条路" ⇒ 把**删除**也做成路径无关 ✗ 会连 `rmSync(tmpdir())`／`rmSync('build/generated')` 一起咬 ✗（门会被关掉）⇒ 删除另立 **L1′**，只判落到 `stories/**` 的 ✓。
2. **不假装覆盖：边界要写出来，并写理由。**
   - 例：L1′ 明记"**运行期拼路径的删除不在覆盖内**" ✗（要收它得做数据流分析，成本高收益低）；K6 ③b 明记"引号未闭合（非法 JS）那形会漏" ✓。
   - 边界**写出来**＝下一个人知道该不该信它 ✓；**不写**＝把"没守"伪装成"守住了" ✗。
3. **新增/改动判据时，必须有一条只对"分支"敏感的用例。**
   - 因为：**多分支写出同一结果时，结果类判据全都沉默** ✗。
   - 活标本：`--out=stories/mist-forest`（相对路径）没走进"包内"分支 ⇒ 对拍不报 ✓ 逐字节不报 ✓ 只有**分支断言**能抓 ✓。
4. **自证要双向。**必红（真用法 ⇒ 报 ✓）＋ **必不红**（字符串里提及／属性访问／通用全局／边界形 ⇒ 不报 ✓）。
   - 只有"必红"一半的自证 ⇒ 下一次扩表会**误报一片** ⇒ 门被关掉 ✗。
5. **登记物/签名只描述既成状态。**
   - 顺序恒为：**状态先变 → 再剪登记/白名单 → 再重签** ✓；重启（rebase）时**重签提交丢弃**、落地后重签一次 ✓。
   - 理由：登记物是**记录**，不是**驱动** ✗ —— 让它先动＝让判据去迎合它 ✗。
6. **先落"不改变行为的加法"。**
   - 纯新增 → 再落会生效的块 → 最后删旧路径 ✓；动作按**行为可见性**排序 ✓（这样每步都能单独验证"没变行为" ✓）。
7. **自证必须能红，且计入退出码。**
   - 自证红而主跑绿 ⇒ 门是**装饰** ✗。

## 三、怎么用这一页

- 写**新判据**前：把"说的/看的/喂的"三句话各写一行 ✓，对不上就先改设计 ✓。
- 看**别人的判据**时问三问：①输入是参数还是环境 ✓ ②声称与覆盖是否一致 ✓ ③观测对象与遮蔽口径是否匹配 ✓。
- 撞到新的一面：**给它命名、写实例、留纸** ✓ —— 没名字的教训会被重犯 ✗。
