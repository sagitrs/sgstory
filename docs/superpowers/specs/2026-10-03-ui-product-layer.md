# UI 产品层：阅读交互与故事级定制

References #1939

**状态：Draft 设计提案，未实现。** 本文中的新接口、文件和验收项均为建议，不代表现有 API 或已经通过的测试。开发顺序见[实施计划](../plans/2026-10-03-ui-product-layer.md)。

## 1. 目标与观察基准

目标不是给巴别之井补几条 CSS，而是让引擎提供一套可靠的默认界面，同时让不同故事能正式配置资源栏、主题、背景与专属面板。

本次静态阅读的引擎基准为 `864f0518278eaed9cba0a9203409f60b396edaa3`；books UI 基准为 `03b1b8f5159c04fedc6cf9e8586ec1435b4ce3a9`。这两个基准不等于试玩产物 `v0.0.1·a7f2a9b3`，不得混用为复现版本。

现有能力与缺口：

| 已存在的基础 | 本方案补充什么 |
|---|---|
| [perform 的输出缓冲](../../../src/core/01-perform.js)、[choice 的异步选择](../../../src/core/02-choice.js) | 输出批次与阅读行为的契约，而非仅等段落挂载 |
| [三个宿主端口](../../../src/core/ports/index.js) | 在现有渲染、生命周期与持久化接缝上接入 UI，不新增第四个领域端口 |
| [面板注册与局部刷新](../../../src/core/72-panel.js) | 标准布局、受支持的面板扩展与交互态保留 |
| [books 面板写回](https://github.com/sagitrs/sgstory-books/blob/03b1b8f5159c04fedc6cf9e8586ec1435b4ce3a9/stories/babel/src/ui/panels.js)、[故事样式](https://github.com/sagitrs/sgstory-books/blob/03b1b8f5159c04fedc6cf9e8586ec1435b4ce3a9/stories/babel/src/ui/ui.twee) | 从低层接线升级为故事配置、主题变量和区域扩展 |

“文字出现前视口提前下移”是操作者反馈，尚未专项复现，本文不预判具体根因。已测存档与状态问题及覆盖限制见 [books 试玩结论](https://github.com/sagitrs/sgstory-books/issues/197#issuecomment-5971116586)。

**不做的事：** 重写规则数学、GameSession、命令结算或存档 schema；修改 SugarCube vendor；一次性迁移全部故事；立即加入打字机动画、纸娃娃或复杂资源下载系统；把本设计当成 0.0.2 发布验收。

## 2. 分层与事实来源

沿[现有架构的 L0–L3 方向](../../arch/sgstory-arch-review.md)推进：

| 层 | 职责 | 禁止事项 |
|---|---|---|
| L1 领域内核 | 游戏事实、动作可用性、消耗、结算、取消语义 | 新增 DOM、CSS、滚动或字体逻辑 |
| L2 规则包 | 提供公开的资源和动作读数，计算预计效果 | 为 UI 再维护一份伤害、恢复或成本公式 |
| L0 宿主表现 | 公共 UI 组件、SugarCube 挂载、焦点、滚动、存档浏览器接入 | 硬编码巴别之井的属性、槽号、地图或剧情 |
| L3 故事内容 | 选择资源与面板、绑定公开事实、主题和场景背景 | 借主题绕过命令或存档限制 |

公共组件先落在 SugarCube 宿主包内，便于复用当前构建包装；纯配置校验、布局决策与只读模型转换可独立测试。不因 UI 专项再启动一轮内核拆域。

每次呈现读取一份只读 ViewModel（展示模型），正文结果、资源、背包和行动可用性都来自本次已提交的事实。渲染不得重跑进入场景、领取奖励或执行动作；不得从日志文字逆向解析体力和敌情。

游戏事实由现有持久化契约管理。展开状态、阅读锚点、选中的背包页签属于临时 UI 状态；字号、动效等偏好单独按故事标识存储，不混入游戏存档，也不保存 DOM 引用。

## 3. 默认界面与移动布局

桌面线框（视觉方向，不是最终稿）：

```text
┌ 地点/楼层 ─ 体力与异常 ────────── 快存 / 存档 / 设置 ┐
│                                                    │
│  场景标题与氛围背景              背包 / 装备 / 记录 │
│  正文与本次行动结果               按需展开的辅助区  │
│  可回看的旧内容                                    │
│                                                    │
├ 当前行动：主操作 / 次操作 / 不可用原因 ────────────┤
└ 保存反馈、短通知；不遮正文、不抢焦点 ──────────────┘
```

手机线框：

```text
┌ 地点 / 关键资源          快存 / 更多 ┐
│ 场景标题                            │
│ 正文与行动结果                      │
│ “有新内容，跳到最新”按需出现        │
├ 当前行动                            ┤
└ 背包 / 记录（打开抽屉，不挤满正文） ┘
```

默认沿宿主页的主阅读滚动面，不额外嵌套第二套正文跟随逻辑；抽屉可独立滚动。固定行动区必须预留正文空间并处理安全区，不能盖住最后一段。抽屉关闭后恢复合理焦点。探索、战斗、失败可以选择不同面板，但系统入口位置保持稳定。旧战报可折叠，最新行动结果仍可读；详细骰点保留回看，不默认淹没正文。

## 4. 输出、滚动与焦点契约

**输出批次**是“当前一轮需要展示的正文、状态与选项”，不是整个异步场景或整场战斗。批次包含会话标识、生命周期纪元、递增批次号和目标区域。

生命周期为：准备 → 挂载 → 提交本批内容与状态 → 展示完成；离开、读档或重开可转入取消。只有完成当前批次后，才执行该批次的阅读定位；旧批次不得向新场景落屏。

“展示完成”不等于收到 `:passagedisplay`：异步正文可能尚未生成。它也不等待所有背景和网络字体下载完毕；图片预留尺寸，字体有回退，装饰资源失败不阻塞游玩。首次布局测量与后续资产变化都不得产生第二次强制定位。禁止用固定延时假装就绪。

| 事件 | 视口策略 | 焦点策略 |
|---|---|---|
| 进入新场景 | 本批正文就绪后定位到开头，不直接跳行动区 | 键盘导航需要时定位标题；指针操作不强抢焦点 |
| 同场景追加 | 原本在末尾时跟随；回看时保持锚点并提示新内容 | 不随战报移动 |
| 资源/背包局部刷新 | 保持阅读位置 | 同语义控件仍存在则保留；消失时选择合理后继 |
| 打开/关闭弹窗 | 不无故滚动正文 | 弹窗内管理焦点，关闭后归还原入口 |
| 读档/重开/离开 | 丢弃旧批次；恢复有效锚点或新场景开头 | 不恢复指向旧页面的节点 |

键盘焦点不是滚动位置，必须分别处理。控制器使用 LifecyclePort 的公开有效性信息，不另造时间戳纪元、不调用私有 token 工厂；若现有契约不能满足取消，需要先评审接口扩展并同步实现与测试。

兼容 `perform` 的链式返回、`choice` 选择成功时的 `Promise<string>`。旧选择取消必须明确结束等待，并由场景接缝处理取消结果；不能伪造空选项或留下永不结束的 Promise。具体取消结果形态在接入前冻结。

## 5. 故事级配置与扩展

三档能力：配置选用和排序；主题控制字体、颜色、间距、背景；组件扩展只在声明的区域注册。布局区域使用稳定名称，不要求作者依赖 SugarCube 内部选择器。

以下全部是**拟议接口**；`babelUI.readModel` 是拟议的故事桥接函数，不是现有符号：

```js
setup.RPG.ui.configure({
  schema: 1,
  profile: 'babel-reader',
  preset: 'reader',
  readModel: babelUI.readModel,
  resources: [{ id: 'hp', label: '体力', view: 'meter' }],
  panels: ['location', 'trauma', 'inventory', 'notice'],
  systemActions: ['quickSave', 'saves', 'settings'],
  reading: { follow: 'if-near-end' },
  theme: 'babel-well'
});
```

`readModel(context)` 读取公开事实，返回资源、位置、已知状态和动作描述；控制器按会话与 UI 根节点持有自己的临时态，不把所有实例放进一个全局可变视图缓存。资源读数形为 `{value: number|null, max: number|null}`，`null` 表示明确的未知值，行动描述包含稳定 id、文案、可见性、可用性、原因和可读消耗；执行仍走现有领域入口。

资源规则：

- 未配置 MP：不生成 MP 控件，不留空格，不访问其读数；不能只用 CSS 藏一条固定蓝条。
- 配置 MP 且值为零：仍显示零；未知值不能伪装成零。
- 上限为零或未知：不用除法生成比例，转为明确的数字或未知读数。
- 可见条件由故事的知识与状态策略决定，不自动暴露未发现事件和敌人资料。

启动校验覆盖 schema、重复 id、未知面板/主题/动作、资源描述和读数类型。配置错误具名失败，运行期读数错误可见且可诊断，不能静默返回正常零值。图片加载失败属于可恢复资源错误，有独立 fallback。

复用 `registerPanel`、通知与道具能力：兼容桥把已注册面板 id 映射到新 UI 的受控区域，保留刷新计数；不让同一次事件同时刷新新旧两套界面。专属组件只更新自身区域，按稳定语义键保留展开与焦点，不按列表序号配对。

阅读偏好优先级为：引擎默认 < 故事主题 < 玩家字号/对比度/减少动效偏好。偏好变化不影响规则数值或行动消耗。

## 6. 系统操作与存档接缝

快存放在常驻系统区，不混入剧情选择。保存不消费当前等待中的剧情选项，不重新进入场景；读档与重开会取消旧选择。成功反馈包含地点与时间，失败说明原因，不靠正文跳转提示。

系统操作描述与最终执行消费同一权威策略：UI 的禁用只改善体验，实际保存前必须再次检查。新工具栏、键盘入口和内置存档浏览器不能各写一份判断。

槽位按角色命名，而非要求玩家记编号。故事提供保留槽角色清单，适配层负责呈现与普通写入限制。对于巴别之井，角色值来自现有 `setup.BABEL.槽位`，通过故事桥接转换；通用引擎不得直接依赖 `BABEL` 或内置 `[3, 4]`。

**推荐默认 UX：** 保留槽显示用途且禁止普通手写；仍可按策略读档。若故事明确允许手写，则每次存在覆盖风险时确认，取消后不变。手动槽仍可用，不能禁掉整个保存面冒充保护。

这项与 [sgstory#1938](https://github.com/sagitrs/sgstory/issues/1938) / [sagitrs/sgstory-books#210](https://github.com/sagitrs/sgstory-books/issues/210) 合流，而非重复实现或改派；若 #1938 的最小修复先落地则优先复用。本提案不改其既定排期、不擅改宿主自动档配置。具体策略接缝先与该修复对齐。

背包默认可查看详情和明确的装备/使用操作；可为低风险道具配置快捷执行。恢复量、耐久、回合成本读领域接口，不在 UI 重算。战斗内使用不得绕过战斗行动入口。

## 7. 巴别之井主题与资源边界

初稿采用低对比石壁、纵向微光、冷灰与少量暖铜色；温泉偏暖，营地强调安全感。正文区域维持高可读性。不是所有故事都强制使用图片背景。

排版初稿：桌面正文 18–20px，手机 17–18px，行高 1.75–1.9；桌面正文约 28–36 个汉字宽；操作与数值使用清晰的无衬线字体。最终数值以阅读走查调整。玩家放大时不锁死布局，触控目标初稿不小于 44×44px。

主题通过带命名空间的变量与组件样式生效，不全局重写所有 `a/button/p`，不破坏宿主弹窗。状态不能仅凭颜色区分，保留焦点指示、减少动效与读屏语义。

首个版本用 CSS 渐变/纹理即可建立身份，不要求先下载第三方字体和全套插画。后续资源有尺寸、来源/授权和降级声明；离线单文件形态使用内联或打包资源。外部资源缺失时仍能阅读和操作。若扩展构建资源清单，单独提构建改动，不把下载系统混进第一条纵切。

## 8. 迁移、合流与待定事项

先以显式 profile 启用新 UI，缺省保留 legacy 模式。故事新模式激活后只有一个 writer 和一套事件订阅；销毁会撤监听、取消批次、清临时态。旧 footer 与旧宿主控件不能靠全局 CSS 静默隐藏，要由适配配置决定启用或停用。

当前 RenderPort 是旧 perform 的薄包装，不能把 perform 改成调端口后，端口又回调同一公共 perform，形成递归。接入时将宿主落地收口为私有实现，公共入口单向委托，输出与通知只记录一次。

沿用 [sgstory#1798](https://github.com/sagitrs/sgstory/issues/1798) 的能力基础，生命周期与 [sgstory#1753](https://github.com/sagitrs/sgstory/issues/1753) / [sgstory#1905](https://github.com/sagitrs/sgstory/issues/1905) 对齐，刷新与 [sgstory#1861](https://github.com/sagitrs/sgstory/issues/1861) 对齐。本 UI 计划不等待所有长期重构，但旧等待不能安全取消的接缝在解决前不得切换新模式。

实施前待定：批次完成/取消的公共结果形态；“接近末尾”的阈值；主题和资源是否需要扩展构建清单。这些必须通过原型与调用点核查决定，不以任意延时、私有 API 或新持久化缓存填补。

[sagitrs/sgstory-books#197](https://github.com/sagitrs/sgstory-books/issues/197) 的发布质量门保持独立。本 Draft 的合入最多代表设计获采纳，不代表任何 UI 行为已实现或发布验收通过。
