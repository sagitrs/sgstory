# 故事面范围：**必需**／**可选**／**不做**（口径文件）

> 为什么有这一份：编辑器的"可选面清单"、新故事接入时"该声明什么"、以及"哪些东西我们**故意不做**"，
> 此前只散落在 `docs/engine-story-boundary.md`（契约形状）、`editor/escape-hatch.json`（本故事不接的面）
> 与各票的评论里。这份文件把**判断口径**单独钉住，供三处共用：编辑器暴露哪些面、复核席怎么判一条
> 声明该不该在、以及**"不做"要写成显式条目**而不是口头约定。
>
> 本文件回答的问题是：**对一个网页文字冒险游戏，什么面是必要的、什么面不是**（地图与 BGM 不必要）。
> 形状与判据的来源是本仓既有机制（见 §五），不是新造。

## 一、三条问句（每个"面"都过这三关）

1. **内容侧**：作者（与编辑器）**需不需要把它说出来**？说得出来才有"面"。
2. **运行时或工具链**：产物里（或在构建期、门里）有没有**真正的消费者**？
   本文件的判据：**一个面要有人读才算数**。读者可以是运行时（引擎、渲染层），也可以是工具链（构建、审计门、测试）；但**写清楚是哪一种**，并不得把“声明了却没人读”算作拥有。
   真实落点（可核对）：`docs/dev-conventions.md` 第 3 节规则 2「**只有写没有读**的键＝红；确属『仅记账』（消费者就是登记表本身）的键必须显式标注」（只说的是“有读”这个必要条件），以及该文件「产物依赖面」那张「产物｜生产者｜消费者」表的用法（它把**测试与报告脚本**也计作消费者）。
   注：完整的“**运行时读取者**”说法是本文件**新立的判据**，不是仓内引文（仓内检索 `读取者` 只在本文出现）。
3. **代价**：它给存读档、回放、验收门、评审带来什么**不可逆**的复杂度？

**判定**：
- 1 与 2 都成立 ⇒ **必需**（或"可选但已接"）；
- 1 成立、2 不成立 ⇒ **只有两条路**：**补上读取者**（运行时或工具链），或**明确拒绝这个面**（写进 `escape-hatch.json`）；
  ⚠️ 不许"声明了却没人读"——那正是 `#1016` 记的那一族（declare-but-undone）。
- 1 不成立 ⇒ **不做**，并写清**什么条件下再考虑**（写在这里，而不是靠记忆）。

## 二、必需面（去掉就不叫文字冒险）

| 面 | 本仓落点 | 谁在读 |
|---|---|---|
| 段落与链接（一张**有向图**） | `stories/<slug>/10-*.twee` 的 `:: 段落名` 与 `[[链接\|目标]]` | 引擎、`test/walker.mjs`、`scenarios`、`event-graph` |
| 玩家可见正文与选择负载 | 段落正文 ＋ `/% payload: 信息｜选择 %/` 标注 | 渲染层、`audit:text`（载荷门）、`audit:literals` |
| 条件（什么状态下可见／可选） | `data/rules.json` 的条件表（`req`／`any`／`exclude`／`prereq`） | `Sg.rules.matches`（`src/engine/40-sim/21-resolve.twee`） |
| 状态 | 故事键命名空间 `Sg.store`（`<slug>.` 前缀）＋ `State` 的 domains／bookkeeping／dynamicKeys | 引擎、`test/store-keys.mjs` |
| 存读档 | `Sg.save`；跨故事靠前缀不串档 | 引擎、`test/saveload*.mjs` |
| 结局与收束 | `Sg.Ending`、引擎登记的 `$pc.ev.ending` | 引擎、`test/witness-trace.mjs`（轨迹到 ending） |
| 故事身份与清单 | `00-story.json`（至少含 `slug`／`entry`／`files[]`／`gates[]`，另有 `title`／`subtitle`／`contractVersion`）＋ `00-meta.twee` 的 `Sg.storyId` | **工具链**：`build.mjs`、`test/store-keys.mjs`（两处必须一致） |
| 判据数据（**本仓的加值**） | `stories/<slug>/audit.json`（`text`／`readBaseline`） | **工具链**：审计门与报告脚本（`k4.mjs`／`scripts/audit/**`／`report-polarity-gap`）；**不进产物**（见 `engine-story-boundary.md` §2b） |

## 三、可选面（**可以没有**，但"声明了就必须有人读"）

以 `night-ferry`（本仓当前唯一真内容故事）为例：它的 `data/contract.json` 声明 **14 个契约成员**，
`data/tables.json` 里 **12 个容器**。这些面都属"可以没有，但不能自称拥有"：

| 面 | 容器／成员 | 没有它时的合法写法 |
|---|---|---|
| 物品与装备 | `Items.defs`／`Gear.defs`／`itemEffect`／`gearDef` | 空表／`null` |
| 经济 | `Economy.prices`／`Economy.events`／`econEvents` | 空表 |
| 短战斗 | `Combat.pools`／`Combat.actions`／`combatPool`／`combatAction` | 空表／`null` |
| 检定位点 | `Checks.sites`／`keyYields`／`checkSite` | 空表／`null` |
| 笔记与图鉴 | `Notes.entries`／`Sg.notes`／`Sg.Codex` | 空表；图鉴属**故事面** |
| 社交与话题菜单 | `Social.asks`／`actionLabel` | 空表；文案缺失走**兜底**且**兜底必须可辨识** |
| 延迟后果（回响） | `Echoes.list`／`revisit` | 空表（本仓判过：`Echoes` 有真读者 ⇒ **配**） |
| 车卡与角色默认值 | `hasChargen`／`pcDefaults` | `const`／空对象 |
| 统计与表达性投资 | `Investment.expressive`／`failClueExempt`／`eraDomain` | 空表 |
| 新机制声明 | `mechanics()` | **`null` ＝ 未启用**（调用方**必须跳过**，不许当空表处理） |

⚠️ **可选的代价**：每一个声明都要有人消费（读者可以是运行时，也可以是工具链；两种都要点得出名字）。机械版是 `test/story-runtime.mjs` 那几条
（引用到的 `Sg.*` 必须在产物里存在；声明的位点要真能判一次；用到的笔记必须已登记且 `add` 跑得通）。

## 四、不做面（**故意不做**，并写清再考虑的条件）

| 面 | 为什么不做 | 什么条件下再考虑 |
|---|---|---|
| 地图／瓦片／坐标／遇敌／队伍／战斗动画 | 文字冒险的"地图"是段落链接构成的那张图，不是平铺数组；瓦片＋坐标是**另一种游戏形态** | 真要"可自由移动的空间"（探索／迷宫）时，**独立设计**，不塞进故事包 |
| BGM／音效 | 属**发布与资源**层，不属故事格式；混进正文会让文本审阅、翻译、diff 全部退化 | 加一份**独立的资源声明**并配套无障碍口径（自动播放／静音／字幕），有消费者、有验收、有基线 |
| 立绘／表情图 | 同上（资源层）；且它会牵动排版与无障碍 | 某个故事**确实需要**插图时，加"插图面"（有消费者＋验收＋基线），缺一不进 |
| 故事侧任意可执行代码（插件加载顺序、脚本钩子） | 会让"内容"变成不可静态审阅的代码；`--engine-story-free` 门正是在守这条线 | 不设条件：**要加机制，就按 `mechanics()` 声明并落在引擎侧** |
| 真实时间／并行进程 | 等待与计时很难"由状态重放" ⇒ 直接破坏存读档 | 前提是它能**由状态重放**（可重放才有存读档与轨迹复跑） |
| 关系型数据库作为**唯一权威数据**（如 SQLite 直接存故事） | 与“改动可被读、可被评审、可 diff、可回滚”正面冲突（评审退化成“相信工具”、二进制不能合并） | 仅作**派生索引**（见 §六）时的确值得做 |

## 五、制度：怎么让"不做"是**显式**的

本仓已经有四件机制，缺一不可（都不需要新造）：

1. **契约成员表**（`data/contract.json`）——每个成员与**运行时读取者或工具链读者**对齐（哪一种是哪一种，要在声明里看得出）；
2. **`mechanics()` 新机制声明**——"这个面存在且引擎认得"的显式入口（`null` ＝ 未启用）；
3. **`editor/escape-hatch.json`** 的 `refusedFaces`（本故事**不接**的面）／`proseFaces`（正文面）／`hatches[]`（本故事自己的临时开口）；
4. **K4** 消费第 3 件 —— ⚠️ 已知缺口见 `#1016`（`hatches[]` 里留**已删 slug** 而 K4 不咬 ＝ declare-but-undone 不被抓）。

⇒ **编辑器只暴露"必需面 ＋ 有消费者的可选面"**；不做面**不出现**在编辑器里。
这样"不做"是写进工具的属性，而不是靠人记（rot 回不来）。

## 六、与同类格式的对照（用于校准，不是选型结论）

| 格式 | 权威数据形态（single source of truth） | 与本仓的关键差异 |
|---|---|---|
| **Twine 2** | **单个 `.html`**（故事数据在 `<tw-storydata>`／`<tw-passagedata>` 元素里），同一份即成品 | 我们用**目录包**（清单＋多件）换"可 diff、可挂门、可评审" |
| **Twee 3**（规范 v3.0.2） | `.twee` 纯文本（`:: 段落名 [标签]`），规范自称是 Twine HTML 的**人类可读等价物** | 同族；我们额外有"生成物"（`15-tables`／`17-rules` 由 `data/*.json` 编译） |
| **ink**（inkle）／**Yarn Spinner** | 源文本（`.ink`／`.yarn`）⇒ **编译器**产出运行态（ink→JSON；Yarn→program＋字符串表） | 我们的 `data/*.json ⇒ *.twee` 属同族；⚠️ 差别：**我们的生成物入库**（为逐字节冻结基线 `equiv`） |
| **Ren'Py**／**ChoiceScript** | `.rpy` ⇒ `.rpyc`（＋`.rpa` 归档）／`.txt` 场景文件 | 编译产物通常**不入库**；脚本层是代码而非声明 |
| **RPG Maker MV** | HTML5+JS 项目 ＋ **以数组下标为 ID 的 JSON 数据库** ＋ 事件里的命令数组（`{code, indent, parameters}`）；文本散在参数数组里 | ⚠️ **文本不可评审**（正文埋在 `parameters`）⇒ 与我们的取舍正好相反；可借鉴的只有**记录＝ID**、**命令＋缩进表达嵌套**、**事件页＝条件＋图形＋命令**三段式 |

## 七、开放问题（未定，别当成已定）

1. **`note:` 词形**：`docs/notes-model.md` 的示例写作 `req: ['note:n_x']`，而引擎 `readKey` **不认**该前缀
   （只认 `n_*`／`inv:`／`era:`／`gear:`／`pc.*`）⇒ 该条件**恒假**（老故事 1 时代就潜伏）。两条修法
   （引擎认它 ＝ **行为变更**；或数据改 `n_`）与代价见 `#1020`——**尚未裁定**。
2. **派生索引**（如本地 SQLite）：只服务编辑器的搜索／回链／图导航，**权威数据仍是文本**；要做需先有
   “索引过时即红”的门。**未决定是否做**（当前判断：非关键）。
3. **资源面**（图／音）：见 §四"再考虑的条件"，目前**全部不做**。
