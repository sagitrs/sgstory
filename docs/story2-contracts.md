# 故事2 引擎契约 A–D：声明表与分布口径（S1–S4 施工图）

> **性质**：设计稿 —— `#486`–`#489`（S1–S4）「**声明表**」与「**分布口径**」两类出口判据的**单一权威形状**。
> **裁定来源**：`#482` 的裁决单（2026-09-13：**全部按建议值走**）＋ 各票票面新增的「## 已定」段（`#486` ④ · `#487` ⑤ · `#488` ②⑧ · `#489` ①③ · `#490` ⑥⑦⑨ · `#491` ⑧⑩）。
> **边界**：本文件**只定形状与口径，不落一行代码**；S1–S4 实现时逐条对表。落地前置 ＝ `#512` → `#458` → `#459` 那条串行链（与并行车道见 Discussion 213）。本文写作时 `src/**` 的搬家结果尚未合入，故下文**一律用逻辑模块名**（`21-resolve`／`15-tables`…），不写具体路径。
>
> 现网形状取自：`Game.Checks.sites`（`{skill, dc, auto?, yields?}`）· `Game.Combat.pools/actions` · `Game.Items.defs/effects` · `Game.Gear.defs` · `Game.Rules.rng`（`set()` 可注入、`d(n)`、优势＝2d20 取高）· `Sg.story.*` 现有 provider。

## 0. 不变量：引擎 / 故事 分工

| 层 | 拥有什么 | 不允许 |
|---|---|---|
| **引擎**（`src/engine/**`） | 机制：结算、状态机、判定流程、随机与分布 | 直读故事表（层间判据 `STORY_SYMBOLS` 0 命中；别名/解构/动态键是已知逃逸面，靠人工复核） |
| **故事**（`stories/<slug>/**`） | 数据与文案：数值表、位点、动作池、异常参数、奖励表、文案 | 把机制实现搬回故事文件（`#512` 清的就是这类反向依赖） |

取数**只经 `Sg.story.*`**。现有 provider：`notes()` · `rules()` · `dragonMaxHp()` · `checkSite(name)` · `checkKnowledge(name)` · `combatAction(id)` · `actionLabel(id)`。
本文件新增的 provider（形状见各节）：**`gearDef(id)`** · **`statusDef(id)`** · **`enemyWave(id)`** · **`eventPool(step)`** · **`chestDef(id)`**。

纪律三档（不许混成一个 `?? {}`）：

| 情形 | 行为 |
|---|---|
| **结构缺失**（表/位点/动作/装备未登记） | **报错**（带着错数据跑比崩更贵） |
| **可选缺省**（无情报捷径、无强制异常） | 返回 `null` |
| **文案缺失** | `Sg.story.copy()` 兜底，不报错 |

**随机唯一入口**：`Game.Rules.rng`（`set(fn)` 注入 ⇒ node 侧可复算）。任何新机制**不得**直接 `Math.random()`。

## 1. S1（`#486`）：部位 · 耐久 · 保护关系

### 1.1 部位枚举（声明表，引擎侧常量）

| 类 | 部位 |
|---|---|
| **受保护部位（7）** | 衣服 · 裤子 · 头盔 · 鞋 · 手套 · 手臂 · 护肩 |
| **不受保护（4）** | 项链 · 戒指 · 腰带 · 内衬 |

### 1.2 装备声明 `Sg.story.gearDef(id)`

| 字段 | 型 | 含义 | 缺省 |
|---|---|---|---|
| `kind` | `'armor' \| 'weapon'` | 护具／武器 | 必填 |
| `protects` | `部位 \| null` | 该件保护的部位（武器为 `null`） | `null` |
| `maxHp` | `3 \| 2` | 可承受伤害上限（护具 3／武器 2 — 裁定 ④） | 必填 |
| `reduce` | `number` | 受击减成值（护具 1／武器 0，见 §1.3） | 必填 |
| `note` | `string` | 说明（UI/fight-meta 用） | `''` |

### 1.3 受击路径（战斗）

```
部位 = PARTS[rng.d(7) - 1]              // 均匀 1/7（本文件定的默认，见 §8）
该部位有护具 ⇒ 伤害先扣该件耐久（扣减量 = 伤害值；耐久 ≤ 0 ⇒ 该件损坏、reduce 归 0；
              溢出量继续落 HP）
该部位无护具 ⇒ 全额落 HP（裁定 ④：无装备 ⇒ 无减成）
```

「掷骰决定攻击部位」**必须走注入的 rng**（`#486` 票面）——这条是 §1.6 分布口径能成立的前提。

### 1.4 判定失败路径（陷阱等）

失败后果由**表**给，不写死在代码里：

| 后果 | 声明形状 | 说明 |
|---|---|---|
| 受伤 | `damage: <n>` | 落 HP，经 §1.3 的部位减成 |
| 耐久下降 | `durabilityLoss: 'rng-1-2'` | **掷骰决定 −1 或 −2**（裁定 ④）；作用对象＝该表指定的装备位（缺省＝随机一件护具） |
| 损坏 | `breakGear: true` | 直接损坏（**v1 只由 `maxHp ≤ 0` 触发**，不设"直接损坏"档 —— 裁定 ④） |
| 遭遇战 | `encounter: <id>` | 转 S3 的波次战斗 |
| 异常 | `status: <id>` | 转 S2 的异常系统 |

### 1.5 损坏与修复

- `hp ≤ 0` ⇒ **损坏**：不可装备、不提供 `reduce`、不参与减成；
- **v1 不实现修复**（接口预留：`repairGear(id)` 桩）；
- **温泉给一次全场修复**（v1 唯一修复锚点 —— 裁定 ④）。

### 1.6 分布口径（可机检）

| 口径 | 判据 |
|---|---|
| 部位命中分布 | 固定注入 rng 跑 **20000** 次 ⇒ 每个部位实测频率落在 `1/7 ± 2%`；同时用固定骰面复算一条确定性序列（同一 seed 两次必须逐字节一致） |
| 减成期望 | 给定一套装备（护具 3 件 ＋ 武器 1 件）⇒ 受击期望伤害可**闭式复算**，并与模拟值一致（容差 ±3%） |
| 损坏阈值 | `maxHp` 依次扣减到 0 ⇒ 恰好在第 `maxHp` 次（护具 3 次／武器 2 次）判损坏；损坏后再受击 ⇒ 减成为 0 |

## 2. S2（`#487`）：部位 × 异常

### 2.1.1 时长单位（`#706`）：**一段 ＝ 一回合**

- **唯一结算点**：`<<caveNext>>`（事件步）里调 `Game.Combat.tickStatuses($pc)` —— 也就是说**走一段**（开箱、走路、交易、打完一场）结算一次；
- **战斗内不结算**：故事 2 的战斗路径（`<<shortFight>>`／`<<foeRound>>`／长战斗段）**不得**再调 `tickStatuses`（实测：一个事件步内 `CON` 结算次数 = 1，战斗内 = 0）；
- **玩家可见**：侧栏异常行写明"每走一段结算一次"；结算句（`#746`）会把"扣了多少、哪个部位"说出来；
- 与 5e 的差别：5e 的时长单位是回合/分钟/小时；本作 v1 以**步**为唯一单位（正典若改用回合制，必须同时改本段与 `stories/hollow-cave/gates/cave.mjs` 的判据⑪）。

### 2.1 异常声明 `Sg.story.statusDef(id)`

| 字段 | 型 | 含义 |
|---|---|---|
| `parts` | `'any' \| 部位[]` | 允许部位（**流血＝any**；**麻痹＝手/手臂/腿/脚**） |
| `perRound` | `{ hp?: number, penalty?: { value: number, scope: 'part' } }` | 每回合效果（流血 −1 HP；麻痹该部位相关判定 −3） |
| `duration` | `number` | 回合数（流血 5／麻痹 3） |
| `cure` | `('hotspring' \| 'item')[]` | 解除途径（温泉／消耗品） |

**v1 两种：流血 · 麻痹。中毒 / 眩晕不在 v1 范围**（`#487` 票面 ＋ 裁定 ⑤）。

### 2.2 每回合判定

- 粒度：**每个部位 × 每个异常各一次**（裁定 ⑤ 与 `#487` 票面一致）；
- 判定属性：**默认体质**，可声明（`statusDef.save.skill`）；
- DC：由声明表给（**默认 12**，见 §8）；
- 成功 ⇒ 该异常在该部位**恢复**（或 `duration − 1`，由 `save.onSuccess` 声明）；失败 ⇒ 走 §2.3。

### 2.3 失败分档（声明表 ＋ 掷骰）

| 条件 | 结果 |
|---|---|
| 判定用的 **d20 原值 ≤ 5** | **随机产生另一种异常**，**部位随机**（`#487` 票面的"骰数过低"） |
| 其余失败 | **该部位受伤 2 点**（经 §1.3 减成；见 §8） |

### 2.4 结算顺序（固定，须一条断言钉住）

```
回合开始 → 异常结算（每部位×每异常一次判定）→ 玩家行动 → 敌人行动 → 回合推进
```

### 2.5 兼容模式

故事未启用异常 ⇒ **不引入回合结算**（保持现网"一回合一次对抗"的行为）⇒ 这是 S7 护栏的一半。

### 2.6 分布口径

| 口径 | 判据 |
|---|---|
| 持续时长 | 固定 DC 下 `duration` 回合内恢复率可复算（多种子 ＋ 固定骰面） |
| 失败分档频率 | 低骰（≤5）⇒ 随机他异常的比例与 `5/20` 的期望一致（容差 ±3%） |
| 部位合法性边界 | 对躯干施加麻痹 ⇒ **必须被拒**（仅限部位的异常不得越界）；中毒 v1 不在表内 ⇒ 施加即报错 |

## 3. S3（`#488`）：波次战斗 ＋ 失败重置

### 3.1 战斗规模（裁定 ②，本故事核心试验变量）

| 档 | 定义 | 胜利 | 失败 |
|---|---|---|---|
| **短战斗** | **单次对抗判定**，**无回合** | 怪退（无奖励或用 `waves[0].reward`） | 受伤 1 档（沿用现网 `hurt` 机制） |
| **长战斗** | **5 回合上限**（`#599` 由 3 调为 5，保留"需 3 次成功"），每回合一次攻击判定，需 **3 次成功**击倒 | 击倒（奖励按难度） | 回合用尽未击倒 ⇒ **判负**（受伤 ＋ 无奖励） |

两档只在**"回合数"这一维**上正交 ⇒ 同一套 `Combat.resolve` 即可跑（不必两套引擎）。

### 3.2 波次声明 `Sg.story.enemyWave(id)`

```
{ waves: [ { pool: '<Game.Combat.pools 的名字>', difficulty: 1|2|3 }, … ],  // 短＝1 批，长＝2 批
  reward: { gold?: n, item?: '道具' | { id, chance }, difficultyScaled: true } }
```

- **增援**：第 1 批**清完**才出第 2 批，第 2 批 `difficulty` 更高；
- `pool` 引用现网动作池（单一权威：动作池仍由 `Game.Combat.pools` 拥有，故事只引用名字）。

### 3.3 奖励随难度（单调）

| 声明 | 判据 |
|---|---|
| `reward.difficultyScaled: true` | `difficulty` 1→2→3 的奖励**严格单调不减**（机检三条曲线的 9 组比较） |

### 3.4 失败与重置（`reset` 语义）

| 触发 | 行为 |
|---|---|
| 单步失败（未全灭） | **带伤继续** —— 不终止、不重置（裁定 ⑧） |
| **仅全灭** | 回出生点 ＋ **道具清零** ＋ **笔记/图鉴保留**（`#488` 票面） |

**明确"不清什么"**：`Sg.notes` 笔记表 · 图鉴（`Game.Codex`）· 已解锁（键命名空间 `Sg.store` 的 `<slug>.` 前缀）· 结局记录（`pc.ev.ending`）。

### 3.5 存档相容

- `reset` 后**读档不复活旧道具**（断言：reset → 存档 → 读档 ⇒ 道具仍为空）；
- 「通关」定义 ＝ 走到第 5 步后**仍活着**（裁定 ⑧）。

### 3.6 分布口径

| 口径 | 判据 |
|---|---|
| 短战斗胜率 | 固定属性下闭式胜率 ＝ `P(d20 ± 优势 ≥ DC)`，与多种子模拟一致（±3%） |
| 长战斗期望回合 | 5 回合上限（`#599`）下击倒概率与期望回合可复算（闭式＝`rounds` 回合内 ≥`hits` 次成功的二项尾和，**两批相乘**）；**须报分布**，不得只报期望值；实测 2026-09-14：清完率 **14.60%** · 期望回合 **6.38** · 受伤期望 **15.29**／局 |
| 方差敏感 | 照 `--dragon` 的教训：连败方差必须可见（最少 6 档种子对照，禁止"期望值对连败视而不见"） |

## 4. S4（`#489`）：通用事件池 ＋ 线索三选一 ＋ 宝箱

### 4.1 事件实例清单（`#778` 起由**引擎**折叠）

故事侧只声明 `roads`（每条路的 `options[]`：`{kind, hint, ref}`）；实例清单是**纯派生**，由引擎从该声明折叠：

```
Game.Combat.roadInstances()   // ⇒ [{ id, kind, hint, ref }, …]（**平数组**、不收参数；未启用 ⇒ null）
```

- `id` ＝ `String(ref)`，与下沉前 `Sg.story.eventPool(step).entries` 里的条目**逐字段相同** —— 过渡期由洞窟的门做等价断言（留着旧成员就必须折得一样）；
- 六类**词表**（`shortFight`／`longFight`／`chest`／`cave`／`trap`／`traveller`）是**故事词汇**，留在门侧，不进引擎（引擎只认 `roads` 的形状）；
- 分组（按 `kind` 归并成 `entries`）由调用方一行完成 ⇒ 引擎不替调用方决定分组口径。

### 3.3 敌人属性面（`#705` 片一：声明面＋门；机制接线见片二）

**为什么必须有**：没有敌人属性（HP／AC／攻击／落点），`#486`–`#488` 的部位/耐久/异常三套机制**永远没机会被触发**（症状：「敌人太简单…无法测试到上述问题」）。

```
enemies: {
  <id>: { name: '洞窟鼠', hp: 4, ac: 11,
          attack: { site: '洞窟·鼠咬', dmg: '1d4+1', parts: ['腿', '手臂'] },
          traits: ['成群'], drops: [] },
}
encounters.short.waves[0].enemies = ['洞窟鼠', '洞窟鼠']   // 遭遇**引用**敌人（不只是难度数字）
```
- **形状门**（`scripts/audit/lib/story-shape.mjs` 判据⑥）：有 `encounters` 就必须有 `enemies`；每只要 `hp`（正整数）· `ac`（正整数）· `attack.site`（非空）· `attack.dmg`（**骰式**：`N`／`NdM`／`NdM+K`——固定数字与 `#702` 方向 3 冲突）· `attack.parts` ⊆ `hitLocations`；遭遇引用的敌人必须已声明；
- **故事门**（`--cave --story <slug>` 判据⑧）：`attack.site` 必须是**已登记位点**（玩家的对抗检定拿它掷）；
- **片二**（未做）：敌人 HP 归零 ⇒ 退场（不再只数命中）；敌人攻击**落到部位**（`slotAbsorbAt(pc, part, dmg)` 已就位）；`traits`/`drops` 的机制。

### 4.1.1 路面提示 = **类型标签 ＋ 线索文案**（`#692` ①）

玩家在"三选一"里必须能**看出这条是什么**（否则"选"不成立）⇒ 渲染面输出 `【类型】线索文案`：
- **标签住声明面**：`Sg.story.eventKindLabel(kind)`（数据＝故事侧 `kindLabels`）——**不写死在段落里**；
- **门**：`--cave --story <slug>` 的判据⑤ —— 出现的每个 `kind` 都必须有**非空标签**（新增第七类而不给标签 ⇒ 红）；
- **不采用"风险档"方案（②）**：取 ①（显式类型），并用**奖励**引导玩家别总是绕过战斗 ⇒ 奖励见伞 `#687` 下的调参票。

- **三选一用现网 `Game.Combat.offer(pool, 3, pc, …)`**（单一权威：不另写一份随机选择 —— 出口判据 1）；
- 每步出 **3 个不同类型**的事件，玩家择一；选定后事件**内部各掷一次判定**（裁定 ①）：

| 事件 | 内部判定 | 位点来源 |
|---|---|---|
| 陷阱 | 闪避 | `checkSite` |
| 宝箱 | 解机关 | S4 / §4.3 |
| 旅人 | 态度或交涉（`Game.Social` 复用） | `checkSite` |
| 短战斗 | 攻击判定（单次） | §3.1 |
| 长战斗 | 回合序列（5 回合上限，`#599`） | §3.1 |
| 特殊洞窟 | 耐受或探索 | `checkSite` |

装备/道具照现网 `advSite`／`advAt` 给优势（**复用**，不新造）。

### 4.2 线索可区分（机检口径）

| 判据 | 做法 |
|---|---|
| 同段三路不等价 | 三路的 `hint` 文本**两两不相同**（归一化后）；且**不得**出现"三路 hint 指向同一 `kind`"（等价类检查）⇒ 玩家不能靠猜 |
| 线索→事件一致 | `hint` 声明的 `kind` 必须与实际抽取的 `kind` 一致（抽 3 次比对，多种子） |

### 4.3 宝箱声明 `Sg.story.chestDef(id)`

| 维度 | 取值（裁定 ③） |
|---|---|
| **机关（3 种）** | 锁扣（灵巧）· 机关针（体质抗毒）· 石块（力量） |
| **稀有度（2 档）** | 普通 DC12 · 珍贵 DC15 |
| **通用道具 ↔ 机关** | 撬棍 → 锁扣 · 手套 → 机关针 · 铁撬 → 石块（各 **−3**） |
| **钥匙** | 长战斗**必掉** / 短战斗 **50%**（`#696`："战斗＝宝箱钥匙的主要来源" ⇒ 30→50）⇒ 难度**降为 0**（`#600` 已落地：声明面 `encounters.*.reward.item`，落账在 `Game.Combat.grantReward`（单一落点）；真机门 `test/cave-drops.mjs` 断言"长战斗清完必有钥匙"＋"声明的掉率多种子 3σ"） |
| **径直通过** | **无判定、无惩罚**（只是没有奖励；不得产生死档） |

四条路径（判定成功／道具降难／钥匙清零／径直通过）**各要一条断言** ⇒ 对应 S6 的"宝箱四路径门"。

### 4.4 频率口径

| 口径 | 判据 |
|---|---|
| 同类事件频率 | 每 `kind` 的实际出现频率落在声明区间内（多种子复算，容差 ±3%） |
| 无死档 | 存在"无判定选项"且任何路径都不产生死档（可达性检查：从任一步都能走到终点） |

## 5. 门与验收映射（S6 `#491`）

| 判据 | 门／断言 | 备注 |

## 9. 短战斗的**相位契约**（`#608`：机制上移引擎后钉住）

`Game.Combat.waveRecord(pc, success)` 返回**对象**，`phase` 有**四种**（`src/engine/40-sim/21-resolve.twee`）：

| `phase` | 含义 | 短战斗 UI 的动作（`<<shortFight>>`） |
|---|---|---|
| `continue` | 本回合记完，**这一批还没打完** | **不结算、不推进** ⇒ 印胜句 ＋ 重渲染本段（下一击） |
| `advance` | 本批打完，**增援进下一批** | 同上（不结算、不推进） |
| `cleared` | 全部批次清完 | 胜句 ＋ `grantReward`（**声明面**）＋ 尾段（故事侧 wiki 片段，例 `<<caveNext>>`） |
| `failed` | 本批回合用尽 | 败句 ＋ `<<damage>>` ＋ **声明面失败笔记** ＋ 尾段 |

⚠️ **两条禁令**（都是 `#598` 那一族踩出来的）：

1. **不许**拿 `waveRecord()` 的返回值与字符串比（它是对象）——要比就比 `.phase`；
2. **不许**用 `$last_check.success` 代替相位：`success` 只说"**这一击中了**"，不说"**打完了**"。
   短档声明（`hits=1`／`rounds=1`）下两者**恰好同构**（所以历史上看不出错），换声明（增援／多击）就会把 `continue` 当胜利 ⇒ 提前结算＋提前推进。

**门**：`test/shortfight-phases.mjs`（四相位各归其位；判别性用例＝`success=true` ＋ `phase=continue`；反例探针：改回 `success` 分支即红）。
