# 表语法实战：**"这个能不能进表"** 决策手册（条件表 / `<<rules>>`）

> 面向"要把一段手写 `<<if>>` 搬进条件表"的人（2026-09-14 由 `#435`／`#568`／`#624` 的连续几片沉淀）。
> **形状规范的正典**是 [`docs/dev-conventions.md`](dev-conventions.md) §11–§12；本页是**可操作的决策树 ＋ 踩坑清单**。
> 表本身住 `stories/<slug>/17-rules.twee`（`[script]` 段），选择器在 `src/engine/40-sim/21-resolve.twee`。

## 0. 三十秒决策树

```
这段东西是…
├─ 条件（"哪一行被选中"）？      → 见 §1：键形 / 算子 / 取值项 / 前缀
├─ 文案（选中后渲染什么）？      → 见 §2：text 的允许与禁止
├─ 点击时发生的动作（写状态）？  → 见 §3：只许**词汇宏**（白名单）
├─ 渲染成功后才授予（笔记/物品/状态键）？ → `yields` / `gives` / `sets`
├─ 一组同时可用的入口（菜单）？  → 见 §4：`<<rulelist>>`（不是 `<<rules>>`）
└─ 机制块本身（`<<damage>>`／`<<sitecheck>>`＋判定依赖写）？ → **不搬**（见 §5）
```

## 1. 条件怎么写（`req` / `any` / `exclude` / `prereq`）

| 想表达 | 写法 | 备注 |
|---|---|---|
| 裸旗标 | `'fog_thin'` | 裸键＝`ev.`（与 `Sg.rules.holds()` 同口径） |
| 世界态 | `'world.hall_hint'` | 必须写全域名 |
| 笔记 | `'n_rumor'` | 走 `Sg.notes.has` |
| 持有物／时代／行囊 | `'inv:日记'` · `'era:past'` · `'gear:火把'` | **前缀键**（求值在引擎；不是状态键 ⇒ 不进 `--state`） |
| 顶层数值字段 | `'pc.gold'` · `'pc.hp'` | **显式根 `pc.`**（裸键＝`ev.`，够不到顶层） |
| 数值比较 | `{ gte: ['star.spent', 3] }` · `{ lte: [...] }` | 算子由 `Sg.rules.ops` 宣告；键缺失 ⇒ 不匹配（不抛） |
| 枚举 | `{ oneOf: ['keeper.state', ['seal', 'ally']] }` | 两种写法都认：`['k', ['a','b']]` 或 `['k','a','b']` |
| 随状态变的操作数 | `{ gte: ['pc.gold', { price: 'rumor_buy' }] }` | **取值项**（词表 `Sg.rules.terms`）；`price` ＝ 该事件当前要花多少钱（正数） |
| 至少一个 | `any: [...]` | 空＝不要求 |
| 都不满足 | `exclude: [...]` | 多项＝**全不中**才满足 |
| 前置行 | `prereq: ['other.row.id']` | 同行作用域；禁环 |
| 优先级 | `prio: 10` | 降序；**同 prio 按表序**（`first-match wins`） |

**复合条件的"else"怎么表达**：
- 单条条件的否定 ⇒ `exclude: ['x']`（或 `exclude: [{ oneOf: [...] }]`）；
- **合取的否定**（`NOT(A ∧ B)`）⇒ `exclude` 单条盖不住 ⇒ 用**无条件兜底行 ＋ 更低 `prio`**（实测样本：`酒馆.情报.else`、`地下宴会厅.哨子.else`）。

## 2. `text` 能放什么（写侧判据**按域分**，`#624` 片一）

| 位置 | 允许 | 禁止 |
|---|---|---|
| **渲染域**（link 之外） | 纯文案、`<<if>>`（只读**渲染期只读槽**：`$last_check`、`_` 局部量）、`<<goto>>` | 任何写（`<<set>>`／`<<run>>`／`<<give>>`／`Sg.notes.add`…）⇒ 写请走 `yields`/`gives`/`sets` |
| **点击态域**（`<<link>>…<</link>>` 体内） | **词汇宏白名单**：`note`／`give`／`take`／`setflag`／`econ`／`flip` ＋ 纯渲染/导航宏 | 裸 `<<set>>`／`<<run>>`／`<<script>>`／模块 API；**`damage` 也不许**（带它的是机制块） |

> ⚠️ 表行 `text` 是 **JS 模板字面量**：行内 `<<link \`…\`>>` 的**反引号必须转义**（`\``）—— 踩过两次。
> ⚠️ 标签里要显示**随状态变的价格**：直接调封装层 `Game.Economy.priceOf(...)`（是**读**，`--reads` 允许）；**不要**在表里写 `$pc.ev.x` 这类字面状态读。

## 3. 授予两面：**渲染后** vs **点击时**

| 时机 | 语法 | 例子 |
|---|---|---|
| **渲染成功后**（行被选中 ⇒ 渲染 ⇒ 落账） | `yields: ['n_x']` · `gives: ['月光花']` · `sets: ['world.flower_taken']` | 行文本出现即已授予；幂等（重复渲染只落一次） |
| **点击时**（玩家真的点了那条链接） | `text` 里 link 体内的**词汇宏** | `<<note "n_x">>` · `<<give "月光花">>` · `<<take "月光花">>` · `<<setflag "world.x">>`／`<<setflag "ev.x">>` |

**为什么要分开**：`#435` Q1 —— 渲染期的写会让 `yields` 变成装饰；而点击态的写**渲染期零副作用**（这正是 `#624` 片一把判据按域分开的原因）。

## 4. 菜单 vs 单选（一作用域一行！）

- `<<rules "作用域">>`：**单选**（first-match wins）—— 用于同一处的**互斥变体**（如 `天文台#取书` 的三种状态）。
- `<<rulelist "作用域">>`：**菜单**（渲染**全部命中**的行，按 `prio` → 表序）—— 用于"同时可用的多个入口"（如 `酒馆#打听` 的 6 个话题）。
- **原文里同时渲染的两块**（入口 ＋ 已得后的说明）⇒ 必须拆成**两个 `scope`**（否则只出其中一行）。
- 同一作用域**同时**被 `rules` 与 `rulelist` 接管 ⇒ `--rules` 判红（单选/菜单语义冲突）。

## 5. **不搬**的清单（都是"门说了算"，不是口味）

| 不搬的 | 为什么 | 谁拦的 |
|---|---|---|
| 机制块（体内 `<<sitecheck>>`／`<<damage>>`／判定依赖写） | 数值玩法量不进表；授予依赖判定结果＝边界① | 写侧判据（`damage` 不在白名单） |
| 战斗瞬态（`ev.fight.*`） | 瞬态不是状态契约键 | `--state`（未落入任何域）＋ `--reads`（键形态） |
| 安全阀（`$pc.hp gt 0`） | 不决定"哪段文案被选中" | `#568` 已定不进表 |
| widget 内分支 | 表的作用域是**段落** | 机制本身 |
| 渲染期局部量打分（`_t`） | 判定面，另议 | 机制本身 |
| 操作数是**计算式**（`-priceOf(…)`）之外的任意表达式 | 取值项只认已宣告的词（`terms`） | `--rules`（未宣告的取值项） |

## 6. 加**新形状**时必须同步的消费点（踩过的坑，一次一件）

| 你加了 | 必须跟着改 | 不改的症状 |
|---|---|---|
| 新的**写**形态（如 `<<note>>`） | `scripts/audit/lib/shared.mjs` 的 `NOTE_WRITE_RE`（写点识别**单一权威**） | `--state`／D2 判「只有读没有写」⇒ **幽灵条件**假红 |
| 新的**前缀键**（如 `gear:`） | 引擎 `Sg.rules.prefixes` ＋ `KEY_PREFIX_RE`（shared）＋ `--reads` 键形白名单 | `--rules` 判「前缀未被引擎宣告」；`--reads` 判「键形态」 |
| 新的**算子/取值项** | 引擎 `Sg.rules.ops`／`terms`（门自动核对） | 引擎不认 ⇒ 条件**永假**（静默） |
| 行 `text` 里出现 `<<give>>` 之类 | `--npc` 的 give 位点归属（按行 `scope`）＋ 跳过 `[script]` 段 | 多出 `StoryRules::道具` 假位点 |
| 任何新形状 | 对应门的**自证**（正例／🔴 反例）＋ 反向探针 | 门"看起来绿"其实没牙 |

## 7. 迁移一处的标准动作（每批一片）

1. **勘察**：读原文的守卫与 link 体，先判"能不能搬"（§0/§5）——**先勘察再认领/动手**（本会话因此撤回过 3 处改动）；
2. **落行**：`scope` 用 `段落`（纯话题）或 `段落#位点`（一段多条件位点，**必须与调用点同段落**）；
3. **删手写分支**，换成 `<<rules "…">>`／`<<rulelist "…">>`；
4. **零漂移**：`node scripts/ui-migration-diff.mjs --zero --baseline=origin/main` ⇒ 必须 **0 段**；
5. **真机断言**：至少一条"点一下 ⇒ 状态真的变了"（幂等：再点不重复落）；
6. **门**：`--rules`／`--reads`／`--state`／`--choices`／`--consequences` 全绿；golden／密度基线按需重签**并写明理由**；
7. 收口时把**不搬的逐条列出来**（含理由）——比"搬了多少"更值钱。
