# 可读性与解耦：渐进重构方案

关联：[文档交付 #2045](https://github.com/sagitrs/sgstory/issues/2045)。

## 1. 一页结论与适用范围

**保留已有抽象，把真实业务接进去；先讲清现状，再迁调用链，不推倒重写。**

局部道具声明、规则数学和小协议通常容易阅读；整体理解仍依赖加载顺序、全局玩家桥、注册约定及历史注释。端口、`GameSession`、提交边界已经提供有效基础，但新旧路径并存，不能只凭目录分层或会话模型测试宣称完整游戏已解耦。

本方案基于 `sagitrs/sgstory` 的固定主线提交 **`32b0e9815c76c20fd09f55857f970a2e4f7990c2`**，2026-10-07重新取远端主线与独立fetch，两者一致。源码依据是静态阅读，未执行构建、单测、浏览器或游戏验收；不是全仓逐行审计。下文源码链接固定该提交，后续实施须重新核对主线和在飞候选。

本次交付仅为Markdown方案及入口。阶段次序是建议，不是派工、工期承诺、版本承诺或新增发布前置；本方案的验收表不是已通过的产品测试。

1. ## 3. 目标：明确依赖、身份和副作用

```text
故事内容 ──使用──> 规则包与公开领域API
                         │
                会话上下文/领域执行
                  │             │
             定义与实例      提交/结果协议
                  └─────端口契约─────┘
                           ▲ 实现
                     宿主适配器
```

这是目标依赖方向，不是要求立即移动目录。会话负责一局的可变态与执行上下文；规则包提供定义和数学；宿主负责存取、界面和生命周期。规则计算不借隐式“当前玩家/当前战斗”。

### 状态所有权建议

| 对象 | 建议归属 | 兼容边界 |
|---|---|---|
| 内容定义与包导出 | 可共享的只读定义视图 | 先明确注册完成后的可变性；不要求每局复制定义表，运行实例不能回写定义 |
| 玩家、库存、场景/战斗进度、当前战斗 | 会话拥有的事实/实例 | 旧全局入口可转发到显式指定的默认会话，不成为第二份事实源 |
| 随机源、输入、执行期事件与待发布呈现 | 会话上下文 | 透传到规则消费点；漏传的兼容调用与已绑定调用可辨，沿#2043候选核覆盖范围 |
| 存档槽、DOM和段落生命周期 | 宿主适配器 | 持久化会话事实而非把DOM/函数/当前调用栈当存档；宿主订阅的拆卸/取消责任明确 |

定义键建议逐步显式为`(pack, definitionId)`；运行件另有`entityId`。标签、显示名、导出别名不是稳定身份。具体键格式、唯一性范围、旧档缺包信息的处理须先冻结契约，不能默认猜包、丢实例或重置耐久。

### 提交语义不统称“原子”

| 现有边界 | 静态读到的范围 | 不能推出的保证 |
|---|---|---|
| 旧`RPG.act` | 调用`used`后支付成本并提交件快照 | 任意target/外部回调先写后拒都会回滚。本轮未构造失败复现，不据此宣布业务bug |
| `GameSession` | 合并/丢弃事实草稿，恢复调用方声明的对象态，拒绝丢弃待呈现；随机消耗可记账但不回退 | 未声明对象、宿主直写或外部副作用自动撤销；重复运行可无条件随机重放等价 |
| `commitBoundary` | 显式事实前像/补丁、去重账与提交后发布；呈现失败不再执行领域效果 | 任意文件/网络/第三方效果事务；去重记录跨任意时长、重启都永久有效 |
| `runPipeline` | 阶段顺序、提前结束；不可逆异常按其契约传播 | 与会话命令有同一种错误吞吐和回滚政策 |

实施时为每个公开入口补：输入/结果类型、写口、拒绝是否耗行动/随机、回滚清单、普通异常、呈现时机和重试政策。可复用结构化结果及薄转换，不强行把不同边界合成巨型事务，也不另建第二份提交账。

## 4. 分阶段交付

阶段间的次序是依赖建议。已有票覆盖的工作先对账与消费；只有未被承载的真实缺口再单独立项。每笔实施须有明确源码范围、对应行为证据和可恢复的旧入口。

### P0：先让当前架构可读

**交付**：短调用链图、公开API/结果表、所有权表、迁移登记表；文件头标现行职责、输入输出、不变量、副作用、失败及遗留适配。相反注释先修，历史移到可达的决策链接而非删除。

**未来验收**：新人沿入口可以指出一条真实业务链的状态来源与提交点；文档不把端口存在、模型测试或棘轮读数当完成证明。正文中的源码和旧决策能定位。

**回退/停止点**：仅文档与注释可独立交付，不改运行行为。本PR只贡献方案与入口，不宣称P0的全量清册已完成。

### P1：迁一条真实业务链，复用既有ctx与端口

**建议试点**：选一条“采集→节点扣费→入包→呈现”的实际消费链；实施前确认两仓真实入口及相关在飞票，必要时由有权者选择其他最小链。迁的是原动作，不是旁边新写一个同形动作。

**交付**：该链所需的玩家/袋/随机/对象来源显式传入；用现有会话/提交边界执行，旧API保留薄转发。不扩大到完整战斗、全场景或全量迁档。

**未来验收**：同一受测树上对照旧路径与新路径的事实、成本、结果、通知顺序；覆盖成功、前置拒绝、普通异常、重复请求和呈现失败。分别断言回滚范围与随机消耗，不能只断“没抛错”。在实际宿主/实际产物上确认一次真实消费。

**回退/停止点**：适配切换有明确开关或入口边界；旧入口不持双份状态。若写口无法纳入承诺的回滚集合，先缩小范围并记录，不静默称原子。只撤该切片，已提交效果不因UI重试再执行。

### P2：扩展身份与会话所有权

**交付**：按具体消费链扩展定义键/实例ID与持久化来源；玩家、背包、当前战斗和随机源归属显式。优先消费#2043/#2044及#2021子票，核其实际合入范围，不以局部随机接缝代表完整游戏隔离。

**未来验收**：同id不同包不会混定义；两件同类不同耐久只消耗所选件；旧档迁移保留身份/耐久；两个真实会话交错行动、关闭/重开/读档后互不改状态、随机、输入、输出及当前战斗。共享只读定义不列为串扰。

**回退/停止点**：一次只切一个读写入口，不能新旧登记并存却各当权威。存档写格式变更另有版本、迁移与恢复契约；未知/歧义来源具名处理。代码回退不等于存档自动降级，未验证前不能承诺回滚版本可读新档。

### P3：按变化责任收瘦Battle与库存协调器

**交付**：区分循环编排、输入/目标策略、规则计算、库存存取/成本结算、呈现翻译。复用42–47系列小协议和规则包数学；协调器只组合公开接口，旧API仍可转发。先迁最常变化的一项责任，不按行数切文件。

**未来验收**：自动/交互/外部提交等受影响入口使用同一领域结果；拒绝、取消、行动消耗、目标身份、重复和恢复语义保持明确；规则层的用例不依赖DOM，实际宿主测试核输入/呈现/生命周期。数学不复制到新controller或测试夹具。

**回退/停止点**：每责任一笔可撤，不造第三套循环。不同时重写协议、目录和规则数值；确需改变行为时另列决策与验收，不伪装成零行为重构。

### P4：补显式依赖和轻量类型，再决定模块体系

**交付**：先补JSDoc结果/上下文类型、公开面清单、加载期与运行期依赖、显式初始化顺序。原型便利层留在具名兼容入口，禁止新领域代码靠不透明原型扩展取能力。是否采用ES modules或TypeScript另行评估收益与工具链成本。

**未来验收**：公开入口缺字段/缺能力可区分；新增依赖在装配清单可见；改变初始化顺序的负例能发现错装；相关路径可在没有SugarCube全局的环境执行。扫描范围及未覆盖形明确，不用一个正则命中数代替依赖证明。

**回退/停止点**：先不换语言/打包器，不同时改变包加载策略。保留已验证产物入口；如后续换构建方式，另核产物、保存/恢复与真实宿主行为等价。

## 5. 实施验收建议与未覆盖账

以下是**未来实施PR的证据建议**，不是修改舰队规则、当前CI覆盖面或放行标准。本PR不新增测试装置、不修改CI，现有工程流程仍有效。

| 要证明的目标 | 最小证据方向 | 不足以替代的材料 |
|---|---|---|
| 行为保持 | 固定前后源码/产物/pin；对照状态、成本、结果与呈现序列 | 文档CI、只报断言总数、只核无异常 |
| 真实接线 | 真实动作入口触发、消费日志/状态前后读数、宿主恢复/取消 | 另写会话同形件或直接调用新API |
| 会话隔离 | 两真实会话交错运行，源/对象/输入/呈现/当前战斗各有归属对照 | 多new一个GameSession或临时互换全局单例 |
| 失败边界 | 拒绝/异常/呈现失败各给状态、行动、随机和重试读数；破坏相关实现后负例会失败 | 仅`assert.throws`通过但无类型/码值区分 |
| 身份与存档 | 包同id、同类多件、旧档/未知来源、迁移/重启/恢复对照 | 定义查得到、UPDATE/加载返回成功、快照里只有显示名 |
| 解耦范围 | 指明已迁链和遗留链；真实headless与宿主各测必要路径 | core/host目录、宿主触点棘轮绿、无操作jQuery桩 |

优先扩充仓内既有工具，不另建平行判据系统。[测试入口](../../tests/README.md)已有单测、基线和门资产；本轮只读其源码接线。实施时应明确harness复位范围：State/rng/host的重置不自动代表注册表、订阅、端口和当前战斗都已恢复。

每次读数绑定**受测头、基座、依赖pin、命令、环境、原始输出及覆盖范围**；通过、产品失败、环境作废和未执行分别报告。不同宿主或两仓分别验，文档/模型通过不自动扩大成游戏、浏览器或发布验收。

## 6. 先冻结的未决问题与非目标
