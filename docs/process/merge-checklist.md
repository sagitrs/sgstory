# 合入清单（sgstory）

## 判定与规则行为的变更（操作者裁定 2026-09-30）

- [ ] 本 PR 是否改动了**判定或规则行为**？具体指命中、伤害、豁免、护甲等级 AC、效果、经济、掉落这几类判定数学，或者 core 的行为语义。
  - 若改动，应当**在同一笔里合入设计文档的差量**（`docs/plan/` 下对应的那一节）。设计文档的每条规范句都要引用权威来源，写法是 SRD pin 行号形；若引用不到，就标明 `house rule（非 SRD）`并写出理由。
  - 若没有改动，PR 描述里要显式声明 `no-behavior-change`。
- [ ] 单测的行为断言要锚在**设计文档的规范句**上，不锚实现输出。断言与文档冲突时，以文档为准。
- [ ] 测试席位与开发席位各自核一次「码、文档、源」三点一线；领队合入时抽查。

## 提交物文本的因果归因（锚 #1745，本仓流程条）

> 由来：#1745 第 3 笔当中，门内注释把「22 处对仓内 28 处」的差额归因成「同一行多引用，加上约定占位不计」。
> 这两条**在实仓里都不成立**。实测的真因是 6 处测试名用散文提及，它们的引用由上方注行继承了 `lastCitationIdx`。
> 经裁定**不做门**，理由是「因果是否可复现」**无法机械判定**，硬做就成了关键词匹配，反而会造出新的假绿面，因此落为流程条。
> 两侧成对：**作者附出处，复核方实跑并核对量纲**。

- [ ] **作者侧**：提交物文本（代码注释、提交信息、PR 正文、设计文档）当中凡写因果归因（「因为」「差额来自」「根因是」「原因是」「来自」这类说法），都必须附上**可复现的命令与读数**。
      **不得**写推断式因果。这与「无出处的读数」是同一族的问题：凡是没有实跑就写下的因果，就是声称，**不是**证据。
- [ ] **作者侧**：还须核对**归因的适用面**。同一个现象常常有**多个口径**，因此要先问清楚这个数是「引用形条数」还是「仓内提及总数」，是「分支单独态」还是「合并态（约等于 CI）」。
      （实证：门报的 `22` 是引用形条数，而 `grep` 的提及为 `28`；门读数在分支态是 `93/94`，在合并态是 `97/98`。）
- [ ] **复核方**：凡票或注释里出现「差额来自」「原因是」「根因是」这类句子，都必须**照它所述的那条命令实跑一次**，并**核对量纲**。
      核对时**不能**只看数是否相等，还要看清**这个数到底是什么**。
- [ ] **门槛或基线类文件变更的复核三法**（出处：锚 **#1745** 与 **#1738**，`tester-4` 实测）：
      第一法是**重播比对**。在候选 head 上跑 `--update-baseline` 重播，产出的结果与提交的基线**逐字相同**（唯一的差异是 `seededAt`），这就证明该基线是**真产物，而非手工凑数**。
      第二法是**判别性抽验**。对每一个被改动的**下限或上限面**，抽一条**能压低它**的真实改动，**验证它变红**。压低之后不红，就说明该面没有在守护，是静默稀释。
      第三法是**放宽与口径归位分离**。对豁免类改动，**去掉条件**后验证计数**是否越限**；并且被豁免面之外的判定必须**一字未变**。

## PR 正文的机械写入口（锚 #1757 与 #1767，本仓副本；跨仓工具面的主落点报 Coordinator 侧）

- [ ] 改 PR 正文**禁用 `gh pr edit`**。本仓实测这条路 **exit=1**，报错是 `GraphQL: Projects (classic) is being deprecated…`。
      正确做法是 `gh api -X PATCH repos/<owner>/<repo>/pulls/<N> --input patch.json`，文件内容形如 `{"body": "<全文>"}`。
- [ ] **写后必须回读**，即执行 `gh pr view <N> --repo <R> --json body | grep <新标记>`，确认**改动已生效**。
      **不得**用 `>/dev/null` 吞掉 stderr，然后凭自己那个 echo 声称「已更新」。
      （实证 #1767：命令 `gh pr edit … >/dev/null && echo 已更新` 把退出码 1 吞掉了，于是据 echo 错报「已更新」；
      回读发现线上正文对新增加的内容**命中 0 次**，本地文件与线上相差 895 字节；改用 PATCH 之后就正确了。）
