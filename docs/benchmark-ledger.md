# 质量对标台账（Benchmark Ledger）

> 伞票 **#297**。用途：让「竞品基准」从**一次性调研**变成**常设台账**——每行记录「学到什么 → 落在我们哪 → 什么时候复核过 → 什么条件触发复核」。
> 事实源分工：维度正文与候选池归 `docs/quality-dimensions.md`（guest-1）；**本台账只做保鲜与落点追踪**，不重复维度正文（避免双记账）。
> 复核记录写在「最近复核」列，日期 + 一句结论；触发条件命中即复核该行，并把结论写回本文件。

## 触发条件（三选一，命中即复核该行）

1. **该竞品出新作 / 大版本**（或该理论/标准发布修订）；
2. **我们某维度落地后回看**（新门一落地，回头校准该维度的外部基准是否仍成立）；
3. **季度例行**（按「最近复核」列挑最旧的若干行）。

## 维护纪律

- **一行一复核**：复核只改「最近复核」列 + 必要时改「落点」列，不新写一段散文；
- **落点必须可点**：票号 / 文件名 / 门名三者至少给一个，**不许写「已在游戏中体现」**这类不可核对的话；
- **无落点的行允许存在**（如凌霄錄、Obra Dinn），但必须写「尚无落点」并说明归并去向；
- 本文件由对抗席（T）维护；维度正文的增删仍走 `docs/quality-dimensions.md`。
