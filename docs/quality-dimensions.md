# 文字冒险游戏质量维度提取手册（给测试/评审）

> **用途**：把「从竞品与理论里提炼质量维度」这件事变成可复用的作业流程——测试按本手册提取维度、写成判据、落成机检门或人工走查项，交回 #247（十维伞）核销。
> **配套**：`docs/quality-selfaudit-ch123.md`（#34 八维首轮自检，历史存档）、`docs/design-review.md`（D6 可用性走查）、`docs/ui-coverage-gaps.md`（覆盖与未覆盖口径）、`docs/impl-map.md`（工程侧变更账）。
> **原则**（#247 横切验收）：**门必须行为化**——每条机检要么给「正例（置条件→断言效果）＋反例（清条件→断言效果消失）」，要么显式标注「仅登记/存在性检查」并说明理由。

## 一、提取方法（三步）

**第 1 步：找信号（Signal）**——一个维度必须先能被「看见」。信号的四种来源：
1. **玩家体验描述**：竞品评测/复盘里的抱怨与赞叹（「读完后不知道下一步在哪」＝呈现维度信号）；
2. **设计理论**：外部基准条文（OPDC 五维、三线索律 3CR、局面化设计、教学曲线、tenfootpole 可用性标尺）；
3. **本仓实锤票**：#227–#231、#239、#259 这类「靠人肉走查才发现」的缺陷——每个都是候选维度；
4. **工程反例**：绿色门下的空判（#265/#266/#267/#269）——它们提示「该维度已有门但没测住」。

**第 2 步：写成判据（Criterion）**——一句话，主语是玩家或文本，不用「某某系统存在」这种结构：
- ✅ 好判据：「NPC 的每个让渡型行为，都能从登记动机推出」「任一玩家路径至少撞见关键结论 3 条独立线索中的 2 条」；
- ❌ 坏判据：「存在 NPC 动机表」「线索表非空」。

**第 3 步：选形态（Form）**——按成本从低到高：
| 形态 | 何时用 | 产出 |
|---|---|---|
| 只读报告 | 还没有稳定判据（先看数据） | 数字进基线，暂不 ratchet |
| 存在性门 | 只需防漏登记 | 红/绿，但**必须标注为仅登记** |
| 行为门 | 判据可行为化 | 正反例断言（scenarios/探针） |
| 人工走查清单 | 审美/手感/理解成本 | 清单＋结论入 `design-review.md` |

### 反例设计的第二条纪律：反例必须真的会变红（反面教训）

**实例（#295 C4 图gen 门首版）**：反例操作为「把 A 家族的路线复制给 B 家族的路线」，期望家族数下降，**实况 16 → 16**——那条路线只是换了个家族，旧家族剩下的人自成一族，**指标根本没动**。修正：牺牲品必须是**单成员家族**（独立内容真的消失），家族数才会 16 → 15 → 红。

**口径（与上面「门必须行为化」并列）**：
1. 反例的判据不能只验「结构变了」，要验「**该指标真的动了**」；
2. 写完反例**必须先跑一遍确认它变红**——不红＝等于没有反例，这是「绿灯空判」的另一种形态：**反例空判**。

（与 #265／#266／#267／#269 四个空判实例并列存档；来源：#295 实况复盘。）

### 另一类假绿：死开关（声明了门、实际永不执行；来源 #331）

`scripts/audit.mjs` 的 `--sel` 曾是**死开关**：`arg('sel').length` 在 boolean 上恒为 `undefined`，于是单独跑 `--sel` **只打收尾行、退出码 0**——看起来「这道门绿了」，其实一次都没跑。口径（与「覆盖 ≠ 验收」并列）：

1. **开关类入口要有「自己会红」的自证**：每个 flag 至少一条反例用例（人为破坏对应规则 → 该 flag 单独跑必须非零退出）；#316 的 golden 台账已为 `--sel` 补此用例。
2. **声明 ≠ 执行**：门清单里写了这道检查，就要有一条断言证明它**在无参数全跑与单跑两条路径上都真的执行**（打印计数／命中数为零时也要与「未启用」可区分）。
3. **默认路径优先**：能进无参数全跑的检查就别做成可选开关，减少「忘了开＝没跑」的假绿面。

> 判据来源 #331／修法 PR #332（对抗席发现）；本条是「假绿」家族的第 3 例（前两例：覆盖 ≠ 验收、反例空判）。

**第 4 例：原理上不可达的断言**（来源 #338／PR #339 实况）。为抓成对趋同，曾加断言「跨家族最大相似度 ≤ 0.92」——但家族本身就是按 ≥ 0.9 聚的，**任何越过 0.92 的配对早已并入同族**，该断言**永远不可能红**。反例自证当场把它证伪（「家族 18→17｜跨家族最大 0.741」）。口径：写完断言先自问**「它在原理上可达吗？存在能让它红的输入吗？」**——不可达的断言与不变红的反例同族，都是**纸面承诺**。现改为「每条路线独有 5-gram ≥50」这类真能咬的不变量。

**第 5 例：把本地观测值当不变量签进基线**（同一轮，CI 首次红）。第一版把本地观测值（家族数 = 18）签进基线做**等值判定** → 在 2 核 CI 上（轨迹细微差异、家族数 17）「正例」直接红。**这不是环境噪声问题，是设计错误**：ratchet 的阈值必须是**绝对不变量**（脚本内声明式常量：家族数下限 16／每条完整路线独有 5-gram ≥50／每拍 ≥3 条路线／E4 结构带），基线文件只做**漂移观测与阈值记录**（可见但不判定）。口径：**「本机能过」不是门成立的证据**——凡把观测值当阈值的门，都得先在另一台/另一核数上跑一次。

### 假绿家族第 6 例：**门未接线**（声明了门，流水线永不跑它）

同一天两处实锤：**#338** 相异度 ratchet（不在 `npm test`／CI，红了 4 个提交无人察觉）、**#343** D7 NPC 门（`--npc` 自 #253 交付起从未被跑，接线后当场抓到 1 处漏登记）。

**口径**：「注册了判定」≠「会执行」；新门**先接线再验证**（把接线当作交付的一部分）。本条已机检化——**事实源＝`docs/gate-ledger.md`（F2 台账，`npm run report:gates:update` 生成）**：逐门标注形态／是否有自证／是否接线，**仅登记或未接线必须写明理由，缺理由即红**。本手册不复制该表，只保留原则与第 3 例（死开关）的区别：**死开关是开关自己坏了，本条是开关没被任何人按下**。

### E4/C4 计量口径（#338 修订后，机检门已接线）

- **数据源**：`build/route-traces.json`（`test/scenarios.mjs` 当轮落盘），门紧跟 scenarios 进 `npm test`：**先跑 `--selftest` 证明反例会红，再用真实数据判定**。
- **C4 相异度**：字符 5-gram Jaccard **＋ 文档频率过滤**——被 ≥50% 完整路线共享的 5-gram 视为共享主线/框架文本（结果槽、跨时代共享旁白等）**不计入**；避免「同主线只有结局不同」的用例被误并。实测 DF 过滤后家族数 14 → 18，`乱翻的代价（星力软限）` 恢复独立族。
- **阈值（声明式常量）**：`clustersMin 16`｜`minDistinctiveGrams 50`（每条完整路线独有 5-gram 下限）｜`beatsMinRoutes 3`｜E4 结构带（≥5 击、≤25 击、情报 ≥3）。
- **降噪的推广价值**：**框架性文本**（每次渲染固定出现的槽/提示/导航）是路线间共享度最高的文字，任何「按文本相似度」的维度都要先剔除它，否则测的是框架一致度而非内容相异度。

### 「覆盖 ≠ 验收」的第五个实例：矩阵只做渲染，原理上抓不到存读档（#300 P1）

`test/saveui.mjs` 首版只把历史 fixture 经 `Game.Pc.migrate` 放进页面并渲染（**不实际 Save/Load**），末尾用「结果槽 ≤1 且文本在屏」判定——因此「门厅原地取物 → 立刻 S/L」这条路径**原理上不可能**被它捕获：P1 复现时该矩阵全绿。

口径（与上面两条并列）：
1. **覆盖清单必须写清「操作维度」**：不只是「场景 × 状态 × 视口」，还要含**操作时序**（原地行动 → 立刻存档 → 读档、跨段导航、跨周目）；
2. **UI 门若声明覆盖某状态，必须真的走一次该状态的完整生命周期**（保存/加载/回退），只渲染不算；
3. #300 修复后 `saveui.mjs` 已补**真实存读档往返**（取物 → save → 破坏 → load → 断言道具与「已翻找」态回来）。
