## 1. 渲染路径契约（#315 · 根因证据 #300）

### 规则

1. **就地反馈一律「结算 → 结果留屏 → `<<goto>>`」**；
2. **禁止「只靠就地 `<<replace>>` 落地的状态变更」**——判定式（机检同款）：
   link 体内**有 `<<replace>>`** ∧ **改状态**（直接：`<<give`/`<<damage`/`<<set $…`/`<<run $pc…`；
   **或间接：调用了一个自身会改状态的 widget**）∧ **没有 `<<goto>>`**；
3. 于是由此推出两条**合法**写法：
   - **改状态后接换段**（`<<goto>>`）＝合法，这正是契约形状——状态随换段进入 history moment；`<<replace>>` 与 `<<goto>>` 同时出现也合法（落地以换段为准）；
   - **就地 `<<replace>>` 只改纯界面态**（展开/折叠/开关/滚动/局部高亮）或临时变量（`<<set _x…>>`）＝合法。

### 为什么（不是洁癖，是存档语义）

SugarCube 序列化的是 **history moment**；同页 `<<replace>>` 修改的是当前活动状态、**不落 moment**，于是存档/读档后丢失。**#300 P1 实测**：门厅取物丢 `坏哨`、花田摘花丢 `月光花`、连 `last_roll`（本次检定记录）一起丢。两条路径在语法上几乎一样（都是 `<<link>>` ＋ 结果文本），**靠人记必出错**——所以必须有机械约束。

### 正确写法

```twee
<<link "把墙上那支哨子摘下来">>
    <<sitecheck "门厅·翻检">><<snapshot>><<hallResult "翻检">>
    <<goto "门厅">>          /% 结算完成 → 换段重渲染：状态随之进入 moment %/
<</link>>
```

结果如何留屏：交给 **#270 的结果槽**（`actOut` / `sceneFeedback` / `sgResult`），**不要**靠就地重绘。

### 机检（两条，缺一不可）

| 门 | 文件 | 断言 |
|---|---|---|
| 静态（**禁止制**） | `test/saveload-inventory.mjs` | 按规则 2 的判定式命中即红；**含 widget 间接变更**（`<<widget>>` 体内 `<<give/<<damage/<<set $/<<run $pc` 者视为「会改状态的 widget」）；确需例外须进 `test/saveload-sites.json` 的 `inPageMutationsAllowed`（理由＋票号） |
| 静态自证 | 同上 `--selftest` | 合规绿 / **非法红** / 纯界面态绿 / **widget 间接改状态红** / widget＋goto 绿 / 白名单失效红 |
| 行为 | `test/saveload.mjs` | 就地操作 → 立即存档 → 读档 → **物品/旗标/HP/金币/检定记录**五项保值 |

> 已有先例：`test/boot.mjs` 的 **dist 过期守卫**（#306）与本节同属「把隐性规则变成会咬人的门」。

## 2. 构建与模块顺序（#319）

### 规则

1. 加载顺序**显式**声明在 `scripts/module-order.mjs` 的 `ORDER`——**不再靠文件名前缀隐含**；
2. **登记分两层**（`#893` 第三步）：**引擎件**（`src/**`）每个都必须登记 `ORDER`（并进 `MODULES`，它们的先后是**全局**的）；**故事件**（`stories/<slug>/**`）每个必须登记**它自己的清单**（`00-story.json` 的 `files`，本就是有序的）。`build.mjs` 会拒绝「**引擎件**未登记 `ORDER`」「**故事件**不在任何清单」「`ORDER`／清单里列出的文件不存在」，以及「`ORDER` 里的非引擎孤儿」。
3. 跨文件依赖只声明**加载期**真实需要的边（`MODULES[file].deps`），且**只能指向更早的模块**；
4. `MODULES[file].defines` 声明该文件必须定义的顶层符号（`window.X` / `widget:X`），用于抓改名与挪位置。

### 为什么

文件名决定加载顺序时，新文件若命名成 `12-*.twee` 却依赖 `15-tables.twee` 的 `Game.*`，会**静默**先加载：构建不报错、运行期才炸，**症状还出现在别处**（看起来像别的问题）。

### 为什么不推断（本节的教训，值得记住）

初版尝试「**文本里出现即算前向引用**」的推断式 lint：对真实源码报了 **5 处**前向引用（`10-core.twee` 用 `Game`/`Sg.Codex`/`Sg.Ending`；`70-codex.twee` 用 `Sg.Codex`），**全是假阳性**——它们位于函数/方法体内，属**延迟求值**（`[widget]` 段落体与函数体在**首次被调用**时才执行，那时后面的文件早已加载完毕）。

因此本仓采用「**声明依赖边 ＋ 校验顺序与定义**」：宁少勿多、**零假阳性**；万一声明与实际脱节，由规则 ④ 的定义清单兜住（改了名/挪了位置就红）。

### 机检

| 门 | 断言 |
|---|---|
| `test/layering.mjs`（在 `npm test` 链里） | ① **两层登记**：**引擎件** ↔ `ORDER` ✓／**故事件** ↔ 它自己的清单 ✓（`#893` 第三步：**换登记处，不撤守卫**） ② 依赖边只指向更早模块 ③ 声明的定义真的在正文里 |
| `test/layering.mjs --selftest` | 合规绿 / **前向依赖红** / **引擎件未登记 `ORDER` 红** / **故事件无人认领红** / **引擎件被清单认领但仍须 ⊂ `ORDER` 红** / 定义漂移红 / 文件缺失红 / 清单列出文件缺失红 |

## 3. 状态契约（#318①②）

### 规则

1. `pc.ev` / `pc.world` 的每个键必须落在 `Game.State.domains` 的**某一个**场景域（按 `prefix` 或 `keys` 匹配），**归属唯一**（命中 ≥2 个域＝红）；
2. **只有写没有读**的键＝红；确属「**仅记账**」（消费者就是登记表本身，如出处/复访记账）的键必须显式写进 `Game.State.bookkeeping`，否则照旧红；
3. **只有读没有写**＝红（幽灵条件＝死分支）；
4. 扫描必须覆盖**三类动态形式**：`<<setflag/<<firstTime>>`（动态写入并动态读回）· `$pc.ev["k"]` · 表内谓词 `p.ev?.k` / `p.world?.k`。**不覆盖这三种就会误报**——本仓实测踩过两次（先是把动态写误判成未声明，后是把 `p.ev?.keeper_why` 误判成「只有写」）。

### 为什么

81 个状态键散在 9 个 `src` 文件里自由命名，此前**没有任何一处**能回答「当前有哪些键、谁写、谁读、语义是什么」；新增键无需任何声明即可通过全部门。

### 现状（2026-09-12 首轮）

`81 键 / 10 域`：`tavern 13 · witch-hut 14 · forest 6 · keeper 4 · tower 13 · flower 4 · seer 6 · banquet 7 · dragon 10 · runtime 4`；
仅记账键 4（`tav_light`/`tav_iron`/`tav_seal`/`banquet_over`，已声明）；未声明 0 · 歧义 0 · 只有写 0 · 只有读 0。

### 机检

| 门 | 断言 |
|---|---|
| `audit --state --check`（在 `npm test` 链里，并纳入 golden 保护） | 上列四条 ＋ **5 例合成自证**（未声明红 / 只有写红 / 只有读红 / 歧义红 / 合规绿） |

## 4. 常量与字面量（#318③）

### 规则

1. **时代**一律用 `Game.Era.PAST` / `Game.Era.PRESENT`（代码路径：条件、赋值、模板）。
   字面量 `'past'`/`'present'` 只允许出现在 `15-tables.twee` 的**数据字段**（`era:` / `flagEra:`）与 `Game.Era` 定义行；
2. **伤害**一律用 `Game.Damage.*`（`graze 1` / `hurt 2` / `hard 3` / `heavy 4` / `lethal 99`）；
   剧情文件里禁止裸 `<<damage N>>`；
3. ⚠️ **SugarCube 宏的裸词参数会被当成字符串**（本仓 integrity 门记过的「坑11」）——所以必须写
   **backtick 表达式**：`<<damage \`Game.Damage.lethal\`>>`。写成 `<<damage Game.Damage.lethal>>` 会静默传字符串，
   把 `hp` 变成 `NaN`（**本轮实测踩到**：`龙·再冲` 因此无可点元素，被 render-all 抓住）。

### 为什么

`<<damage 99>>` 无法回答「99 是什么意思」（它是「处死」的魔法数）；而 `$era is "past"` 拼错一个字母会**静默失效**（条件永假、不报错）。

### 现状（2026-09-12）

- 代码路径时代字面量：**37 处已替换**为 `Game.Era.*`；
- 伤害裸数字：**10 处已替换**为 `Game.Damage.*`（含那处 `<<damage 99>>`）；
- 剩余字面量：**仅 `15-tables.twee` 数据字段 11 处**（按设计，由门校验取值）。

### 机检

| 门 | 断言 |
|---|---|
| `audit --literals --check`（在 `npm test` 链里，纳入 golden 保护） | 两条判定 ＋ **5 例合成自证**（常量绿／裸时代红／裸伤害红／数据字段绿／常量定义行绿） |

## 5. CI 测试计划与并行跑器（#381）

**单一权威**：`scripts/test-plan.mjs` 的 `SEGMENTS` 是「CI 跑哪些段」的唯一定义。**不要**再往
`package.json` 的 `test` 脚本里塞 `&&`——那里只有一行 `node scripts/run-tests.mjs`。

```js
{ id: 'test-reread-mjs', phase: 'test', cost: 0, cmd: 'node test/reread.mjs --selftest' },
{ id: 'test-reread-mjs-1', phase: 'test', cost: 0, cmd: 'node test/reread.mjs' },
```

| 字段 | 含义 |
|---|---|
| `id` | 稳定标识（`--only=<子串>` 用；同段重复运行加 `-1`/`-2` 后缀） |
| `phase` | `build` 的段**先跑且独占**（后续段都可能读 `dist/`）；其余段可并行 |
| `cost` | 本机实测秒数（**仅供跑器打印串行合计与预估**，不参与任何判定——不要求精确，但新增重段请顺手填） |
| `needs` | **前序段的产物依赖**：本段要读某段落盘的产物就写它的 id。调度器保证前序全部成功才起跑；前序红了/跳过 → 本段标 `skipped`（不白跑、不假绿）。配错（指向不存在的段）或成环 → **起跑前**报错退出 2 |
| `cmd` | 与旧链**逐字一致**的 shell 命令 |

**跑器**（`scripts/run-tests.mjs`）：

```bash
npm test                                   # 并行（默认 jobs = min(4, 核数)）
npm run test:serial                        # 串行＝旧链行为（排查/对照）
npm run test:list                          # 列出计划与串行合计
node scripts/run-tests.mjs --jobs=2 --only=scenarios   # 调试单段
```

- **退出码**：`0` 全绿 / `1` 有段失败 / `2` 用法错或**选择为空**（空选择不许当绿）；
- 失败段的 stdout/stderr 会被原样打印（尾部 28 行）并汇总「哪几段红」——**不吞输出**；
- 跑器**每次运行先自证**（成功/失败识别、失败输出不吞、并行真的重叠、`phase:'build'` 红即中止；约 2s，`--no-selftest` 可关）。判「CI 绿不绿」的东西，自己坏了必须当场暴露。

**产物依赖面**（改测试的落盘/读取时同步这里——CI 曾因漏掉它红过一轮）：

| 产物 | 生产者 | 消费者 |
|---|---|---|
| `build/coverage-render.json` · `build/coverage-links.json` | `test/render-all.mjs` | `test/coverage.mjs` |
| `build/coverage-scenarios.json` · `build/coverage-links-scenarios.json` · `build/route-traces.json` | `test/scenarios.mjs` | `test/coverage.mjs`（前两个）· `scripts/report-rhythm.mjs`（`route-traces.json`，**连 `--selftest` 也用它当正例**） |

**新增门的三件事**（缺一即红）：

1. 往 `SEGMENTS` 加一段（不是往 `package.json` 加），读前序产物时写 `needs`；
2. 台账 `docs/gate-ledger.md` 的「已接线」列来自 `planChain()`，所以只要段在计划里就会自动判定 ✓；但 `npm test` **必须仍是 `node scripts/run-tests.mjs`**——`report-gate-ledger.mjs` 有 `phantom-runner` 反向查，脱钩即红。

**「跳过」不许静默（#363/#385 族）**：验收类脚本在**前置条件不满足**时只打印锚点行并退 0，会让绿灯含义失真（看着跑了、其实一行断言都没跑）。约定：

- 需要真机/真浏览器的脚本，**守卫下沉到脚本**：`CI_REQUIRE_BROWSER=1` ⇒ **跳过即失败**（`test/browser.mjs` 已实现；调用方只需给这个环境变量，不要再内联 `grep skipped`）；
- **断言数下界自 ratchet**：下界写在脚本里（`MIN_ASSERTIONS`），**跟着断言数走**——删断言即红。不要在 workflow 里写魔数（曾写 `N -ge 24`，而实际已 38，删 14 条也放行）；
- 稳定锚点（`BROWSER_ASSERTIONS n/m` / `… skipped`）保留给人读，但**不要**让 CI 依赖解析它。

**成本口径（2026-09-12 实测）**：53 段 · 串行合计 **197s**（本机 32 核）/ **186s**（`taskset -c 0-3`）→ 并行 4 核 **54s**（**3.4×**，53/53 绿）；CI `npm test` 原为 **207s**（环境准备仅 17s）。新增段时请自问：这段的 `cost` 是否值得？单段 > 60s 或串行合计 > 4 分钟就该先优化/拆分。

## 6. 断言口径：**信息可见** vs **键盘可续**（#304）

就地反馈（`<<replace>>` / 结果槽）这一带的断言经常**假红**，根因是它把两件事写进了一条断言、并且绑定了**具体元素**：

| 维度 | 该验什么 | **不要**验什么 |
|---|---|---|
| 信息可见 | 「本次内容**在屏**」：槽存在、未 `hidden`、文本含本次内容（`passageText` / 槽 `textContent`） | 不要用 `document.activeElement.textContent` 当可见性证据 |
| 键盘可续 | 「**焦点仍在 `#passages` 内**」（`activeElement.closest('#passages')`） | 不要绑定「焦点落在 `.fresh-heard` / `[data-heard=…]` / `.soc-said`」——共用层一改反馈目标就红（#304 实证） |

理由：焦点落在**哪一个**元素是实现路径（仓里有三条：就地反馈定位 / 子对话返回到行动区 / 丢焦时的回收），会随后续共用层调整而变化；而「信息在屏」与「焦点没跑出正文区」是**用户可感的契约**，稳定且可机检。

**这类断言的实测咬合力**（改测试时请照做）：只关掉「丢焦回收」不应该红（那是安全网，不是契约）；**关掉「就地反馈定位」＋「丢焦回收」才应该红**——这才是它负责的那一类回归（焦点跑到 body）。写新断言前先跑一遍确认它真的会红，否则就是空判。

**门**：`test/globals.mjs`（入 `npm test`）：

- **A1** 出现**新的裸全局** → 红（不在白名单、也不匹配 `^(Game|Sg)`）；

## 8. 定位与断言分离：选项用**稳定 key**（#317②）

**规则**：测试里定位一个选项，用**目标段落名**（派生 key），**不要**用中文文案；文案只用于**断言**。

| 做什么 | 用什么 |
|---|---|
| **定位**（点哪一条） | `click(key)` / `clickByKey(key)` / `byKey(key)` —— key ＝ `data-choice`，由 `src/80-script.twee` 末尾的派生 pass 写入，值＝**目标段落名**（内容骨架，改文案不动它） |
| **断言**（点完对不对） | 仍然用文案／状态：`text().includes('…')`、`passage()`、`pc()` |
| 歧义处（同一段落里多条链接指向同一目标） | 给容器加 **`data-key="…"`** 显式覆盖派生值 |

**为什么**：文案是**最常改**的东西，而它曾是测试的**定位键**——实测改一句文案连动 5 处测试调用点。
key 用目标段落名后，两者解耦：`keyOf(el)` 返回三元组 `{ choice, authored, label }`（派生值／作者覆盖／文案），
`test/scenarios.mjs` 每次跑都会打印 `定位方式：key N 次 / 文案 M 次`，迁移进度可见。

**门 `test/choice-keys.mjs`**（入 `npm test`）：逐段落（`$era` 段跑双时代）× 渲染态枚举派生 key，
若同一渲染态里出现 **≥2 条相同 key** → 红（两条链接目标相同但**副作用未必相同**，`clickByKey` 会静默点到第一条）。

## 9. 「自证」的有效性条件（#342 F2 收尾沉淀）

补自证的目的是**让判据真的有牙**，而不是让台账上的"行为化率"好看。因此：

1. **打印了 `自证·<label>` ≠ 自证有效**。有效的最低条件是两条，缺一不可：
   - **①失败必须计入退出码**（`--check` 时退 1）——否则自证只是"打印了一行 ✗"；
     本仓实例：`⓪q 选择后果门` 原本**没有** `bad` 变量、`--check` 只看 `problems.length` ⇒ 自证一失败要么崩、要么没人管（`#470` 修）。
   - **②失败路径不能崩**——否则"该判红"会变成栈回溯（更糟：可能被当成环境问题忽略）。
2. **计数器声明必须早于任何使用**（TDZ）。本仓实例：龙战门的 `let dragonBad = 0` 写在**使用点之后** ⇒
   只要真有"破坏平衡的道具"，门自己就会崩（今天数据里没有 ⇒ 长期没暴露）；`#471` 修。
3. **抽纯函数时，方法不要裸传**：`f(C.pick)` 会丢 `this`（`#467` 撞到 ⇒ 门直接崩），要包一层 `(…args) => C.pick(…args)` 或把依赖参数化。
4. **注入式判据**：凡"判据住在共享分类器/工具里"的门（如 `classifyNarrativeState()`），
   给该工具加**可选注入参数**（默认取真实来源 ⇒ 向后兼容），否则等于"用被测对象证明被测对象"（`#470`）。
5. **自证抓到的错，大多不是笔误**：本轮 9 门补自证共抓出 **8 处**问题，其中
   浮点边界陷阱（`0.501-0.5 < 0.001`）、语义算在插入序而非章序、`this` 丢失、TDZ —— 都是**判据或基础设施本身的缺陷**。
   ⇒ 自证的价值主要在这里，而不是"多打几行 ✓"。
8. **补断言前先量"边际检测力"**（`#608` 交叉验证沉淀，`#668`）：发现"判据依赖某个假设"（例：相位门的用例全是
   `成功＋未结束`／`clear＋成功骰` 的组合，于是"成功支＝结算支"这个假设从未被验）时，**先补两条交叉用例，再数红数**——
   装两种错法各跑一遍，若"补前/补后"的**红数完全相同** ⇒ 边际检测力 **0** ⇒ **删掉那两条**，把假设与两次实测红数**写进头注**。
   - 为什么不能"加了就算"：零边际断言会让门**看起来更严**（用例变多）而**实际不增判别力**，还抬高维护面；
   - 判据一句话：**新增用例必须能改变"至少一种错法下的红数"**，否则它只是仪式（`#640` 的四向探针即按此验过）。
9. **前 1、2 条已由机器兜住**（`#474` 接线）：`scripts/report-selftest-validity.mjs` 静态扫描全部 `scripts/`＋`test/`
   —— 出现 `自证·` 就必须有「**被增量的计数器进了可达 `process.exit` 的条件**」；任何 `X++`／`X += …` 的声明
   也必须早于使用（置后的按**警告**报：闭包里合法，静态判不了调用序）。已入 `npm test`（`scripts/test-plan.mjs`）
   ＋台账翻 `wired` ⇒ 手工复核降级成"读报告"；**要绕过得写进脚本的 `WHITELIST` 并写理由**（白名单腐烂会报红）。
   踩坑留档：这台检测器**自己**曾被自己的剥离器误报（用四条正则**顺序**剥注释/引号串/模板/正则 ⇒ 任一层都能
   与另一层**跨行贪婪错配** ⇒ 整段代码被抹成空白 ⇒ `counters` 空 ⇒ 判「不能判红」；同一次错位也造**假阴性**）。
   **换顺序治不了**（先剥正则 ⇒ 正则吃掉模板收尾 backtick；先剥模板 ⇒ 模板吃掉正则里的 backtick）；
   正解是**单扫描器按 JS 词法一次遮蔽**，未闭合的保守剥到行尾**并打印诊断**（反沉默：宁可报可疑，不可静默错下去）。

6. **判据变更 ≠ 补自证**：自证过程中若发现判据本身该收紧/放宽（例：`npc` 的旗标判据把"只出现在块注释里的旗标"也算位点），
   **不在补自证的 PR 里顺手改**（一个 PR 一个自变量）：先用一条自证把**现有语义**钉住并写明观察，改动另开一次。

## 10. CI 作业分层：**只改文档就不跑真机/确定性面**（#520）

**规则**：PR 的**全部**改动文件都落在「文档面」（`docs/**` 或任意 `*.md`）⇒ `soak` job **跳过**；否则照跑。
判据由 `changes` job 给出（`gh api .../pulls/N/files`，无 checkout，≈3-5s），跳过的理由留在 run 页上
（`soak: skipped` ＋ `changes` 的输出）——**不做静默降级**。

**为什么**：实测纯文档 PR（`#515`）的 run 仍 **167s**，其中 soak **124s**（walker 60s ＋ 真机浏览器 24s
＋ playwright 装机 19s ＋ build 6s），对文档改动**零价值**；而 `npm test`（98s，含文档相关门：
台账新鲜度／golden／计划一致性）**照跑**，所以"文档改动"这件事并没有失去保护。

**两条硬边界**（都不许放宽）：

1. **失败开向 = 照跑**：算不出改动面（API 失败／空列表）⇒ `code=true`，**不静默少跑**；
2. **push（main）恒 `code=true`**：`deploy` 依赖 soak，main 上这一段不省 ⇒ 发布前的全量验证不变。

**有意不缩覆盖**：soak 的 10+10 局与「位点双支清扫」照旧（双支是确定性定向扫描，与局数无关）；
每晚 `soak-nightly` 另有 30+30 × 3 种子的更强兜底。**只跳"与本次改动无关"的那一次，不砍判据本身。**

**顺带记录两条否定结果**（实测过，避免重复走）：① 调度改 LPT（最长段优先）无效——同一套 `npm test`，
FCFS **81.3s** vs LPT **84.3s**；②「每个测试段各自 boot JSDOM」不是大头——boot **0.6s**/次、
完整 `newGame` **1.0s** ⇒ 16 段合计 ≈24s，重构测试基建不成比例。

## 11. 故事文本源与「归属面」（`#435` 前置 0）

**单一权威**：`scripts/audit/lib/shared.mjs` 的 **`storyText()`** —— `段落名 → 故事文本`，其中
**故事文本 ＝ 内容段落原文 ∪ 归属到它的条件表行 `text`**（归属＝行 `scope` 的 `#` 前那一截；多行按**表序**追加）。

**规则**：
1. 凡判**正文**的门（锚句/禁词/代词/传说线/臂数/措辞密度/总字/位点）一律从 `storyText().text` 取文，**不再** `passageSrc.get(p)`；
2. 凡判**条件**的门，除段落里的 `<<if>>` 外还要认**表行的 `req`/`any`/`exclude`**（`--echoes` 的 `rowCondsOf()` 是范本：表侧条件与段落条件**同一份判据**）；
3. 表行归属到**不存在的段落** ⇒ 不静默：`--rules` 判红（`scope` 是结构，不是备注），`storyText().orphans` 交调用方报告。

**为什么**：阶段 4 之后「这段话属于哪个段落」由**归属**决定。一次搬家实测**同时红六道门**
（`--truth`/`--echoes`/`--npc`/`--notes`/`--interact`/`--text`）——那不是六个 bug，是**一个横切面**（门的文本面窄了）。

**已接线的面**（`#435` 前置 0）：`truth`·`echoes`·`npc`·`notes`·`interact`·`text`·`choices`·`craft`·`canon`·`systems`·`investment`(G2/G4/G3-存在性)；
**已知边界**：`--investment` G3 的「登记合龙门」条件面仍只在段落里找（等它真搬进表时再接）。

### 条件语言的键形（`#435`，2026-09-14 拍板）

`req`/`any`/`exclude` 的键形：`n_*` note id ∕ 裸键名 ∕ `ev.x`／`world.x`（状态路径）＋ 两种**前缀形**：
**`inv:<道具>`**（持有物）· **`era:<时代>`**（`past`/`present`）。
**前缀必须由引擎宣告**：`Sg.rules.prefixes`（与引擎侧 `holds()` 的求值能力一一对应）—— 行里用了未宣告的前缀 ⇒ `--rules` 判红。
理由：引擎不认的前缀会让条件**永假** ⇒ 行静默死掉（最坏那种 bug）。前缀键**不参与**状态契约（`--state`）与旗标分级（D2）——持有物与时代本来就不在 `pc.ev`/`pc.world` 域里。

### `text` 里的分支：判定结果 → 两段文案（同一次拍板）

**允许** `<<if>>`/`<<elseif>>`，但只许读**渲染期只读槽**：`$last_check`（判定结果槽）与 `_` 前缀局部量。
**禁止**在分支里读状态／时代／持有物／笔记 API（`pc.ev`·`$era`·`inv[…]`·`Sg.notes.*`）——那些属**条件面**，请写成行的 `req`/`any`/`exclude`（`--rules` 机检，白名单带理由）。
**为什么允许**：判定结果 → 文案属**渲染**（与 `<<lastcheckFor>>`/`<<checkres>>` 同一条渲染链）；把"判定面"外置就得让表声明检定/DC/骰 ⇒ 那才是把**机制**复制进表。

### 授予家族三类：`yields` / `gives` / `sets`（`#435` Q1 拍板）

行声明**授予**，`<<rules>>` 渲染成功后统一执行（写点恒在一处）：`yields` 笔记 · `gives` 物品 · **`sets` 状态键**（布尔置真，≡ `<<setflag "k">>`）。
`sets` 的三条收窄（都可机检，就是为了不让"表＝脚本"）：
1. 键必须是**已登记的状态键**（裸键或 `ev.`/`world.` 限定；复用 `--state` 域表）；
2. **有笔记的键不得进 `sets`**（必须走 `yields`——否则同一知识两条写路，正是 `#434` 用 fail-loud 挡的）；
3. 只许**布尔置真**；数值/枚举写不在内（另票）。
**反沉默**：引擎要在 `Sg.rules.effects` 里宣告兑现的面（与 `prefixes` 同轴）——行里用了未宣告的面 ⇒ `--rules` 判红（引擎不兑现的声明＝静默空转）。
`--state` 同步把行的 `sets` 当**写点**（否则只经 `sets` 写的键会被判"只有读"）。

### 键形与命名空间的边界（同日修正两条）

- **键形**（`--reads`）：note id ∕ 裸键（默认 `ev.`）∕ **任意域的状态路径**（`ev.`/`world.`/`keeper.`/`star.`…）∕ `inv:<道具>`／`era:<时代>`。
  修正①：原先只放行 `ev|world` 两域 ⇒ 误杀 `keeper.met`／`star.spent` 这类**第三命名空间**。
- **状态契约面**（`ruleRowKeys()`/`ruleRowFlags()`）：**非 `ev`/`world` 域的键跳过**（它们不在状态契约域里，今天也看不见）——修正②：
  不跳过的话 `keeper.met` 会被当成裸键 `met` ⇒ `--state` 报"未落入任何域"（引入一个今天不存在的假红）。

## 12. 故事作用域：故事门的**分析宇宙**（`#460`／`#441-E`）

**规则**：一个故事的**分析宇宙** ＝ **引擎文件**（`MODULES.layer === 'engine'`）∪ **该故事 `00-story.json` 声明的 `files`**；顺序由 `ORDER` 决定。
**单一权威**：`scripts/module-order.mjs` 的 **`scopedFiles(story)`** —— 构建（`build.mjs`）与门（`scripts/audit` 的 `createContext`）**共用同一份**（各算一次就会出现"产物是 A、门在判 A＋B"的错位）。

**为什么必须是硬规则**（spike `feat/460-minimal-demo` 实测）：宇宙若＝全部源文件，第二个故事会
① **污染**第一个故事的指标（同名段落、载荷统计、最薄段落榜、密度基线）；② **又被**第一个故事的判据要求（段落登记手册、覆盖宇宙、可达性）。
⇒ 一次引入就 4 段门红，根因只有一句：**故事门没有故事作用域**。

**现状（三个故事）**：`mist-forest`（故事 1，默认）· `minimal-demo`（第二故事，**接入契约的自检夹具**）·
`hollow-cave`（第三故事，`#490` S5 雏形：**唯一声明了 S1–S4 四件套的故事** ⇒ 那四道引擎门在这里判真数据）。

**用法**
- `node scripts/audit.mjs --story <slug> [--engine-only] --check`；默认故事（`mist-forest`）⇒ 与改前**逐字节相同**（golden 零漂移）；

**引擎保留的运行时槽（接入契约的一部分，`#460` 补齐）**：引擎自己会写这几个键

`stories/mist-forest/12-widgets.twee`；`StoryCaption` 的「📖 设定集」链接改成**存在才渲染**（`<<if Story.has("设定集")>>`），

### 条件项两种形状：字符串键 ／ **对象算子**（另票口径，门侧先就位）

**`#624` 落地的两处延伸**（机制侧已合 `2c0ba99`／`269…`）：

|---|---|---|
| 字符串 | `'n_flower_warned'` · `'fog_thin'` · `'world.x'` · `'inv:日记'` · `'era:past'` | 键为真 |
| **对象算子** | `{ gte: ['star.spent', 3] }` · `{ lte: ['hp', 1] }` · `{ oneOf: ['keeper.state', ['seal']] }` | 数值/枚举比较 |

- **算子词表由引擎宣告**：`Sg.rules.ops = ['gte','lte','oneOf']`（与 `prefixes`／`effects` 同轴的反沉默：用了未声明的算子 ⇒ `--rules` 判红——引擎不认的算子会让条件**永假**＝行静默死掉）；
- 门侧只取**键**参与状态契约（`--state`）与旗标分级（D2）（阈值/算子不进契约）：单一权威 `condKeysOf()`；
- `--reads` 的键形态与 `premise-source` 的依据键都认这个形状；
- **`$pc.hp gt 0` 这类护栏不算"未搬条件位点"**（它不决定哪段文案被选中）——票面记账时单列，不进门的判据。

### `yields` 的两种形状：note id ／ **`{ id, path }`**（多源笔记的路径选择）

多源笔记（`n_study_hint`＝`world.study_hint` ∨ `ev.study_found`）没法用 `Sg.notes.add` 的 fail-loud 默认路径 ⇒ 行里必须**声明走哪条**：
`yields: [{ id: 'n_study_hint', path: 'world.study_hint' }]`。
门侧判据（`--rules` 的 `yieldPathProblems()`）：`path` 必须**属于该笔记的 `flagPath` 集合**，否则红——防"声明了一条不存在的路径"（写进去读不出来：`Sg.notes.has` 永不成立）。

## 12.5 引擎/故事边界：**三档机检**（`#660` 片三-0 / 片三-2）

`--engine-story-free` 现在有**三档**（同一个门，不是三个门）：

1. **字面量档**（`#602`）：**引擎门**（`scripts/audit/gates/**` 里声明进 `AUDIT_ENGINE` 的那些）里不得出现**故事专有 token**
   （段落名、故事侧 `Game.<X>`）；判据数据请放 `stories/<slug>/audit.json`。
2. **成员档**（`#660` 片三-0）：**引擎源文件**（`src/**`）里不得**直读故事数据成员**。规则＝「出现故事表的**成员名**（含**一层别名**
   `const T = window.Game` 之后的 `T.<成员>`、以及**在故事表上挂方法时的 `this.<成员>`**）、且未登记白名单 ⇒ 红」。
   - 成员集**自动从故事声明面抽**（把故事 `[script]` 段在 vm 里跑一遍取自有键）——不手维护；
   - 白名单键形 `<引擎文件>::Game.<表>.<成员>`，每条**必须写移除计划**，且**腐烂即红**（不再命中 ⇒ 报，逼你删）；
   - **已知漏（静态不可判，故意不上数据流分析）**：`const { events } = Game.Economy` 之后裸用；`this.<成员>` 在没有
     `Object.assign(window.Game.X…)` 包着时。两者都在门的自证里**断言"它会漏"**（避免误以为门全知）。
   - 口径提醒：`21-resolve.twee` 的头注记着「层间门按字面量匹配，这里**曾用别名 `T.Game` 躲过它**」——
     成员档正是为这一幕加的（追别名只为**少误报**，不为抓漏）。
3. **存在性探测档**（`#660` 片三-2）：**引擎源文件**里不得用「**这张故事表在不在**」的探测去摸故事表。形状（只咬**裸表名**）：
   取反 `not Game.X` / `!Game.X`、空合并 `Game.X ?? y`（**不含声明式 `??=`**——那是引擎在自己命名空间上挂成员）、
   `null` 比较（`== null` / `!== null`）、真值用法（`Game.X && y` / `Game.X || y` / `Game.X ? a : b`）。
   - 为什么单开一档：`<<elseif not Game.Chargen>>`（`src/10-core.twee` 的侧栏分支）**既是边界破口**（引擎知道故事的全局名），
     又是**最爱藏在条件里**的那种——成员档咬不到它（没有 `.成员`）；
   - 口径：**故事表在不在，必须问接入契约**（如 `Sg.story.hasChargen()`）。引擎**只问"有没有"**，不把故事全局再拿回去
     （对照：`Economy` 片三-1 是"**只给表**"，因为引擎要用表里的数据）；
   - 误报控制：表名必须在**自动抽取的故事表集**里；注释已遮；**成员/调用**（`!Game.X.m()`）不算表探测（归成员档）。
   - 边界：引擎**自己**声明的表（`Game.Era`/`Game.Damage` 等 `CONST_SECTION` 常量）不在故事表集 ⇒ 天然不参与本档。
   - 自证 6 例（正/反/三条边界＋`??=` 声明式边界）；真实位点修掉后**命中 0 处**，白名单**不新增条目**（本档起步即零豁免）。

### 12.5.1 F4（文档里的仓内路径）两类边界（`#617`／`#606` 抽验沉淀）

`md-format` 的 F4 只咬**一类**陈旧引用，另**一类必须放行**（两类的判据都在门的自证里，这里给"给人读的两行"）：

## 12.6 域表的归属纪律（`#660` 片三-4）

**域表是故事数据**：`Game.State.domains` 住 `stories/<slug>/15-tables.twee`（第二/第三故事各一份，例：`minimal-demo` 只有一个
`runtime` 域，note 写着"引擎保留的运行时槽（每个故事都要登记）"）。三条纪律：

1. **引擎不声明域**，也不许拿引擎常量去"补"一份域表（域表描述的是**这个故事的**状态词汇）；
2. **引擎写点必须在每个故事的域表里找到归属**——引擎保留槽（`ev.last_result`／`ev.last_roll`／`ev.soc*`／`ev.fight`／`ev.ending`…）
   在各故事都有域，否则 `--state` 会红（`未落入任何域`）。**新增引擎写点 ⇒ 同步三个故事的域表**（这是"引擎改了、故事没跟"的典型漂移）；
3. **读侧口径同 `#569`**：**经历走键、知识走笔记** —— 引擎不得把"知识"写进 `pc.ev.*`（那是 `Sg.notes` 的活），
   写点要么是**经历/运行时槽**，要么在故事域表里有明确归属。

**这条纪律是可机检的（不只写在文档里）**：`scopedFiles(story)` ＝ **引擎文件 ∪ 本故事文件** ⇒ `--state` 的域表判定**天然覆盖引擎写点**；
`test/story-runtime.mjs` 的 `[域表纪律]` 段把这个**机制**钉住（每故事两条断言：作用域 ⊇ 引擎文件 · 引擎写点全有归属），
反向探针两条都验过：① 把某故事的 `runtime` 域删掉 ⇒ `--state` 点名 `last_roll`/`last_result`/`ending`/`fight` **未落入任何域**（rc=1）；
② 让 `scopedFiles` 不再含引擎文件（作用域只剩本故事）⇒ `[域表纪律]` 立刻红（防"门静默退化成只查故事写点"）。

## 13. 取证方式必须**可复算**（`#557` 的教训）
`#557` 实测：`ui-migration-diff` 的清单仍写 `src/<name>.twee`，而故事文件已搬到 `stories/mist-forest/`
⇒ **基线与工作区都解析出 0 段** ⇒ 输出「变更 0 段」并 **退 0**。于是 `#435` 批三引用的「`--zero` 退 0 ✓」**是空跑**。
⇒ 结论一句话：**「退 0」本身不是证据**，必须能回答"它解析了什么输入"。

**四条硬纪律**（门与探针都适用）：

1. **解析不到输入 ⇒ 红**：任何"零漂移／零命中／全绿"的判据，都要先断言**输入非空**
   （工作区侧与基线侧**任一侧 0 段即红**，且不分是不是 `--check`——读不出输入就该响）。
   *为什么*：所有"两边都空"的假绿都长这样（`0 === 0` 永远成立）。
2. **清单与单一权威同源**：不许在门里自己拼路径。工作区侧取 `scripts/module-order.mjs` 的
   `MODULES`／`ORDER`（`scopedFiles()`），基线侧取 `git ls-tree` —— 两侧取**并集**，
   于是「本 PR 删掉一个正文文件」也看得见。
3. **每条"零 X"结论配一条能翻红的探针**：把真输入改一个字（`sed -i 's/正则/探针/'`）⇒ 必须报"检测到变更／命中"；
   探针（含改前/改后的实际输出）写进 PR。没有探针的"零漂移"结论一律**当未取证**。
4. **引用别人的门结论时，写清三件事**：命令 · **它解析的输入面** · 解析到的数量。
   只抄一个"退 0"会把空跑传染给下一个引用者（`#435` 批三就是这么被传染的）。

**推荐取证形状（`#435` 批四实测）**：**基线独立 worktree × 工作树**两侧各自渲染，再**逐字节对照**
（比"跑一个门看它退 0"更强：对照面是产物本身，不依赖门自己解析得对不对）。

**另一条同族纪律：覆盖范围要自报（`#619` 片二）**：`ui-migration-diff` **只对默认故事**（`mist-forest`）
做判定，其他故事「**只登记、不判定**」——所以它的输出**必须打印覆盖范围**（报告头也写），
防止读者把"故事 1 的绿"当"三个故事都判过"。同类工具照此：**能覆盖什么、不能覆盖什么，写在输出里**，不只写在手册里。

### 读点两个口径：`readKeys()` vs `literalReadKeys()`（`#437` 批二）

| 口径 | 含义 | 谁用 |
|---|---|---|
| **`readKeys()`**（单一权威，含**封装层读**） | "谁读了它" —— 直读（`p.ev.x`／`$pc.ev.x`）＋ 封装层读（`Sg.notes.readPath(p, 'ev.x')`） | 消费可数（`--notes`）· 旗标分级（D2/`--consequences`）· 状态契约（`--state`） |
| **`literalReadKeys()`** ＝ `readKeys()` − 封装层读 | "**绕过封装层的裸读**" | 「无字面状态读」门（`--reads`）与它的知识键基线 |

- **为什么必须分开**：表里的谓词从 `!!p.ev.x` 改成走封装层之后，**它仍是读点**（消费点不该消失）但**不再是裸读**——一个口径会让改一处就假红另一处（`#437` 批二实测）。
- **顺带修掉的潜在 bug**：`readKeys()` 的"写行不算读"用 `\b` 判 `= true`——`=` 与空格都不是词字符 ⇒ **赋值行被当成读**（旧基线里那 9 条"知识键直读"其实一半是 `apply:` 里的赋值）。现改用 `(?:=(?!=)|to(?![a-z]))`。
- **第三份口径已收编**：D2 的"图鉴桶"旗标集合原来自带一条 `p.ev.X` 正则，谓词改走封装层后**静默失明**；现在＝直读 ∪ **封装层读**（`wrappedReadKeys()`）。
- **读知识走笔记（`Sg.notes.has`），读分支/经历面走键（`Sg.notes.readPath`）** —— 与 §1 的层归属一致；两处都能被 `readKeys()` 数到。

**出处**：`#491` 已定 ⑩——"要有调试开关，且限定为**构建期/URL 参数**（如 `?seed=123&pool=short,long,chest`），**不进玩家 UI**"。

| 开关 | 作用 | 生效范围 |
|---|---|---|
| `?seed=<n>` | 固定整局骰子（内联 mulberry32 ⇒ node 与浏览器同序列） | 只影响 `Game.Rules.rng`（**不动**规则/数值表） |

2. **不进玩家 UI**：开关**不渲染**任何东西（无菜单项、无按钮、无文案）——门会断言"带参数与不带参数，玩家可见文本一致"；
3. **只改随机与池**：不许用它改数值表/规则（要改数就改声明表，那是可审计的变更）。

**门**：`test/story-runtime.mjs` 判据 ⑩（同 seed 两次逐字节一致；不同 seed 至少一处骰面不同；`?pool=` 只出指定类型；带/不带参数玩家可见文本一致）。

## 15. 仪器 vs 规格：**随机游走不是门**（伞 `#626`；沿革 `#27` → `#628`/`#629` → `#630`）

**判据**：门禁只放两种东西——①**可枚举的覆盖**（例如 coverage 门4「时代双态」：按 `$era` 分叉的段落两态都要被踩到）；
②**可机检的规格**（场景 × 道具/线索集合 → 期望：可见选项 key 集合／状态增量／去向段落/结局）。
**随机游走**两者都不是：它断言的是"**这 N 条抽样路径上**没崩、不变量没破"——绿＝没抽到问题，**不是**"行为符合预期"。

**现状（2026-09-14 起）**：

| 面 | 地位 |
|---|---|
| PR 门（`ci.yml` 的 `realmachine` job，旧名 `soak`） | 只跑**确定性**部分：位点**双支清扫**（`node test/walker.mjs 0 0`，实测 68 位点 ≈3s）＋ 真机浏览器断言 |
| 夜间（`soak-nightly.yml`） | 多种子随机游走照跑，**report-only**：失败**不阻塞合入**，而是**开票留痕**（`[soak-nightly]`，同形态不重复开） |
| 覆盖口径 | 本就不吃它：`test/coverage.mjs:24`（`#27` 的降级决定）以 scenarios 为输入 |
| 缺口可见性 | `npm run report:polarity`（`#628`）：条件原子 × 极性的覆盖缺口报告（**抽样观测**：未观测 ≠ 断言不存在） |
| **规格门（MVP）** | `test/itemmatrix.mjs`（`npm run matrix`，`#640`）：**场景 × 道具/线索集合 → 期望**。数据住故事侧 `stories/<slug>/matrix.json`、门形状住引擎侧；
  **`exempt`**（可选）：显式豁免某些原子（**理由必填**、与 `promised` 互斥）——例：`era` 已有 coverage 门4「时代双态」，矩阵再承诺＝两份真相。
  行隔离：每行开始前**恢复车卡后基线**——行与行互不污染、与执行顺序无关（实测踩过：前 19 行把角色弄死 ⇒ 后面行的检定侧判定不可用）。
  三条判据＝①行键＝**谓词上下文** ②期望用**渲染后＋行为面**口径，且**分两相位**：`expects`＝渲染后·点击前、`expectsAfter`＝点击后（有 `click` 的行**必须**给 `lands`）；判据＝`text`/`noText`/`choice`/`noChoice`/`lands`/`delta`/`domCount`（`delta` 的 `null`＝键不存在＝消耗；`domCount`＝**结构面**，如 `[data-heard=...]` 折叠块）；`patches` 路径用**点号**（`pc.inv.道具名`——方括号会被当成字面键名，实测踩过） ③**承诺 ratchet**（`promised` 只增不减，每个原子两侧都要有行；承诺的原子在内容里消失即红）。当前承诺：**69 行 / 46 原子**（全部条件原子：**46 承诺 ＋ 1 显式豁免**（`era` ← coverage 门4）＝ **47/47 全覆盖**）；`npm run report:polarity` 的报告里同步标出「哪些原子已被门承诺」——**报告管抽样可见性、门管承诺**，两个口径并排看 |

**硬规则（游走器发现之后）**：每个发现**必须沉淀**为「矩阵一行」（该行的谓词上下文 → 期望）或「覆盖原子的一条路线」，
否则**不开修复票**——把仪器产物变成规格，才叫修好。

**两条已实测的口径（写进 `#629` 的报告，别踩）**：

1. **行键＝谓词上下文，不是单个原子**：`<<if A and B>>` 下，只满足 A 时那一行的行为**不等于**"A 为真的期望"；
   "极性覆盖"仍按**单个原子**统计 ⇒ 两个口径并行，缺一不可；
2. **期望用渲染后口径**：`缺''完整星图''` 在屏上是 `<em>` 斜体，`textContent` **不含引号**；且**两侧链接标签可能完全相同**
   （差别只在落点/副作用）⇒ 判据必须看**行为面**。

## 16. 去权威化：注释／文档**不写「谁定的」**（`#748` 口径 · `#752` 门）

### 规则
