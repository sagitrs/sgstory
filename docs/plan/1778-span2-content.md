  该改动的**回归判据**已入用例，即「二段代表件 id 与 dnd-5e 面零重叠」。
- **双 id 收敛的经过，这是一处值得记的教训**：本笔首稿带 `iron-sword`，本席（writer）当时的理由是「二段遭遇表要有一个可引的注册 id」。

  因此本段最终**只留 `iron-longsword`（武器）与 `iron-ore`（资源）**，两者皆属 `#1779`；本笔的遭遇表**引用它们**。

## 三、段内定标（**house rule**，`SPAN2_SCALING`，形同一段）

三条原则沿用一段，不另立：第一，层内 CR 带随断代梯度递增；第二，第 20 层是 hub，无战斗；第三，数值带只约束引用强度。
**相对一段的抬升**体现为「铁器时代」：CR 带从 **≤2** 抬到 **≤4**，价值带从 **2 gp** 抬到 **50 gp**，后者是鳞甲的实值。
> **不变式（可测）**：遭遇表每层引用的敌人 CR 不超过该层的 `crBand.crMax`。这条有用例守着。
> 该用例在首跑时**真的红了**：L16 引了 CR 4 的巨锹甲，而带上限是 3，据此把峰值件下移到 L18 与 L19。

## 六、门侧缺口（本笔发现，**修门归测试域**）

**3E 怪物的 HP 与 AC 不可判**，原因是门的 `SRC_VAL_RES` 只认 5E 形：
```
const SRC_VAL_RES = { HP: /\*\*HP\*\*\s+(\d+)/, AC: /\*\*AC\*\*\s+(\d+)/ };
```
也就是说它只匹配 5E 源的 `**HP** 11` 与 `**AC** 16`；而 **3E 源写作 `Hit Dice: 1d8+2 (6 hp)` 与 `Armor Class: 15`**，
因此**抽不出**，于是 3E 怪物的 HP 与 AC **从不进 A 组比对**。

**本席的实测证据**（本笔的突变探针）：
| 刀 | 突变 | 期望 | 实得 |
|---|---|---|---|
| M1（声称面） | 文件头 `Armor Class **16**` 改为 `**17**`（代码不动） | 红 | **绿**（门不解析该声称） |
| M1b（用例名与断言） | 用例名 `AC 16` → `17`，断言不动 | 红 | **红**（第①级自洽支有效） |
| M1c（名、断言、代码**三处一致地错**） | 全改 17 | 红（A 组对源） | **绿**（**源侧抽不出 AC**，无从比对） |
| M2（声明面） | 代码 `ac: 16` → `17`（声明面） | 红（单测守） | **红**（单测 `AC 16：17 !== 16`） |

因此**净缺口**是：3E 怪物的 **AC 与 HP** 只有「单测守声明面」这一层；**门不守**，因为源格式不匹配。
本笔的六维（Str 到 Cha）**确实**被 A 组对源核过（`sourceFormats3e 219 次`），所以缺口**仅限 AC 与 HP 两个键**。
**建议**（测试域）：给 `SRC_VAL_RES` 增两条 3E 形，分别是 `/\|\s*Hit Dice:\s*\S+\s*\((\d+) hp\)/` 与
`/\|\s*Armor Class:\s*(\d+)/`。**注意**：3E 的 `Armor Class:` 行还带 `touch` 与 `flat-footed` 数值，
正则须锚行首，本席实测源行形如 `  Armor Class:           16 (+1 size, +5 natural), touch 11, flat-footed 16`。

## 七、覆盖面基线的同步（`#1720` 机制，**本笔必须做**）

本笔把 `faces` 大幅抬高（`claims 99→235`、`aGroupChecked 69→243`、`titleChecked 8→28`、`sourceFormats3e 45→219`）。
因此**基线不更新的话，`titleChecked` 仍以 8 为下限，K16 刀（标题删值）就失去判别力**：
它删一值后 `titleChecked` 只降到 27，仍不小于 8，于是**门绿**，自检报 `✗ K16 未如期`（**CI 已实测红**，run `36800745126`）。
因此本笔按**唯一更新通道** `node tests/gates/refs-integrity.mjs --update-baseline` 重播基线（`seededAt 5aecb988 → 4f1ea4c2`），
K16 恢复红（22 刀全如期）。
> **这是 `#1720` 基线的设计意图在起作用**，而不是缺陷：基线是**下限棘轮**，抬高后须随笔收口，
> 否则「地板被抬高」会让下探类判据静默失效。**教训（可入巡检条）**：**凡大幅新增声称或用例的笔，
> 必须 `--update-baseline` 并复跑自检**，只跑门会得到一个「绿但钝」的结果。
