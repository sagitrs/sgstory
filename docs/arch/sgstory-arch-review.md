# sgstory 架构重构建议

**检视基础**：仓实读（core 18 模块 2870 行、dnd 三包、stories、tests 44 件、build.py）× open 30 票交叉 × 代码实证对拍。
**性质**：架构性建议——不含止血件（M0 族另案）；供长期演进排期决策。

---

## 一、现状诊断：五条结构性根因

### 1. 单平面命名空间——耦合无方向约束

`src/core/` 18 个模块以数字前缀加载序（`00-namespace` → `65-encounters`）共享一个 `RPG.*` 全局命名空间。模块间互引密度高（实测 `40-battle.js` 引用 10+ 个 `RPG.*` 面：`turnBoundary`/`respawnHooks`/`loot`/`layerMeta`/`events`/`death`/`rng`/`act`…），**依赖关系只存在于加载序约定中**——无显式接口边界，任何模块可摸任何模块的内部结构。

**后果**：
- 「改一处、抖一片」——模块不可独立替换或测试；
- 数字前缀是**隐式依赖图**——新人无法从结构读出分层意图；
- 循环依赖风险随模块数线性增长（当前靠加载序侥幸避免）。

### 2. 宿主渗透——领域逻辑不可脱离 SugarCube

`State.variables` 直引散布 5 个 core 模块（`30-inventory`×3、`60-map`×3、`20-character`/`36-build`/`50-scene` 各 1）；`$()`/`jQuery`/`Dialog` 等 SugarCube/Twine 宿主 API 出现在 7 个 core 模块。**引擎的领域逻辑（战斗/物品/场景）与宿主框架（状态容器/渲染/页面生命周期）深度交织**。

**后果**：
- 领域逻辑只能在 SugarCube 运行时内验证（jsdom 打桩复杂、测试面残缺的根因之一）；
- 迁移宿主（SugarCube 升级/换格式）= 全仓手术；
- 并发/回退等时序语义由宿主隐式决定（D2 跨段渲染泄漏的根因面）。

### 3. 状态无契约——事实与视图不分

NPC/宝箱/地图/一次性结算标记以**堆对象**直接存放（非 entityId 索引的持久事实）；`State.variables` 兼作事实源、视图缓存与模块间传参通道（`50-scene.js:61` 直写 `sceneId` 即例）。

**后果**：
- 跨段/刷新/回退/重开后状态不一致（D1/D4/D5 族的架构根源——票面自认「旧线最贵教训」）；
- 存档演进无版本化 schema+迁移链（`00-namespace` 的 `version: '0.2.0'` 是引擎版本非存档契约）；
- 派生数据与原始事实无界——「哪个是真值」不可判。

### 4. 动作语义不统一——四路入口各自为政

战外/交互战/自动战/同伴四条动作通路独立实现成本扣减与状态变更（代码实证：`40-battle.js:314` 交互战「使用」入口绕开 `useItem` 检索面）；返回值无统一契约（`undefined` 被误判 `applied` 的 #1783、拒绝却已耗弹药的 #1801、回合经济语义分歧的 #1773——同一根因的三个投影）。

**后果**：
- 每条通路各自演化——一致性靠人肉对齐，症状票收不尽；
- 无原子性保证（校验/扣减/状态变更非事务——部分失败留中间态）；
- 事件时序不可推导（提交前/后的事件混发）。

### 5. 注册面无隔离——包边界不存在

`registerItem` 同 id 重复仅 `console.warn`（`10-item.js:69` 自注「后者遮蔽前者是已知风险」）；`RPG.items` 跨包单表（dnd3×dnd-5e 已 6 例重复 id——#1743）；无依赖声明/激活语义/版本约束（#1764 探索中）。

**后果**：
- 多规则包共存时行为取决于加载序（非确定配置）；
- 包无法独立测试/独立演进（互相污染）；
- 「跨版同物=两对象各自 pin」的通则无机械面承载。

## 二、目标态：四层架构 + 端口适配

```
┌─────────────────────────────────────────────────┐
│ L3 内容层   stories/*.twee + 场景脚本            │  只消费 L2 manifest
│             （只经 L0 呈现，不触内核内部）        │  与 L1 公开原语
├─────────────────────────────────────────────────┤
│ L2 规则包层 dnd3 / dnd-5e / d20m / future…       │  声明式注册
│             manifest：id 空间/依赖/版本/导出      │  命名空间隔离
├─────────────────────────────────────────────────┤
│ L1 领域内核  entity store │ action(act) │ rules   │  纯逻辑
│             event bus    │ Event 命令对象体系     │  零宿主依赖
├─────────────────────────────────────────────────┤
│ L0 宿主适配  PersistContract │ RenderPort         │  唯一宿主触点
│             LifecyclePort（passage/session）     │  （依赖倒置：L1 定义接口）
└─────────────────────────────────────────────────┘
```

### L0 宿主适配层（host adapter）

**职责**：把 SugarCube/Twine 的状态容器、渲染、页面生命周期**收口为三个端口**——全仓唯一允许出现 `State.variables`/`$()`/`Dialog`/`:passageinit` 的地方。

- **PersistContract**：slot 读写 + **版本化 schema + 迁移链**（`Save.onLoad` 钩子的唯一消费者）；对 L1 暴露「按契约存取事实」的接口——内核不知序列化细节。
- **RenderPort**：`perform`/`render` 输出的抽象（当前 `$()` 直写 DOM 的所有点收编于此）；为测试提供可注入的输出收集器。
- **LifecyclePort**：passage 切换/session 纪元/异步取消的宿主事件翻译（D2 族的根治位——旧 session 失效由端口统一分发，内核只消费「当前纪元是否有效」）。

**关键机制——依赖倒置**：L1 定义 port 接口（`src/core/ports/`），L0 提供实现（`src/host/sugarcube/`）。依赖方向 L0→L1，**内核永远不知宿主**。

### L1 领域内核（domain core——高内聚的载体）

按 bounded context 重组（替代数字前缀平面）：

| 域 | 内容 | 对外接口 |
|---|---|---|
| **entity** | entityId→事实的 store；视图派生缓存；变更追踪 | `store.get/apply/checkpoint` |
| **action** | 统一动作入口：校验→效果计算→**原子提交**→事件发布；`{applied\|rejected\|cancelled}` 三态契约 | `act(actor, itemRef, target, action)` |
| **rules** | dice/battle-turn/item-consumption/skill-check——以 **Event 命令对象体系**承载（现有 `15-event.js` 的「可执行剧本」设计是正确种子，扩展为全部规则效果的统一形态） | Event 子类 + `rules.eval` |
| **event** | 唯一广播总线（与 Event 命令对象双轨分工：总线=已发生事实的广播，Event 对象=待执行的剧本——现有注释已表达此意图，落地为体系） | `bus.emit/on` |

**内聚判据**：域间只经上表接口交互；域内自由。**耦合判据**：禁止跨域摸内部结构（lint 可机械守——见 §四）。

### L2 规则包层（包边界的机制化）

- **manifest 声明**：每包一份（`package.json` 形态）——`id` 前缀/命名空间、依赖包、引擎版本约束、导出清单（items/monsters/effects/scenes）。
- **注册面 fail-loud**：同命名空间 id 冲突**抛错拒绝加载**（替代 console.warn）——配置错误的最早暴露点；跨包引用他包导出须声明依赖，未声明即拒绝。
- **激活语义**：故事声明启用哪些包（单一激活集，非全量加载）——加载序不再影响行为。
- **纯度判据入 CI**：包内只经 L1 接口+L2 manifest 消费（禁直触 L0/他包内部）——机械可验。

### L3 内容层

twee + 场景脚本只消费 L2 manifest 导出与 L1 公开原语（`act`/`bus.on`/store 视图），呈现一律经 L0 RenderPort。**当前 twee 面引 RPG 极少（实测 2 处）——内容面耦合本已低，此层重构成本最小**。

## 三、状态架构细则（单一事实源）

```
事实（Facts）                     视图（Views）
entityId → 持久化字段              堆对象/派生缓存
┌──────────────────┐             ┌──────────────────┐
│ EntityStore       │ ──派生──▶ │ ViewModel         │
│ · 唯一可变源       │           │ · 只读            │
│ · 版本化 schema   │ ◀─迁移──  │ · 重建即得        │
│ · checkpoint 历史 │           │ · 不入存档        │
└──────────────────┘             └──────────────────┘
        │                                ▲
        └───── L0 PersistContract        │ 消费方（UI/场景）
              （slot 读写+版本迁移）──────┘
```

- **事实只有一份**：NPC/宝箱/地图/标记全部以 entityId 进 store——视图（含现有堆对象）降级为派生缓存，可随时重建；
- **存档=事实快照+schema 版本**：迁移链在 PersistContract 内逐版演进（v1→v2→v3…），旧档永远可载；
- **checkpoint**：每个改状态动作提交即留检查点（回退/舞台重入的机制基础）；
- **守卫**：开发构建加「视图混入事实」检测（对象原型污染类 bug 的最早暴露）。

## 四、耦合的机械守卫（低耦合不靠自觉）

| 规则 | 守卫方式 | 成本 |
|---|---|---|
| L1 禁 import 宿主符号（`State`/`$`/`Dialog`/`engine`） | ESLint `no-restricted-globals` + 目录级 override | 低（规则一条） |
| 域间禁摸内部（`battle._xxx`） | 公开面导出清单 + lint 命名约定（下划线=私有，跨域引用即报） | 低 |
| L2 包禁直触 L0/他包内部 | manifest 导出面 + 注册时校验 | 中（注册器一次实现） |
| 事实禁视图直写 | store 唯一 mutator + 开发守卫（§三） | 中（随状态契约落地） |
| twee 禁直引内核内部 | 构建期扫描（build.py 加一步：twee 中 `RPG._`/未导出符号报错） | 低 |

**原则**：每条耦合规则对应一个**可机械执行的守卫**——架构不靠 review 自觉维持，靠门维持（与本仓 test-infra 的 pin 门/gate 思路同族）。

## 五、迁移策略：绞杀者渐进（非大爆炸）

**总原则**：每相行为等价（e2e 基线先行验证）；每相独立可停（停在任何一相，仓仍健康）；每相配负例用例（接缝缺陷的回归防线）。

### Phase 0：e2e 行为基线（前置，非可选）
jsdom 主线通关脚本进 CI（M0 已含此件——**本方案唯一的 M0 依赖**：它是后续每相「行为等价」的判据来源，不是止血件）。

### Phase 1：宿主触点收口（立 L0）
把 7 模块的 `State.variables`/`$()`/`Dialog` 直引改经三 port——**不改任何行为**（纯转发）。完成后 L1 的宿主渗透=0（lint 门即刻生效）。
**验证**：e2e 基线全绿 + 全部现有单测绿。

### Phase 2：状态契约（entity store 接管事实）
NPC/宝箱/地图/标记逐域迁入 store（entityId 索引）；堆对象降级为派生视图；PersistContract 挂版本迁移。
**顺序**：先低风险域（一次性标记）→ 地图 → NPC/宝箱 → 角色档。
**验证**：跨段/刷新/回退/重开一致性用例族（Save 往返）+ e2e。

### Phase 3：动作统一（act 收编四路）
`act()` 三态契约+原子提交落地；四路逐路收编（战外→交互战→自动战→同伴）——**每收编一路，撤该路旧通路**（防补丁长期化）。
**验证**：同动作四路成本/事件一致用例 + 拒绝时零变更用例（负例）。

### Phase 4：包系统（manifest+隔离）
注册面 fail-loud（6 例现存冲突按「跨版同物=两对象各自 pin」通则处置——前缀化或命名空间）；manifest+激活语义；纯度判据入 CI。
**验证**：冲突包同载报错用例 + 单包独立测试跑通。

### Phase 5：core 拆域（bounded context 落位）
按 §二 L1 四域重组目录（battle/inventory/scene/…各归其域）；数字前缀让位于显式依赖声明（import 图即可视化分层）。
**验证**：lint 域边界门生效 + e2e + 模块独立测试（每域可单独跑）。

## 六、长期演进收益（为什么值得）

1. **可测性质变**：L1 零宿主依赖，因此可以做纯单测（当前 jsdom 打桩复杂度的根因由此消除）；接缝集中在 L0 与 L2，因此接缝测试有明确靶点；e2e 只验 L3 集成。三层测试各就其位。
2. **宿主可替换**：SugarCube 升级/换格式只动 L0 一个目录。
3. **包生态可扩**：新规则包（d20m/未来五段内容）= manifest+导出，不触内核——巴别之井五段伞（#1729-#1733）的引擎能力缺口在 L1 域内逐域补，内容面零感知。
4. **存档可演进**：版本迁移链让老玩家存档跨版本存活——长线运营的正道。
5. **并发/时序可推导**：session 纪元/异步取消/原子提交——当前 D2/#1801 类「时序意外」从结构上不可再现。
6. **架构自守**：五条 lint/CI 门——新人贡献不破坏分层（低耦合靠机制不靠口头）。

## 七、风险与成本（如实）

| 风险 | 缓解 |
|---|---|
| Phase 2/3 触及存档兼容（旧档迁移） | PersistContract 迁移链 + 旧档往返用例族先行 |
| 四路收编期间双轨并存 | 每路收编即撤旧路（§五纪律）——双轨窗口最小化 |
| 包冲突处置牵动故事引用 | Phase 4 与内容票排程协调（#1743 已注） |
| 重构窗口与内容交付竞争 | 绞杀者各相独立可停——不必一次性让路 |
| 92 文件规模下单人上下文极限 | 分域推进（每相一域）+ 接口先行（port/manifest 先定后迁） |

**规模感**（粗估，供排期参考）：Phase 0/1 各 1-2 天；Phase 2 按 3-4 域各 2-3 天；Phase 3 按四路各 1-2 天；Phase 4/5 各 3-5 天——**总量 ~4-6 周单人当量**，可分散在内容迭代间。
