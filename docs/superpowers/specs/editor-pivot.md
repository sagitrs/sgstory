## 0. 一句话

**把"故事"从代码变成数据**：用户在 WebUI 里维护一份**故事 JSON 包**，由编译器生成现在这些 twee 文件；其余的构建、门、发布链路**一行不改**。

```
[WebUI 编辑器] ──写──> [故事 JSON 包] ──编译器──> [twee：tables/rules/passages] ──build.mjs──> dist/<slug>/index.html
      ↑                      │                          │
      └──── lint（同一批门）──┘                          └─> npm test（96 门，K1–K5 全留）
```

**不动的**：引擎（`src/**`）· SugarCube · 96 道门 · `build.mjs` 的产物形状 · Pages 发布。
**新来的**：`editor/`（schema ＋ 编译器 ＋ UI）＋ 故事包的目录约定。

### 0.1 术语底座（本线的「故事」定义 —— 供后续各期引用 ✗）

> 来由 ✓：会外意见（`gsvector-process#215` `18508550` ✓）提、发起者裁定**采纳为工作词汇** ✗（不是"定理"✓）。本节只**给既有口径命名** ✓；若有条文与本定义**语义冲突** ⇒ **当场指出并走裁定** ✗。

**① 故事（产物）＝ 三元组 ⟨D₀, E, ≺⟩** ✓：`D₀` ＝ 道具初始配置（属性袋全量 ✓）；`E` ＝ 事件集（门槛谓词 ＋ 文本 ＋ 效果 ＋ 出口 ✓）；`≺` ＝ 授权结构 ＝**出口图 ∧ 门槛谓词** ✓ —— **状态是门，图是路** ✓。
**② 故事实例（一次游玩）＝ 轨迹** `τ = (S₀,e₁,S₁,…,e_k,S_k)` ✓（战斗段＝战斗内核按回合规则展开的**机制子序列** ✓）。
**③ 叙事 ＝ 轨迹的因果投影** ✓：`last_roll` 7→9 是**噪声** ✗；"拿到钥匙 ⇒ 开得了门"是**叙事** ✓。

**术语族落位** ✓（日常词 ⇒ 本定义 ⇒ 可 lint 性）：

| 日常词 | 模型定义 | 可 lint 性 |
|---|---|---|
| 场景／段落 | `E` 中单事件（或其 `say` 部分 ✓） | — |
| 弧／章 | `≺` 中一条主干 ＋ 必经事件集（临界路径 ✓） | **可达性视图** ✓（P2 已落 ✓） |
| 结局 | 终态等价类（多轨迹收敛的可识别终态 ✓） | 终态断言 ✓ |
| 侧支 | 不达终态、可回环子图 ✓ | ✓ |
| **伏笔／回收** | **早事件效果写属性 `x`，晚事件门槛读属性 `x`** ⇒ **因果关系 ＝ 一次写-读对** ✓ | ⭐ **写了没读 ⇒ 悬空线索**（可达性抓 ✓）／**读了没写 ⇒ 幽灵条件**（fail-loud 已抓 ✓） |
| 设定集 | 不进轨迹的世界常数（`D₀` 惰性道具 ✓ —— 供语料，自身不迁移 ✓） | ✓ |

⭐ **「伏笔 ＝ 写-读对」是本定义最实的一红利** ✓：它把**两个既有门**在术语上合成一条 ✗ —— 「**悬空线索**」与「**幽灵条件**」不再是两件事，而是**同一对写读的两面** ✓。

> ⚠️ **边界（2026-09-19 裁定 ✓）**：本节（与 §7 的 **G1′ 注记** ✓）是**建模立场 ＋ 编辑器面的生长方式** ✓，**不构成对引擎的重构指令** ✗ —— 引擎侧改动一律**另立票** ✓，并按 `contractVersion` 的现成判法处置 ✗：**改既有面的形状／语义 ⇒ `CURRENT ＋1`** ✓／**新增一面 ⇒ 不 ＋1（但必须在 `EXTENSIONS` 显式登记）** ✓（出处：`editor/lib/core/contractVersion.mjs` 的声明四 ✓）。⚠️ 且「单质／本体」这类词**只描述既有事实与生长方向** ✓：`contract.json` 成员**早已有 `kind`** ✓、实体**早已是** `tables.json` 的 `containers` ✓ ⇒ **不是**"把代码改成对象继承体系"的口子 ✗。

## 1. 不变量与让步（转型期纪律，票面 D5）

**必留 K1–K5**（K1 失败开向 · K2 契约 fail-loud ＋ `--engine-story-free` 三档 · K3 点得动/不抛错/走得到终点/存档不丢 · K4 单一真源 · K5 让步留痕）。

**可放（转 report-only，不删）**：数值平衡（`--dragon` · `--combat-dist` · `fight-seq` 逐字节）· `size-gate` ratchet · 文笔密度（`--craft`/`--text`）· 覆盖承诺（`--investment` · `itemmatrix` 的 `promised`）· `ui-migration-diff`。

> 判据一句话：**允许「数值不对」，不允许「点了没反应」**。

**为什么这么切**：转型期最贵的不是"数值漂了"，而是**分不清是新架构坏了还是没做完**。静默失败（空屏、红框、死链、存档丢）会直接毁掉这个判断力，而数值漂移不会。

## 2. Schema v0

### 2.1 故事包目录（一个故事 ＝ 一个文件夹）

```
stories/<slug>/
  00-story.json        ← 清单（已存在！）：slug/title/entry/files/gates  ＋ 新增 contractVersion
  data/
    tables.json        ← 声明面：Checks.sites / Economy / Combat.pools+actions / Gear / Items / Social / Truth / Echoes / State.domains / Notes.entries …
    rules.json         ← **条件表行**（＝现在 `17-rules.twee` 的内容；车道 B 已抽出 61 行，与手写版 L1 深度相等）
                          **字段 ↔ 手写列一一对应**（`equiv --rules` 打印**字段直方图**并断言两版相同）：
                          `id` 行 id · `scope` 作用域（`段落`／`段落#位点`，是**结构**）· `req` 全部满足 · `any` 至少一个 ·
                          `exclude` 都不满足 · `prereq` 前置行 id（本故事 0 行用）· `prio` 显式优先级 · `text` 选中时渲染的正文 ·
                          `yields` 授予笔记 id · `sets` 置真状态键。**当前基线**：`any 2 · exclude 33 · id 61 · prio 61 ·
                          req 32 · scope 61 · sets 1 · text 61 · yields 1`（61 行 / 9 列）
    events.json        ← 编辑器侧的**统一事件模型**（本稿 §2.2）：其"条件表行"子集编译成 `17-rules.twee`，
                          "`roads` 类事件"子集编译成 `15-tables.twee` 的 roads 行（车道 A 落地）
    contract.json      ← 接入契约的注册（`Sg.story.*` 的 18 个口子；空表/null 是合法数据集）
  passages/            ← 散文（**文本**，不是 JSON）：`<段落名>.twee` 或单文件多段
  15-tables.twee       ← **产物**（生成，禁止手改）
  17-rules.twee        ← **产物**（生成）
  10-*.twee            ← **产物**（散文，由 passages/ 拼装）
```

**为什么散文不进 JSON**：散文是长文本、要 diff、要人读；JSON 里塞长文本会毁掉评审。**结构进 JSON、文本留文本**是这套 schema 的第一条边界。

### 2.2 事件模型（统一两种现有形状）

```jsonc
{
  "id": "keeper.flower_warning_echo",          // 稳定 id（机检与 UI 的键）
  "scope": "守林人",                            // 段落 或 `段落#位点`
  "when": {                                     // 「何时」：与现有表语法一一对应
    "req": ["n_flower_warned", "n_keeper_told"],// 全部满足（裸键=ev./n_*=笔记）
    "any": [], "exclude": [], "prereq": null,
    "prio": 10                                  // 显式优先级（降序；同 prio 按序）
  },
  "say": { "text": "''\"塔基墙根那片银白的花——…\"''" },  // 「说什么」：选中时渲染
  "do": {                                             // 「做什么」：**封闭词汇**
    "effects": { "yields": ["n_keeper_told"], "gives": [], "sets": [] },
    "blocks": []                                      // 机制块白名单：sitecheck / damage / give / note / …
  },
  "next": ["塔门", "花田"]                            // 「去哪」：出口（可空＝就地渲染）
}
```

**契约成员的 `kind` 封闭集合（v1 ＝ v0 ＋ 车道 A 实测缺口 4 个）**：`empty-object` · `empty-array` · `null` · `const` · `game-ref` ·
`identity-string` ＋ **`lookup`**（`{from,key,default,optional?,required?,error?}`：查表；`required` 表达契约的 fail-loud）·
**`lookup-field`**（取字段 ＋ 兜底表达式）· **`bool-exists`**（`!!window.X`）· **`state-ref`**（`pc?.<path> ?? default`）。
`from` 允许直接写全局根（`window.`／`Sg.`）——手写版两种写法都有，schema 要能表达"哪个根"。
**逃生舱 `kind:'js'` 的实测清单为空**：洞窟 15 个契约成员全部可用上表表达；故事 1 只有 3 项真逻辑（`combatPrepick`／`checkKnowledge`／`battleDamage`），
且前两项建议"下沉引擎变规则表数据"（详见 `#762` 的《必须逃生舱的成员清单 · 草案 v0》）。

**与现有两种形状的映射**（适配器就是把统一模型降级成它们）：

| 现有形状 | 由什么生成 |
|---|---|
| 故事 1：`17-rules.twee` 的条件表行 | `events.json` 逐行 → `{id, scope, req/any/exclude/prereq, prio, text, yields/gives/sets}`（**已经是这个形状**，几乎 1:1） |
| 故事 2：`roads` 表 ＋ `机制·X` 段落 | `events.json` 里 `kind` 类事件 → `roads` 行；`do.blocks` → `机制·X` 段落骨架（段落文本仍在 `passages/`） |
| 故事 1/2：章节/事件段落 | `passages/` 的文本 ＋ 由 `next`/`scope` 生成的链接与 `<<rules>>`/`<<rulelist>>` 调用 |

### 2.3 词汇白名单 ＝ UI 的 enum（**引擎已经宣告了**）

| 面 | 真源（引擎） | UI 用法 |
|---|---|---|
| 条件键形 | `Sg.rules.prefixes`：`inv:` / `era:` / `gear:` | 键输入框的前缀下拉 |
| 算子 | `Sg.rules.ops`：`gte` / `lte` / `oneOf` | 对象算子的下拉 |
| 效果面 | `Sg.rules.effects` | `do.effects` 的可选项 |
| 取值项 | `Sg.rules.terms`：`{price:'econ_id'}` | 可负担性条件的下拉 |
| 机制块 | 词汇宏清单（`docs/twee-cheatsheet.md`） | 「做什么」的可选块 |

⇒ **编辑器不做自己的词汇表**：`Sg.rules.*` 就是 enum，UI 与 `--rules` 门同源（否则必然漂移）。

## 3. 编译器边界（谁是源、谁是产物）

| 生成物 | 由谁生成 | 关键约束 |
|---|---|---|
| `15-tables.twee` | `data/tables.json` ＋ `data/contract.json` | 容器与注册口**显式给空**（空表＝合法数据集，缺失＝报错） |
| `17-rules.twee` | `data/events.json` | 表语法见 `docs/rules-table-guide.md`；`text` 不许读渲染期状态（`--rules` 判） |
| `10-*.twee`（散文） | `passages/` 拼装 ＋ 插入 `<<rules>>`/`<<rulelist>>`/链接 | 段落**名与顺序**仍由 `00-story.json` 的 `files` ＋ 登记表决定 |
| 目录登记（`ORDER`/`MODULES`） | **P3 之前手工**；P3 起由编译器**生成一段**（或改为动态发现） | 见 §5 拦路石 2 |

**K4 的判据（P0 要写进门）**：`15-tables.twee` / `17-rules.twee` 首行带生成标记（`// @generated by editor/compile-story.mjs —— 手改会在下次编译被覆盖`），且门断言"有生成标记的文件 ∈ 某故事的 `data/` 的产物集合"。

**逃生舱**：段落文本允许任意 twee（包括手写 `<<if>>`）；**结构**（条件/效果/出口）才强制进 JSON。⇒ 不让作者被 schema 卡死，也让迁移可以分块做。

## 4. 等价判据（P0 的验收方法，三级）

| 级别 | 判据 | 工具 |
|---|---|---|
| **L1 结构等价** | 两版各自在 vm 里求值后：数据容器**深度相等**；契约成员**逐个 × 多组实参**（实参表由故事声明的 id 驱动 ＋ 未知 id ⇒ 顺带验 fail-loud）调用结果相等 | `editor/equiv.mjs` |
| **L2 门等价** | `npm test` 全绿 ＋ **`audit:golden` 零漂移** | 现成 |
| **L3 形式等价**（**报告制**，见下） | 生成的 twee 段与手写段在**词法遮蔽注释**（`scripts/audit/lib/mask.mjs`，不动字符串内容）＋去空白/冗余尾逗号后逐字节相同 | `editor/equiv.mjs` |

> **L3 的适用边界（车道 A 实测口径修正）**：**不能**把「逐字节」当**跨故事**的权威判据 —— 三份手写文件的风格并不统一
> （`window.Game?.Checks?.sites?.[name]` vs `window.Game.Checks.sites[name]`、模板串 vs 拼接、抛错形状各异）。
> 这条很重要：把 L3 当权威会逼着 schema 去复刻**每份手写文件的排版与写法**（＝把历史包袱搬进数据模型），与 D2 相反。
>
> **⇒ 迁移某故事时，权威判据是下面这一组（缺一不可）**：
> 1. **L1 结构/行为**（本文件 §2）；2. **L2 门**：`npm test` 全绿 ＋ **`audit:golden` 零漂移**；
> 3. **`ui-migration-diff` 零正文漂移** —— **这才是"玩家看到的字"那条线**，而且它覆盖**散文段**（L3 只比 `[script]` 段）；
> 4. **`fight-seq` 逐字节**（掷骰序不变）；5. **该故事自己的门**（`stories/<slug>/gates/**`）。
> **L3 降为报告制，但保留"逐故事棘轮"**：已确认逐字节相同的故事（今：`minimal-demo`）**不许变红**，且 L3 **永远打印**
> ——可以不是权威，但不能静默消失。

**为什么不是"dist 逐字节"**：手写版有大量解释性注释，数据化后注释归文档；L3 剥注释（并归一冗余尾逗号这类纯格式）后相同已足够强，且 L1/L2 兜住语义。

**P0 已收紧的四条**（审查提的四条，都已落码）：① L3 的注释遮蔽改用 `mask.mjs`（否则字符串里的 `//` 会被吃掉 ⇒ **假绿**；自证里有这条反例）；② 契约探针**多实参**（原先 14/15 个成员只验零参）；③ **判到的面打印出来且为 0 判红**（`#557` 口径：等价不能建立在空集上）；④ **幂等进门**（连编译两次逐字节相同，`equiv` 自跑编译器两次）、**数据面不许有函数值**。

**P0 实测（`#762`）**：`minimal-demo` 已过 L1 ＋ L3（`editor/compile-story.mjs` ＋ `editor/equiv.mjs`）。过程中**判据当场抓到三处真差异**（漏写 `window.Game =`／`State.domains[0].keys` 缺 `settle`／`Consequences.engine` 缺 `settle`）——这类"数据与手写版漂移"正是 L1 存在的意义。

## 5. 拦路石与对策

| # | 拦路石 | 对策 | 落在哪期 |
|---|---|---|---|
| 1 | 故事数据现在是**手写 JS 字面量** | P0 的编译器（JSON→`[script]` 段） | P0 |
| 2 | 新故事要改**中央登记表**（`scripts/module-order.mjs` 的 `ORDER`/`MODULES`） | 编译期生成该故事的登记段，或把 `ORDER` 改成"引擎序 ＋ 故事内序"两段拼装 | P3（P0 先接受"手工登记一次"） |
| 3 | **契约漂移**（`Sg.story.*` 随引擎演进） | `00-story.json` 新增 `contractVersion`；引擎侧保留 N-1 兼容层；用户故事跑 story-CI（全套 K 门） | P3 |
| 4 | "事件"现有**两种形状** | §2.2 的统一模型 ＋ 适配器；P0 用两个真实故事各证一次 | P0 |
| 5 | 叙事耦合（跨章节状态语义） | 沿用 `--state` 域表 ＋ Notes 模型；**编辑器把"未声明键"挡在保存时** | P1/P2 |
| 6 | 文笔与内容质量 | **不做**：`--craft`/`--text` 只判"不许烂"，编辑器不承诺"写得好" | — |

## 6. 风险与"接受缺陷"的边界

**可以进**：数值失衡 · 文案粗糙/密度下降 · 覆盖缺口扩大 · UI 布局退化。
**不可以进**：`K1`–`K5`。任何一条要放宽，必须**先改票面**（不是改 PR 描述）。

**为什么写死这条**：本仓历史上最贵的缺陷（`#300` 存档丢进度 · `#746` 文案不到落点 · `#647` 宏错误不进 `uncaught`）**全部**是"静默失败"。转型期噪声本来就大，再放任这一类，就再也分不清是新架构的问题还是内容的问题。
