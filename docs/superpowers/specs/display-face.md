## 0. 一句话

**引擎不该"提供一个血条"，该提供"一个条"** —— 引擎只认「**一个数落在一段区间里**」；
**"这数是血／是法力／是饥饿"** 与 **"它画成什么"** 全归**故事声明**。
今天 `hpbar` 把这两件事焊死在引擎里（`10-core.twee:564`）。

## 0.1 问题（Admin 原判断 ＋ 实证）

> 【引擎侧不感知 hp 概念】和【引擎侧要有状态表示 UI】二者矛盾。
> 解决方案：**引擎侧提供 bar UI，故事侧定义玩家属性与属性通过什么 UI 如何图形化**。

**实证（`#1534` 评论 `5851722091`，books ref `2ea9679`，5 个故事）**：

| 引擎仍然"知道" | 位置 | 数据面能改掉吗 |
|---|---|---|
| 存在 `hp`／`maxHp`／`salves` 三个**量纲槽** | `10-core.twee:135` `vitals.keys` | ✗ 只能改键名字面量，改不掉"存在这三个槽" |
| 量纲要画成 **`❤ cur / max`** | `10-core.twee:564` `hpbar` | ✗ 形态写死（含三档配色阈值 `50/25`） |
| 侧栏该放**哪几个面＋什么形式** | `StoryCaption`（约 50 行） | ✗ 版面写死 |
| 掉血说「点**伤害**」／恢复说「点**生命**」 | `damage` widget | ✗ 句式写死 |

★最直白的一条：**把 `salves` 的名字从数据读，也改不掉"引擎认定主角有药膏、且药膏显示成 `N 副`"**。

★**实测症状**（同一实证）：引擎给**没声明 hp 的 4 个故事**照画 `❤ 0 / 1`（假值）；
给**没声明 economy 的 3 个故事**在侧栏印出**字面 `$pc.gold`**（裸变量当散文 ⇒ SugarCube 原样印）
—— 连"出声"都不是，是**印开发期符号**（`#1495`／`#1523`「空面必须出声」族）。

## 1. 定形（Q1／Q2 已裁）

### 1.1 Q1 槽位模型 ＝ **中间形**

```
引擎只给"**容器**"（挂载点），✗ 不给"槽位的语义"；
容器内**顺序与组成全由故事声明** —— 与"引擎提供 bar() ✗ hpbar"**同构** ✓
⇒ 引擎侧**领域词归零**（可机检面 ①：`hp`／`gold`／`inventory`／`gear`／`status` ✗ 许出现在引擎的表示面）
```

**为什么不是另两形**（为什么不取另两形）：
- **引擎给固定槽位名**（`sidebar.primary`…）⇒ 引擎又"知道"版面结构 ✗（把刚拿掉的东西换个名字装回去）；
- **故事 `slot` 名任意、引擎只按序渲染**（完全自由）⇒ 侧栏失去统一性（各故事版面不可预期）。
- **中间形**：引擎给**容器**（今天的 `#story-caption` 就是那个容器），**容器内**顺序/组成由故事声明 ⇒ 引擎不知语义 ✓。

### 1.2 Q2 声明面落点 ＝ **契约成员 `panels`**

```
与 `pcShape`／`rulesPack`／`mechanics` 等**声明维同住**（"属性 → UI" 是**声明**，✗ 不是内容）；
体积真大再议独立件 —— emit 两条路都通，**先走成员形**（✗ 新开第 6 个数据面）✓
```

**实证支撑**：5 个故事的 contract 成员数 3–11 不等；`panels` 每故事预计 **2–3 条** ⇒ 体积无虞。
（✗ 新开 `data/panels.json` 的必要性不存在；若将来单故事面板数过百再议 —— 那是显式决定，✗ 顺手。）

## 2. 目标形

### 2.1 引擎侧：无领域语义的**图形原语**

```
Sg.ui.bar({ value, max, label?, style? })     ← 一个数落在一段区间里（本方案起步件①）
Sg.ui.list({ items, empty? })                 ← 一元列表（起步件②）
（Sg.ui.group({ title?, parts: […] })         ← 组合/嵌套 —— ★待执行票定（Q3））
```

**红线四条（原语"无领域"怎么保证 —— 可机检面 ① 的判据）**：

```
① ★原语实现里 ✗ 许出现领域词：`hp`／`gold`／`inventory`／`gear`／`status`（扫 `Sg.ui.*` 的实现体）
② ★原语入参**只接受已算好的值**（`value`／`max`／`items`）—— ✗ 自己不知道去 `pc` 里取哪个键
③ ★"没数据 ⇒ 不渲染"由**原语统一处理**（空 `items` ⇒ 不产字节；✗ 不是印 `（空）` 或 `$pc.x`）
④ ★样式（颜色阈值／图标／分隔符）**全部**由 `style` 传入或取数据面缺省 —— ✗ 引擎不内置三档配色
```

### 2.2 故事侧：契约成员 `panels`（声明维）

```jsonc
// data/contract.json 的 members 里新增（形状草案，待执行票细化）
{ "name": "panels", "kind": "const", "value": [
  { "mount": "bar",  "props": [ { "slot": "sidebar.primary", "key": "hp", "max": "max_hp",
                                  "label": "生命", "style": "hp" } ] },
  { "mount": "list", "props": [ { "slot": "sidebar.primary", "key": "inv", "empty": "（空）" } ] }
] }
```

★**关键**：`key`／`max`／`label`／`style` **全在故事数据** ⇒ 引擎只说"拿 `bar` 去画 `props` 里这几个数"
⇒ **引擎侧再无 `hp` 这个字**（这正是 Admin 要的那条线）。

### 2.3 取值来源（`#1531` 的定位）

```
`#1531`（已合 `da9652e`，按裁定**保留但冻结**）的 `Game.Rules.vk(name)`／`vl(name)` ＝
  ★**声明面的取值来源**（`key`／`label` 从 `vitals` 取）⇒ ✗ 不废、✗ 不回退；
★但其"**引擎内置血条这一形**"是本方案要替换的对象 ⇒ 迁移完成后 `hpbar` 宏**退役**
  （照 `#1227` 类一删 `dragonbar` 的先例：引擎✗为某个故事/某个概念提供渲染件 ✓）。
```

```

   · ★但形不同族（"模板 ＋ 数据" vs "图形原语"）⇒ 建议**另立一节**，✗ 不硬塞进 `Sg.ui.*` ✓

Q5 过渡 ⇒ **零声明 ⇒ 玩家面空 ＋ 开发者面出声**（✗ 静默照画）
   ★实证支撑（`#1534` 评论 `5851722091` §三）：今天画的 4 处里 **2 处是假值/垃圾**（`❤0/1`、`$pc.gold` 字面），
   真正"有用"的只有 `fruit-demo` 的 `❤12/12`（也是引擎替它猜的）
   ⇒ ★**迁移面很小**（4 故事补 `panels`，逐故事 2–3 行声明），且**净收益**（顺手清掉假值与垃圾）✓
   ★★"**出声一行**"的**对象必须写明**（✗ 两处都出声）：
     · **玩家面 ⇒ 干净的空**（侧栏该块**不产字节** —— ✗ 印 `（空）` ✗ 印 `$pc.x`）；
     · **开发者面 ⇒ 出声**（控制台一行：哪一个故事、哪一块没有声明）✅
   ⇒ ★即：本条**不是**"空面印一行给玩家看"（那会把开发期提示变成玩家可见文本 ✗，正与金币缺陷同族）✓
   ★口径归属：与「空面必须出声」（`#1495`／`#1523`）**同族但落点不同** —— 该族的"出声"指**门/日志面**，
     ✗ 玩家面；本票把这一点显式区分（防后人读成"侧栏要印一行字" ✗）✓
```

### 3.1 过渡期规则（迁移窗内新旧并存）

```
★**以 `panels` 声明为准画**；**未声明的块 ✗ 画** —— ★该条**立即生效**（✗ 等迁完）：
  · 即：只要故事的 `panels` 声明落地，引擎那一块的**内置默认画法即刻停用**（✗ 两块并存 ✗ 新块叠加在旧块上）；
  · 理由：与金币缺陷**同口径** —— "引擎✗画没被声明的东西"；若过渡期允许旧内置块继续画，
    则同一属性可能**出现两处**（一个来自声明、一个来自内置）⇒ 读者看到重复块，✗ 且“真正生效的那一份”不可判 ✓
  · 实现上就是**逐块切换**（粒度＝块，✗ 全故事一次切）：故事补一块 ⇒ 那一块立即改走声明 ✓
```

## 4. 验收（草案）

```
① ★引擎侧**领域词归零**：扫 `Sg.ui.*` 实现体 ＋ 表示面（StoryCaption 的替代件）
   ⇒ 出现 `hp`／`gold`／`inventory`／`gear`／`status` ⇒ 红并点名文件:行
   （门形照 `engine-story-free`／`test/vitals-consumers.mjs` 的"按块扫 ＋ 新旧形两断" ✓）
② ★原语**纯函数可测**（✗ 不经故事）：`bar({value:7,max:20})` ⇒ 给定 DOM 串；`list({items:[…]})` ⇒ 给定串
③ ★声明面**两态**：改 `panels[].label`（或 `key`）⇒ 屏上跟变（照 `#1531` 的形 ✓）
④ ★**"没声明 ⇒ 玩家面不渲染"**：零 `panels` ⇒ 侧栏无状态块（✗ 不是"渲染一个空血条"；
   也 ✗ 印 `（空）` ✗ 印 `$pc.x` —— ★玩家面应**干净的空**，✗ "空面出声"那行属**开发者面** ✓）
⑤ ★**"假值不画"**：故事没声明 hp ⇒ 屏上 ✗ 出现任何血条（今天会出 `❤ 0 / 1` ⇒ 本条能假 ✓）
⑥ ★**过渡期逐块切换（§3.1）**：故事补一块声明 ⇒ **那一块立即改走声明**（✗ 旧内置块仍画 ✗ 两块并存）
   —— ★能假：补声明后若屏上仍出现**两份**（或旧那份优先级更高）⇒ 本条红 ✓
```
