> **依据**：`#1780` 第八节的未落面**第 6 条**：「本仓 3E 面**尚无**『力量检定』类消费点（无技能系统），

## 一、现状勘定（实取，不凭印象）

core 只给通用掷骰 `RPG.roll`（`05-dice.js`）；两包各自有 `d20()`。**检定逻辑散在 5 处**：

| # | 位置 | 形 | 状态 |
|---|---|---|---|
| 1 | `dnd-5e/core/conditions.js:146` `DND5E.save` | `d20 + modOf(stats, ability) >= dc` | **已收敛成函数**（自洽支有效） |
| 2 | `dnd3/core/saves.js:15` `DND3.save` | `1d20 + mod` 对 `dc`，按**豁免类型**索引 | **已收敛**，但口径与第 1 处不同 |
| 3 | `dnd3/core/traumas.js:131` `treatTrauma` | `1d20 + mod` 对 `dc` | 有局部实现 |
| 4 | **`dnd3/core/chest.js:15` 撬锁** | `DND3.d20() + DND3.modOf(that?.stats, 'dex')` | **内联手写，未收敛** |
| 5 | **攻击骰面**（见下「第 5 行原表不全」）：`dnd3/core/combat.js:69` 与 `d20m/core/combat.js:99`，**及逐字复制该式的 5 处**：`dnd3/items/trap-shock.js:7`、`trap-needle.js:9`、`trap-fire.js:7`、`bomb.js:20`、`dnd-5e/core/combat.js:91` | 内联 | 攻击面（**见第五节 边界**） |

> **第 5 行原表不全**，这是落码时发现的**本稿自身缺口**：
> 原表只举了**两包 combat** 两处，但 `grep -rn "die !== 20" src/` 显示该攻击式
> （`die !== 20 && (die === 1 || die + atkMod < ac)`）**被逐字复制到 5 个文件**（3 个陷阱、炸弹、5E combat）。
> **分类未变**，因为它们确是攻击骰，第五节边界照旧适用，但**清单面漏了 5 处**。
> 因此有一条**共同教训**（与本日 E2 立的「**双向差集**」同条）：**列了「列举项都在」不等于「没有漏项」**；
> 本稿在 `#1800` 评审时，tester-4 与我**都只做了前一半**，也就是逐条验证表中 6 条属实，**后一半没人做**。
> 修法是：**凡「清单式」勘定，须附「实况计数与清单计数」的差集读数**，本行即按此补。

**#1780 实撞的实取证据**（本稿独立复核，不是转述）：
```bash
grep -rn "modOf(.*'str'" src/dnd/dnd3/     # ⇒ 恰 1 处：combat.js:54（攻击掷骰的 abilMod）
grep -rn "'str'" src/dnd/dnd3/ --include=*.js   # ⇒ 同上，仅 1 处
```
因此 **3E 面确实没有任何「力量检定」的消费点**，设计稿第四节 C2 的陈述**逐字属实**。
于是 `fracture` 初版的「力量检定 −2」会成**死旗标**（罚无处生效），改绑近战伤害是**当时唯一可落的选择**。

## 二、落形：**薄壳，加值来源由包侧传入**

> **落码时的两处差量**（本设计稿对实现 `#1798` E1a）：
> 第一，**入参改名 `total` 为 `bonus`**。原稿入参与返回的 `total`（等于和）**同名不同义**，
>    是**命名冲突**，会把「传入的其它加值」读成「总和」。入参改 `bonus`，返回 `total` 仍等于和。
> 第二，**补 S6 的返回形政策**，见下。tester-4 于 `#1800` 评审指出：原稿 S4 的形与四个消费方的既有形
>    不兼容，而 S6 的「行为零变」**未覆盖返回形**这一维。

```js
// core（实落 `src/core/05-dice.js`，与 `RPG.roll` 同档 —— 掷骰族）
RPG.checkRoll = ({ mod = 0, dc = 10, die = '1d20', bonus = 0 } = {}) => {
  const roll = RPG.roll(die);          // 掷骰经既有 `RPG.roll`（不另造随机源；它**返回数**）
  const total = roll + mod + bonus;    // bonus 是包侧已加好的**其它**加值（如 3E 的创伤罚）
  return { success: total >= dc, roll, mod, bonus, total, dc, die };
};
```

**规范句**：

- **S1**：检定判定的**统一形**是「**掷骰加加值对阈值**」；`success === (total >= dc)`，边界取「**大于或等于**」。
- **S2**：**加值来源**（`mod` 与 `bonus`）由**包侧**计算并传入。core **不认识** `stats` 的字段语义，
  因为 3E 按**豁免类型**索引 `save_*`，5E 走 `modOf(stats, ability)`，两包口径本就不同。
  因此是 **core 提供机制（掷骰与比较），包侧提供语义**，与 `#1760` 层表注册面、`#1794` `defStock` 同哲学。
- **S3**：**骰面族**由调用方给，缺省 `'1d20'`。**d20m 是百分骰**，因此传 `'1d100'`，core 不硬编 d20。
- **S4**：返回值形是 `{ success, roll, mod, bonus, total, dc, die }`，其中 **`total` 是和，含 `mod` 与 `bonus`**，
  而**不是**裸 `roll`（`#1780` 第四节 C3 的用例断言锁的是 `total`：脑震荡罚须**进 total**）。
  还有一个要点是 **`mod` 与 `bonus` 分离**：3E 的「角色自身豁免加值」与「创伤罚」是两个来源，
  合账会丢失「**罚不改 `mod`**」的既有语义，这一语义在 `saves.js` 的注明里有写。
- **S5**：**无副作用**。本函数只掷骰与比较，**不写任何状态**，不出手，也不改 hp、effects、items。
  因此它与 `RPG.roll` 同级（纯判定），写路径仍归调用方。
- **S6（本笔按 tester-4 的 `#1800` 评审补全）**：**「行为零变」含「返回形不变」**。
  薄壳**只共用判定式**（`d20 + 加值 >= dc`），**不强行统一返回对象**，各消费方
  **保留其既有键**（`DND3.save` 的 `trauma`、`DND3.treatTrauma` 的 `ok` 等等），由调用方自行构造返回对象。
  **判据**：收敛后 `DND5E.save`、`DND3.save`、`DND3.treatTrauma` 的返回**键集逐键不变**，
  否则 `traumas.test.js` 读 `b.trauma`、`span1-hub.js` 读 `r.ok` 会红（实测如此），
  而且四消费方的**既有用例逐条仍绿**。

## 三、收敛：把第一节的散点改走本原语

| # | 位置 | 处置 | 返回形 |
|---|---|---|---|
| 4 | `dnd3/core/chest.js:15` 撬锁 | **改走 `RPG.checkRoll`**（本稿的**首要收敛点**） | 原**无返回对象**，因此播报文案不变（`r.total`） |
| 1 | `dnd-5e/core/conditions.js:146` `DND5E.save` | 薄壳（**行为零变**） | **4 键不变**：`success/roll/mod/dc` |
| 2 | `dnd3/core/saves.js:15` `DND3.save` | 同上（创伤罚走 `bonus`，**不**并入 `mod`） | **6 键不变**：含 `trauma` |
| 3 | `dnd3/core/traumas.js:131` `treatTrauma` | 同上 | **5 键不变**：键名是 **`ok`**，不是 `success` |
| 5 | 攻击骰（两包 combat） | **不并入**（见第五节 边界） | — |

**规范句**：

- **S6**（**本笔按 tester-4 的 `#1800` 评审补全**）：`#1/#2/#3/#4` 改走本原语后，**既有断言逐条仍绿**，
  这是收敛的**验收条件**；而且 **「行为零变」含「返回形不变」**：薄壳**只共用判定式**，
  **不**强行统一返回对象；各消费方**保留其既有键**（`trauma`、`ok` 等等），由调用方自行构造返回对象。
  **判据**：三处有返回对象的**键集逐键不变**（实测：`traumas.test.js` 读 `b.trauma`、
  `span1-hub.js` 读 `r.ok`，因此改形即红）。
- **S7**：本仓**新增**的检定**一律**走 `RPG.checkRoll`，**不**新写内联 `d20() + …`。

## 四、与 `#1780` 实撞的关系：**骨裂可重挂的标准**

`#1780` 第八节第 6 条留了话：「**将来落技能面时，宜由那一笔决定是否把骨裂重挂到力量检定上**」。
因此本稿给出**重挂的判据**，而**不在本笔重挂**，因为那是 `#1780` 后继票的事：

- **S8**：若将来重挂 `fracture` 到力量检定，须**同时**满足三条：
  ①力量检定**有真实消费点**，**不**只为创伤造一个假调用；
  ②**不与 C2 的伤害罚重复**，两者是不同量纲，因此二选一，**不**双罚；
  ③重挂后**既有用例**（`dnd3 trauma：C2 骨裂——近战伤害 −1`）须**同步改**，并注明裁定来源。

## 五、边界（**不做**）

- **✗ 不并入攻击骰**：攻击是 `1d20 + bab + abilMod` 对 **AC**，不是对 DC，而且含**重击确认**（第二次 d20）；
  强行并入会造出「攻击是一种 skillCheck」的**假统一**，何况 5E 的攻击还有 adv/dis 面。
  **落码时该边界被进一步证成**：原稿只给了「对 AC 加确认掷」两条理由，实取后**多两条**。
  第一，攻击式含 **`nat-20` 必中与 `nat-1` 必失**语义（`die !== 20 && (die === 1 || …)`），
     `checkRoll` 的形（`total >= dc`）**结构上无法表达**「骰面值本身触发」的规则。
  第二，该式**已被逐字复制 5 份**（3 个陷阱、炸弹、5E combat，见第一节），若并入，须把
     「必中与必失」也带进 `checkRoll`，那是**把两条规则混成一个函数**，与本原语的立意相反。
  因此**两条都支持「不并入」**；**另立一笔的候选**是「攻击掷骰的复制份数」本身是可收敛面，
     但它属**攻击**而非**检定**，**不是**本笔，记此备查。
- **✗ 不建技能系统**：本笔只给**判定原语**，✗ 不给技能表／熟练加值／技能点。
  `#1780` 第八节第 6 条说的「无技能系统」是**内容面**的缺口，本笔只补**机制面**。
- **✗ 不做 adv/dis（优势与劣势）**：属 `#1798` 后续期「E1 其余（rollMode、constraints、canAct、移动）」。
- **✗ 不改 random 源**：掷骰一律经既有 `RPG.roll` 与 `RPG.rng`，这是 `#1706` 契约。

## 六、用例与规范句

| 用例 | 规范句 |
|---|---|
| core：`checkRoll` 形 —— `success`、`roll`、`mod`、`total`、`dc`、`die` 六键俱在 | S1／S4 |
| core：**边界** —— `sum === dc` 因此 `success: true`（3E 与 5E 皆「大于或等于」） | S1 |
| core：`mod` 由调用方给，因此加不同 `mod` 得不同 `total`（core 不认识 stats） | S2 |
| core：**d100 骰面** —— 传 `die:'1d100'` 因此读数落在 1..100（**不**硬编 d20） | S3 |
| core：**无副作用** —— 调用前后角色 hp、effects、items **逐字不变** | S5 |
| dnd3：撬锁改走本原语后**既有用例仍绿**（行为零变） | S6 |
| dnd3：`save` 与 `treatTrauma` 改走本原语后**既有用例仍绿** | S6 |
| dnd-5e：`save` 改走本原语后**既有用例仍绿** | S6 |
| **S6：四个消费方的返回形逐键不变**（`5E save` 4 键／`3E save` 含 `trauma`／`treatTrauma` 用 `ok`／`not-held` 早返回含 `why`） | S6 |

## 七、未落面（逐条声明，**留白**）

1. **✗ 技能表与熟练加值**：本笔只给判定原语，内容面缺口见第五节。
2. **✗ adv/dis（rollMode）**：属 `#1798` 后续期 E1 其余。
3. **✗ `constraints`、`canAct`、移动**：同上。
4. **✗ 骨裂重挂**：本稿只给**判据**（§四 S8），✗ 不重挂（属 `#1780` 后继票）。
5. **✗ 百分比检定的语义面**（d20m）：本笔只保证**骰面可传**（S3），✗ 不定百分骰的成功语义（那属 d20m 包）。
