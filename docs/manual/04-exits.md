## 4.1 出口分两类：**终局** 与 **章节出口** [锚]

```
终局（10 个）／章节出口（5 个）—— 都走同一个宏：`<<ending>>`（`src/80-script.twee:133-135` 的注释即口径）
  ★"每个结局都有出口"**只依赖 `<<ending>>` 一处**（✗ 不靠每段各写一份 ✓）—— 原文：图鉴门已强制所有 `结局*` 段落都调它 ✓
```
**为什么要有这个宏**（同处注释）：它给每个结局发一张**出口卡**（退回上一步／读档／从头再来…）⇒ 玩家**不会卡在结局页** ✓
**落点**：卡片写在 `<<ending>>` 里（渲染在段落**顶部**），再由 `:passagerender` 把它**挪到段落末尾** ✓（与 §8 面板同族的"挂载时机"问题 ✓）

## 4.2 执行器四张面：用例拿什么判段 [锚]

权威实现＝`scripts/case-run.mjs:92-101`（**逐条**）：

| 面 | 形状 | 判法（原文） |
|---|---|---|
| `visible` | `string[]` | 每一项**必须在渲染文本里出现**，否则出 `{kind:'visible'}` ✓ |
| `absent` | `string[]` | 每一项**必须不出现**，出现了就出 `{kind:'absent'}` ✓ |
| `edges` | `{from,label,to}[]` | **按 `label` 比**（`seen.edges` 的 label 集合里必须有它 ✓）—— ★比的是**标签**，✗ 不是目标段名 ✓ |
| `state` | `{ "<路径>": <期望值> }` | 按**路径**取 `seen.state[path]`，与期望**逐字比对**（JSON 相等 ✓） |

**用法**：四张面**各自独立**（✗ 不互相替代）：`visible` 判"该出现"、`absent` 判"不该出现"（**反向断言** ✓）、`edges` 判"出口在不在"、`state` 判"状态值" ✓。
★`absent` 这一面**最容易被忘**：只写 `visible` 的用例**证明不了**"旧文案真的没了" ✗ ⇒ 凡是**改文案/换分支**的改动，都该配一条 `absent` ✓。

**反例形态（✗ 这样写判不出来）**：
- 只写 `visible` 不写 `absent` ⇒ "**旧文案残留**"这种坏法**看不出来** ✗（改结局文案时尤其危险 ✓）。
