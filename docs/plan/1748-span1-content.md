## 二、段内定标系数（**house rule，非 SRD**）

依 `#1729` 裁定②：`#1712` pin 表只 pin SRD **原值**；**任何段的缩放系数若未成文，即「未 pin 的隐藏判据」**。
本笔把一段的定标成文在**码内**（`src/dnd/dnd3/core/climb.js` 的 `DND3.SPAN1_SCALING`），三条原则：

1. **层内 CR 带**逐层递增（`L1`–`L2` ≤ 0.5 → `L3`–`L4` ≤ 1 → `L5`–`L9` ≤ 2），不越段（段间由单向门分割 ⇒ 段内自洽即可）；
2. **第 10 层（hub）不设战斗遭遇**（整备区）⇒ 无 CR 带、遭遇表无条目；
3. **道具价值带** `maxGp: 2`（就地取材，以简易武器价带下限为锚：木棒 0 gp／矛 2 gp）。

> **不变式（可测）**：遭遇表每层引用的敌人 CR ≤ 该层 `crBand.crMax`。该不变式有对应用例
> （`tests/unit/dnd3/span1.test.js` 的「定标自洽」格）——定标从「文档承诺」变成**机械可判**。

## 三、遭遇表条目（对齐 `#1748` 票面契约）

契约（领队钉在票面，**单向**：实现需改形须先回票修契约）：

```js
// 层元数据（挂 WorldMap 位置或独立表）
{ id, type: 'climb'|'hub'|'exit', start? }
// 遭遇条目（按层 id 键控，B2 表驱动消费）
<层id>: { encounters: [{ ref, weight, elite? }], loot: [{ id, weight, qty? }] }
```

本笔产出（`DND3.ENCOUNTER_SPAN1`，`src/dnd/dnd3/core/climb.js`）：`L1`–`L9` 九行、`L10` **无条目**。
两条纪律：

- **只引注册 id，不内嵌数值** —— 敌人引 `RPG.characters` 的 id（`badger`/`wolf`/`boar`/`monitor-lizard`），
  掉落引 `RPG.items` 的 id（`coin`/`herb-poultice`/`wood-spear`/`bone-dagger`）。
  数值改动只需改定义面 ⇒ 本表零改动（防两套语义）。
- **抽样经 `RPG.rng`**（`#1710` 约定）—— 本表只给权重与组合，不自行掷骰（消费方＝ B2 实现）。

权重为层内相对值；`elite: true` 供消费方取「精英标记」（本笔只标、不消费）。

## 四、第 10 层整备 Scene 骨架（非战斗区，最小形）

`src/dnd/dnd3/scenes/span1-hub.js`，三件（照票面，**不多做**）：

| 件 | 落地形 | 后续接线 |
|---|---|---|
| ① 整备点 | `Location('L10-camp')` + 一个 action（入口） | 休息/消耗品规则归 `#1747` |
| ② 聚落建设入口 | `Location('L10-settlement')` + `when` 前置位（入口） | 资源 id 与消耗端归 `#1747`（本笔不抢定资源语义） |
| ③ 升层单向门 10→11 | `DND3.span1GateExit()`（`RPG.Exit`，**只给定义不挂图**） | 挂图归 `#1746`（届时 `L11` 已存在，不悬空） |
| — | `Span1HubScene()`（入场文本 ＋ 两个非战斗选项） | 试玩载体形态归 `#1746` |

**单向的机械表达**：全图**不存在** `L11 → L10` 的边（段内自由、段间封闭，见 `outline.md`「单向门法则」）。
**为何不挂图**：`L11` 实体归二段票 ⇒ 现在 `addPath` 会造悬空边、`validate()` 必红。
本笔用 `map.validate()` ＋「无反向边」两个断言把该口径**机械化**。

**不含**（显式排除）：居民／剧情／献祭兽／建筑树 —— 前两项依赖留白（居民来源），后两项超出「整备」射程。

## 五、门侧缺口（本笔发现，**修门归测试域**）

`tests/gates/name-map.json` 的 C 组校验硬编码 `### <entry>` 前缀（`refs-integrity.mjs` 的
`const want = \`### ${mapHit.source.entry}\``）。而 3E 的 `Monsters/Monsters - Animals.md` 条目
一律是 **h2**（`## Lizard, Monitor`）⇒ 若把本笔的映射并入 C 组，**必假红**。

- 本笔处置：条目已入表但置 `"cCheck": false`（字段当前被门忽略，等于不参与 C 组），
  并在该条 `why` 里写明原因 ⇒ 映射数据在表（单一权威源），校验缺口可追溯。
- 建议（**测试域**，非本笔车道）：C 组前缀放宽为 `#{2,6}`（或按源文件声明标题级）。
  一旦落地，把该条的 `cCheck` 去掉即可。
