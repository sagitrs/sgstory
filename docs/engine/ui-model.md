# UI 模型

本篇讲清一件事：**引擎怎么把"可点的东西"摆到玩家面前**。

故事侧的一切交互（段内选项、道具使用、菜单、能力触发、时代翻转）都归**同一条渲染原语**；引擎在这条原语上只提供一个新增摆放，不新造交互概念。想加新交互形态的作者，走文末的**提案制**。

本篇是**形态说明**，不是待办清单：讲"终态长什么样、边界在哪"。具体落地在 `#1222`／`#1223`（见文末"下游消费者"）。

## 一、一条渲染原语吃下全部交互面

```
输入：条件（可用性） ＋ 数据集（要摆哪些项）
输出：可点项（点它 ⇒ 去某处）
```

段内选项与常驻动作条**是同一个渲染原语的两种摆放**——输入形态相同，差别只在**位置**：

| 摆放 | 位置 | 典型来源 |
|---|---|---|
| 段内选项呈现 | 当前散文段之内 | 车卡三轮选一 |
| 常驻动作条 | 界面常驻区（侧栏扩展区） | 道具使用、菜单打开、能力触发、时代翻转 |

这条统一结论是我方实现与文档的**收敛点**：任何"新交互"只要落不进这两个摆放，就是真新概念，得走提案制；能落进去，就只是**数据 + 摆放**。

## 二、段内选项呈现（纯渲染）

当前段**自己的选项**怎么摆（卡片或链接）。

- 输入：纯数据（本段的选项集）；
- 输出：一次回调（点了哪个）；
- 不持有业务状态 —— 它不关心点了之后发生什么。

车卡的三轮选一归这里：它是"段内选项"的一种摆放形态，不是独立机制。

## 三、第三选项：条件 ＋ 跳转 ＋ 返回策略

界面上的动作按钮，本质是**"在任何时刻都可以强制跳转到特定散文的第三选项"**——当前段落只有"左转／右转"两个选项时，界面上那个"绷带（＋2HP）"就是随时可选的第三个。

对它的定义（Operator 原话，见"出处"）：

> "ui 的本质是一种'在任何时刻都可以强制跳转到特定散文的第三选项'，这么理解对吗？"

例：绷带在界面 UI 里，而当前段只有"左转／右转"→ 点绷带 ＝ 进入绷带结算事件，结算完成后**回到原事件**；回城卷轴同形，但结算完成后**不回原事件**，进入城镇。

### 数据面只剩两样

```
{ 可用条件, 目标段 }
```

- **可用条件**：条件真 → 该项出现在动作条上；条件假 → 不出现（不做置灰，不出现就是不存在）；
- **目标段**：跳转目标 ＝ 一段**普通散文**（结算散文；它自己也可以有自己的选项）。

这俩甚至可以从道具行派生 —— 不需要为它专门开字段家族。

### 返回策略是散文写法，不是引擎概念

这是本模型**唯一容易多造概念**的地方，所以定死：

> "实际上除了界面上的按钮以外其他机制都是现成的。跳转本质是链接，目标本质是散文，返回策略本质是散文内链接，只不过对大多数道具而言，这个散文内链接可能是一个叫'继续'的'回到上个散文'的链接，不必新造概念。"

拆开说：

| 环节 | 本质 | 是不是引擎新概念 |
|---|---|---|
| 跳转 | 链接 | 否（现有） |
| 目标 | 散文段 | 否（现有） |
| 返回 | **散文内链接** | 否（现有） |

→ 于是：

- **没有 `return` 字段**，**没有策略枚举**，**引擎零流程编排**；
- 绷带回原段：作者在**结算段末尾**写一个返回宏（回到上个散文）——大多数道具用这个；
- 卷轴落城镇：作者在结算段末尾写一个**普通链接**指向城镇段 —— 落定地就是那一行链接；
- "返回策略"是对作者写法的**描述**，不是引擎要认的字段。

**引擎在这条原语上唯一的新增**是把状态驱动的可点项渲染成**常驻动作条上的按钮** —— 按钮不是新机制，它是**链接的另一种摆放**。

## 四、状态投影

"状态投影"指**把已有状态展示出来**（显示件）—— 玩家看到数值、名目、图鉴条目等。

边界：

- **只读**：投影不改状态、不产生跳转；
- **与动作条互不相干**：加动作条**不动**既有状态展示；动作条上的按钮是"可点的东西"，不是投影；
- 需要"点一下看详情"时，那是**第三选项**（条件 ＋ 目标段），不是投影的职责。

## 五、常驻动作条（＝按钮即链接的摆放）

- **位置**：界面常驻区（侧栏扩展区），不随当前段落增减而是**常驻**；
- **内容**：所有**可用条件为真**的第三选项，逐个渲染成按钮；
- **行为**：点击 → 跳到该项的结算段；结算段按作者写法（返回宏或普通链接）落定；
- **不变式**：条上出现什么，完全由**条件**决定 —— 同一份存档、同一时刻，读数可复算，不依赖"什么时候点的"。

## 六、不预设可扩展框架（提案制）

引擎**不预先**为"将来可能的交互形态"留框架、留钩子、留插件位。理由是：框架一旦预置，就要求作者把机制掰成框架的形状，代价由作者付、账记在引擎上。

要加真正超出上述两个摆放的新形态 → **走提案制**：

1. 先说清"它落不进段内选项／动作条"的**理由**；
2. 给出**最小形态**（输入什么、输出什么、谁持有状态）；
3. 附**字节账**（删什么、增什么、净效应）与**验收面**（玩家可见面是否逐字节同）；
4. 由 Operator 过目后动码。

（这套流程不是本档新立，`#1222` 就是按它走的：先提案、Operator 两刀砍完、提案终版定稿、再动码。）

## 七、模板实体说明

"模板实体"指 UI 侧承载渲染的具名单元（如卡片列表、动作条、显示件）。约定：

- **模板里零故事字面量**：模板吃数据、不吃故事名字；故事名一律由数据带进来；
- **模板要具名**：故事侧引用**名字**，不内嵌骨架（这是"渲染能力进引擎"的原型口径，见 `#1177`）；
- **一个模板只做一种摆放**：段内选项与动作条各是一个模板实体，共用同一条渲染原语；
- **模板变动 → 玩家可见面必须逐字节同**（除提案明确要改的那一面），这是所有 UI 收编的验收基线。

## 八、资产面（图片与图标）

来源：Operator 2026-09-23 裁定（甲案）＋ `#1225`。

### 口径（甲案）

- **资源随产物拷本地**，产物保持**自包含、可离线**：不引外链、不依赖 CDN；
- **美术资产住 books 仓**（故事侧），不进引擎仓；
- **图片二进制不计入体积门**：另开 `rows.assets` **单独登记**（登记总量与件数，不设硬额度；见下文门的三面）；
- **URL 作为属性计入**（数据面可见，可被门读到）；
- **单页 HTML 保留，资源旁挂** —— `dist/fonts/` 是先例（按故事实际用字数子集化为 woff2 旁挂，页面用相对路径引）。

### 数据位

道具／条目行上放一个图标位（与文本名并列），故事数据只写**名字**，取到哪张图由资产面决定。

**无图退文字**：条目没配图时，槽位的**默认行为是退回文字**——不出现空位、也不隐藏该条目；"有图标"是增强，"没图标"是常态，作者无需为缺图另作声明。

### 定案（2026-09-23 裁定；原先三件待定已决）

**一、位名与形态 ＝ 契约成员**

图标位是**条目的一部分** → 归契约管：在 `contract.json` 声明一个成员（`itemIcon` 形态），吃到缺省机制，可被契约缺省判据校验。

- **值一律写相对路径**；**绝对 URL 本批不支持**（见下文边界二），但属性形态**留出可容纳 URL 的位置**。
- **代价如实登记**：契约成员数 +1 → `test/contract-defaults.mjs` 里三个夹具故事的钉值（`EXPECTED_DATA_MEMBERS`）随之同改，谁后合谁带上（与 `#1219` `pcShape` 那次同形）。
- 另一条路（数据面自有位，如 `tables.json` 行上直接加一个字段）**未取**：那要先开"数据面允许扩展字段"的口子，是比加一个成员更大的契约决定。

**二、拷贝链与命名 ＝ 保源名整目录拷贝**

源 `stories/<slug>/assets/**` → 构建时**整目录拷**到产物侧，页面用**相对路径**引（与 `dist/fonts/` 同一摆法）。

- **不做内容哈希**：本产物是离线自包含，内容寻址的唯一收益（缓存失效）在这里不存在；而它要多一层"数据名 → 产物名"的**映射**，映射是可腐面（与"两份清单必腐"同族）。
- **登记口径**：随包资源进 `story-manifest` 的清单里（**清单是登记，不改名**），与"清单派生"的既有语义对齐。

**三、预算线与门 ＝ `rows.assets` 只作登记，门咬"引用"与"清单"**

- **门咬的两面（各配能假例）**：① **引用面** —— 引用了产物里不存在的资源 → 红（能假：删掉那件资源，门当场点名）；② **清单面** —— 清单与实际文件不一致 → 红（能假：清单里多写一件未拷贝的文件，门当场点名）。
- **体积只登记**：`rows.assets` 记二进制总量与件数，作**展示与趋势**；**不设硬额度**（与"图片二进制不计体积门"一致）。将来若要有线，只可设**提示线**（超线告警、不阻断）—— 那不是门。
- **不影响首屏读数**：assets 不进 `index.html`／`fonts` 两行 → 首屏门读数与现在一致。
- 一句话承诺：**门咬的是引用与清单，不是图片体积；体积只登记**。

### 边界

1. **不做上传／编辑工具**：资产面只定义"住哪、怎么拷、怎么计预算"；**不含**作者在本仓上传／编辑图片的工具链。
2. **绝对 URL 变更需另票**：本批只把 URL 作为属性计入（值要求相对路径）；远程托管策略的变更**另开票**。

### 素材与许可

优先 CC0（如 Kenney），其次 MIT／Apache／OFL（如 Tabler），CC BY 需署名面（如 game-icons.net），尽量不用 CC BY-SA／GPL。建议随资产放一份 `assets/CREDITS.md`：文件名、标题、作者、许可、来源 URL。
