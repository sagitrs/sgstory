## 一、为什么需要这一层（改前读数）

改前（头 `489948f2`）的登记面是一张**平表**：

```console
$ git show 489948f2:src/core/ports/index.js | sed -n '93,120p'
...
RPG.ports = Object.create(null);
...
RPG.defPort = (key, impl) => {
	...
	if (RPG.ports[key]) console.warn(`[RPG] 端口「${key}」重复注册：将被覆盖。`);
	RPG.ports[key] = impl;
	return impl;

```

⇒ 三点事实（各有命令与读数）：

| 事实 | 命令 | 改前读数 |
|---|---|---|
| 宿主 id 有声明、无消费 | `git grep -n "SUGARCUBE\|sugarcube" 489948f2 -- src` | 只命中 `src/host/sugarcube/**` 自身 ⇒ **装饰件** |
| 登记面无宿主维度 | 上引代码 | 平表 ＋ 重复只 `console.warn` ⇒ 两宿主同载时**后者覆盖前者**，行为取决于加载序 |
| 内核唯一消费点 | `git grep -n "portOf" 489948f2 -- src` | 仅 `src/core/55-session.js:146-148`（`ports?.x ?? RPG.portOf('x')`） |

结论：三端口**已落**（`#1917`），但「换一个宿主」在当时**不可能** —— 不是缺端口，而是缺**宿主身份**。

## 二、契约（本笔落地的面）

| 面 | 形 | 语义 |
|---|---|---|
| `RPG.defHost(id, {desc})` | 登记 | 同 id 重复登记 ⇒ **具名抛**（✗ 静默覆盖） |
| `RPG.defPort(key, impl, {host})` | 填入 | `host` **必填**（✗ 缺省落影子表）；未知 host ⇒ 具名抛；缺方法 ⇒ 具名抛（复用 `portMissing`） |
| `RPG.useHost(id \| null)` | 选择／清除 | 未知 id ⇒ 具名抛（列候选）；`null` ⇒ 回到自动规则（**不是**「选默认宿主」） |
| `RPG.hostOf()` | 读数 | **已定宿主** id；未定 ⇒ `null` |
| `RPG.hosts` / `RPG.hostIds()` / `RPG.hostsReady()` | 读数 | 登记表／已登记 id ／各宿主缺哪些端口（✗ 不抛） |
| `RPG.ports` / `RPG.portOf(key)` / `RPG.portsReady()` | 解析 | 端口袋与取用面（签名未变） |

**解析规则（单一权威，一处实现）**：`已定宿主` ＝ `显式选择` ?? `恰好一个登记（自动）` ?? `无`。

- 0 个登记 ⇒ 抛「**无宿主登记**」；
- ≥2 且未选 ⇒ 抛「**宿主未选择 ＋ 候选清单**」；
- 已定宿主但没提供该端口 ⇒ 抛「端口 X **未注册**（宿主「Y」未提供它）」。

三者**互不同形**：前两者是「宿主层面没定」，第三是「定了但缺件」。

## 三、为什么这样切

1. **单一权威**：解析规则只在一处（`已定宿主()`）。两处各写一份 ⇒ 早晚不一致，而这类不一致正是
   「哪个宿主在跑」不可判的根源。
2. **两种具名抛而不是一种「端口不在」**：若多候选时静默取第一个，则「内核替调用方猜」，
   行为回到**加载序决定**——那正是本层要消灭的形。
3. **单宿主自动定**：既有配置（`src/host/` 下只有 SugarCube 一个宿主）行为**逐字不变** ——
   由改后读数背书：单测 `pass=770→774 fail=0`、老宅 `cell=16 pass=78 fail=0`（改前后同值）。
4. **「内核不知宿主」从纪律变机制**：门新增「宿主标识」判据（第四节）。

## 四、判据与门（落点）

- 判据：`tests/unit/core/hosts.test.js` 四格 —— ①登记读数＋登记四路具名抛；②多候选未选⇒具名抛＋列候选＋
  端口袋空；③零宿主与未选择两种形可分；④★**核心正控**：用例内**自造**的最小宿主上跑完一个 `GameSession`
  （构造时**不注入** `ports`），并断 SugarCube 宿主收集器零条（收口未漏）。
- 门：`tests/gates/host-touchpoints.mjs` 增「宿主标识」判据 —— `src/core/**` **不得提及**任何已登记宿主 id 的
  **字面量**；id 集合从 `src/host/**` **动态**提取（✗ 硬编码清单）；**空集即红**（✗ 判据静默空转）。
  口径与同门的棘轮相反：**算原文、不剥注释与字符串** —— 要抓的恰恰是字面量（剥了就把它剥掉了）；
  需举例处用 `<宿主 id>` 占位符。同笔加 K24 刀。
- 刀架：`tests/unit/framework/knives.mjs` 加 `silent-first-host`（把自动规则从「恰好一个」放宽成「至少一个」）
  ⇒ 须**恰红**「宿主②」一格；单宿主自动定、零宿主形、显式选择三处**不受影响** —— 即三种形互不混淆的机械证据。

## 五、本笔**不做**（切片 B，另票）

- **产物级选择**（`build.py --host <id>`）：现 `collect_js_files()` 把 `src/host/**` **无条件**打进产物
  ⇒ `src/` 里一旦真有两个宿主，无头／老宅／e2e 都会撞「多候选未选」⇒ 必须先有产物级选择。
- **第二个随仓宿主适配器**（如 `src/host/headless/`：内存 persist/render/lifecycle，供编辑器／CLI／无头复用）。
- 与 `sgstory#1940` M2 的**单向委托域**（UI 公共入口收口）无同文件冲突，两笔可并行。
