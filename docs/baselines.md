# 基线报告：E4 节奏密度 · C4 路线相异度

> 探索票 **#295**（伞 #297）。**只读报告＋基线 ratchet**，不是 CI 硬红：先入基线，数字稳定后再谈阈值。
> 数据源：`build/route-traces.json`（`test/scenarios.mjs` 跑 40 条路线时顺带落盘的轨迹：段落序列／点击数／首个不可逆点／当时情报旗标）。
> 复现：`npm test`（生成轨迹）→ `npm run report:rhythm`（出报告）→ `--check` 与基线比对 → `--selftest` 反例自证。

## 判据

- **E4 节奏密度**：五拍（Five Room Dungeon 的经典五段：入口与门槛／谜题或交涉／诡计或挫折／高潮／奖励与揭示）齐备；开局 → **首个不可逆点**（花田致死位点 / 龙战）的**交互数**与**当时情报覆盖**在带内——ratchet 防退化（不许把不可逆点推得更远，也不许推得更早＝铺垫变少）。
- **C4 路线相异度**：不同**游玩路线**的屏文重叠不过高（OPDC「支持多系统」的 twine 等价）——防未来加内容时路线趋同。

## 度量口径（两处踩坑后的修正，值得记住）

1. **截断轨迹不进 C4**：只用了几次点击的专项用例，其轨迹天然是长路线的**前缀**，包含率（inter/min）必然 = 1.000——那是伪信号。C4 只比**走完结局的完整路线**（本次 21 条 / 40 条），截断用例只进 E4 表。
2. **先聚「游玩路线家族」，再比家族之间的距离**：测试用例里有大量「同一段路径的多个用例」（如「平凡之路」×「结局页收尾」相似度 0.994——它们本来就该一样）。直接报两两最大值只会测出**用例重复度**而非内容趋同。故按相似度 ≥ 0.9 自动归并成家族（本次 **16 族**），**家族间**相似度才是真信号。

## 本轮的观察（供后续开修复票/维度立项）

- **③ 诡计与挫折是最薄的一拍**：只有 5 个可达段落、15 条路线经过（对比 ② 20 段/27 条）——第三章的「代价与回退」主要靠花田致死位点与观星者僵局撑，支点偏少。**只登记，暂不开票**（是否加内容属设计取向，需 Admin/D 席定）。
- **首个不可逆点最早 7 击**（花田死亡线），最晚 20 击（中性骰金路径）——带较宽，说明**玩家信息量差异大**（4–13 个旗标），这是有意的分支设计，不是缺陷；入基线是为了防未来把这条带无意拉大或压扁。
- **家族规模**：金路径家族 3 条用例 / 新任守林人家族 3 条用例，其余多为单条——即使扣掉用例重复，仍有 16 个互不相同的游玩路线，相异度健康。

# 附录：就地行动存读档一致性门（#300 §5 机检）

> 来源：操作者 P1 票 **#300**（门厅原地取物后立即 S/L 丢进度）＋ T 席范围扫描。**测试基建，不含产品修复**。

## 为什么需要它（漏测的机理）

| 现有资产 | 为什么抓不到 P1 |
|---|---|
| `test/saveui.mjs`（90 行） | 只做 `Pc.migrate(fixture)` → 渲染 → 点击后断言 `slots <= 1 && hasText`，**从不调用 `Save.browser.slot.save()` / `sgLoadSlot()`** |
| `test/browser.mjs` | 门厅键盘用例在 Enter 之后即停，**不按 S/L** |
| `test/scenarios.mjs` | 路线只断言剧情分支与旗标，**不含存读档往返** |

即：**「操作后状态」与「存档快照」之间的一致性从未被断言过**——这是「全绿 ≠ 关键状态覆盖」的又一实例。

## 两个门

| 门 | 文件 | 何时跑 | 当前状态 |
|---|---|---|---|
| **静态门**（登记完整性） | `test/saveload-inventory.mjs` | **在 `npm test` 链里** | ✅ 绿——它保证的是「**被登记**」，不是「已修好」 |
| **行为门**（存读档保值） | `test/saveload.mjs`（`npm run test:saveload`） | 独立跑；**接入 npm test 的时机＝#300 修复合入的 PR** | ❌ **红＝缺陷基线证据** |

### 静态门保证两件事

1. **就地行动站点不得漏登记**：凡 `<<link>>` 体内含 `<<replace` 且改状态（`<<give`/`<<damage`/`<<set $`）的站点都必须进 `test/saveload-sites.json`；新增同类站点会被立刻抓住（＝#300 票面「不要只对门厅与洞穴打特判」的机械保证）。
   - **口径限制（已显式登记）**：扫描器只看得见 link 体内的**直接**变更；门厅「把墙上那支哨子摘下来」的 `give` 藏在 widget `<<hallResult>>` 里，属**间接站点**，只由行为门盯（静态门仅校验该 widget 仍存在）。
2. **检定 key 必须有归宿**：每个 `<<sitecheck "KEY">>` 的 KEY 要么出现在某处 `<<lastcheckfor>>` 参数里，要么在豁免表写明**理由＋票号**（空豁免＝红灯）。当前 25 个 key：23 个有复显、8 个登记豁免（2 个是已实测缺陷＝#300 P2、5 个待裁定、1 个静态误报）。

### 行为门当前结果（`npm run test:saveload`，缺陷基线）

```
就地行动站点 4 个：0 保值 / 4 不保值
  门厅「把墙上那支哨子摘下来」   丢 inv[坏哨] · 丢 ev[last_roll]
  门厅「先看清钉子是怎么卡的」   丢 ev[hall_seen, last_roll]
  门厅「摘哨子（widget hallPick）」丢 inv[坏哨] · 丢 ev[hall_seen, last_roll]
  塔外花田「伸手去摘最靠里的那一朵」丢 inv[月光花] · 丢 ev[last_roll]
```

四项断言（物品／旗标／HP／金币／检定记录）**逐站全丢**，且**不掉 HP/金币**——与 #300 的引擎级根因分析一致：保存的是 `_history` 快照，同页 `<<replace>>` 的变更进不去。

## 附：dist 过期守卫（2026-09-12 实测咬过一次）

`test/*.mjs` 跑的是**构建产物** `dist/index.html`，不是 `src/*.twee`。源码改了、忘了 `npm run build` 时，
所有 jsdom 断言都基于**旧游戏** → 得到与源码不符的**假红/假绿**。

实际案例：pull 了 G3（#302）之后直接跑 `node test/scenarios.mjs`，得到「#291 G3：两侧证据齐了却问不出（门不可达）」的**假红**——
真实原因只是 `dist/index.html` 落后源码 4 分钟。重建后同一条路线通过（覆盖 85 格）。

现在 `test/boot.mjs` 在任何脚本启动时都会校验 `dist` 是否比 `src/*.twee` 新，过期则**大声报错并给出修复命令**
（不自动 build——那会掩盖问题）。`npm run test:saveload` 已改为先 build 再跑。
