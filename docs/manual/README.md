# sgstory 引擎功能手册

**给写故事的人**：按**功能**组织（✗ 按文件组织）。每节固定五栏 —— **做什么用** ／ **最小例子（可复跑步骤）** ／ **数据面键** ／ **边界与坑** ／ **相关票号**。

> 本页＝手册的目录与**写作规约**。规约见下面「准入条」——**它比目录更要紧**。

## 准入条（每条断言要么可机检、要么可复跑）

```
① 要么带**可机检的锚**（宏名／键族／路径／票号）—— 校验器能核"它还在不在"；
② 要么给**可复跑步骤**（命令 ＋ 期望读数）—— 读者与校验器都能复核；
③ 两者都没有的句子 ⇒ **不许进手册**（"读起来像真的" ≠ "断言成立"）。
④ 读数/行为类 ⇒ 明标**不可机检**，但**必须给复现步骤**；语义/口味类 ⇒ 明标不可机检 ＋ 给**反例形态**。
```
**每节开头标 `[锚]`／`[步骤]`**（决定校验器能覆盖多少）。

**为什么这套例子能"可复跑"**：最小例子直接用仓里现成的东西当载体 ——
`sagitrs/sgstory-books` 的 `cases/north-room/*.json`（真实用例＝一段点击序列 ＋ 一组期望面）、
本仓 `test/fixtures/m3-chk-e2e/`（一条命令 `bash test/fixtures/m3-chk-e2e/run.sh`）与 `test/fixtures/c1282/`。
⇒ 每条例子都能写成「命令 → 期望读数」 ✓

## 防漂移（与校验器的分工）

- **[锚]** ⇒ 从引擎**派生**（**宏清单＝由脚本产出**（与 `#1322` 校验器同源；§3 那段是它的产物，✗ 不手派生）；键族＝`readKey` 的族集合；路径＝`git ls-tree`）⇒ 校验器只判"手册里出现的锚**都还在**"；
- **[步骤]** ⇒ 校验器判"命令**能跑通**且读数**形状**与手册写的一致"（形状，不是逐字）；
- **不可机检** ⇒ 手册里**明标** ＋ 给复现步骤或反例形态。
