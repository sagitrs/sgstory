# `00-meta.twee` —— 入口件（**产物**）

> 实况样本：`stories/night-ferry/00-meta.twee`（构建后生成）。**形状单一权威**：`editor/lib/core/story.mjs` 的 `metaTwee()`；
> **数据源**：`stories/<slug>/data/meta.json`（主源）＋ `00-story.json` 的 `title`／`entry`（次要／兜底）。
> 来源：`#1132` 块二 B4（数据源切换，2026-09-22；三故事的 `00-meta.twee` 由此从手写件改为产物）。

## 0. 它现在是产物，不是手写件

B4 之前：`00-meta.twee` 是**唯一不生成的手写 `.twee`**。B4 之后：它由编译步生成，带 `@generated` 标记，属
**生成物家族第 5 类**（前四类为 `15-tables`／`16-notes-*`／`17-rules`／`18-chargen`）：

- 生成器：`editor/lib/core/emit.mjs` 的 `compileStory()`（写出前先做语法检查，见 `#1176` 的段级语法面）；
- 名字**沿用** `00-meta.twee`（清单／序表／依赖表的路径都不必动）；
- 与其余产物同族：`gitignore` 族、`clean-net` 白名单、`dist-fresh` 的源面排除、K4 的标记／新鲜度判据、
  `#1185` 的"产物必有源"守卫，四处收纳齐。
- 注意 **不要手改**：改了会在下次编译被覆盖（K4 判据会先咬）。

## 1. 源：`data/meta.json`

```jsonc
{
  "section": "StoryMeta",                                      // 必填（缺则编译器干净拒绝）
  "title": "夜渡",                                              // → :: StoryTitle
  "entry": "渡口",                                              // → :: StoryData.start
  "ifid": "4FDB2374-A7A6-4181-AFDD-C2E53D79AAE9"               // → :: StoryData.ifid
}
```

| 键 | 型 | 必填 | 去向 | 校验 |
|---|---|---|---|---|
| `section` | `string` | ✅ | — | 数据面通用：缺 `section` 则编译器拒绝 |
| `title` | `string` | — | `:: StoryTitle` | 缺省 `'未命名故事'`；清单 `title` 是次要源 |
| `entry` | `string` | — | `StoryData.start` | 缺省 `'开场'`；**必须 ≡ 清单 `entry`**（不一致则起始段找不到） |
| `ifid` | `string` | — | `StoryData.ifid` | **UUIDv4 形态且大写 hex**（小写则报 `Story IFID is invalid!`，退出码 1） |

`ifid` 在 B4 是**保真搬运**：三故事（`face-fixture`／`minimal-demo`／`night-ferry`）的新值与被删手写件的原值
**逐字节相同**（`#1183` 复核时用主干历史原文件比对过）。**新故事必须新生成**，照抄既有故事会撞。

## 2. 生成物的三个段

```twee
// @generated by editor/compile-story.mjs（源：stories/<slug>/data/meta.json）——手改会在下次编译被覆盖
:: StoryTitle
夜渡

:: StoryData
{
	"ifid": "…", "format": "SugarCube", "format-version": "2.37.3",
	"start": "渡口", "zoom": 1
}

:: StoryIdentity [script]
window.Sg ??= {};
window.Sg.storyId = { slug: 'night-ferry' };
```

| 段 | 内容 | 校验 |
|---|---|---|
| `StoryTitle` | 故事标题（SugarCube 读） | — |
| `StoryData` | 编译器元数据 | `ifid` 形态（大写 hex）· `start` ≡ 清单 `entry` |
| `StoryIdentity` | `Sg.storyId = { slug}` | **必须与清单 `slug` 一致** → `test/store-keys.mjs` 判红 |

`StoryIdentity` 带 `[script]` 标签，是**脚本段**，因此在 `#1176` 的段级语法检查面内（实测有牙：往该段注入坏脚本，
构建退出码 1 并点名段名）。格式三常量（`SugarCube`／`2.37.3`／`zoom: 1`）留在 `metaTwee` 里，**不因故事而异**。

## 3. `StoryData` 字段表

| 键 | 型 | 必填 | 含义 |
|---|---|---|---|
| `ifid` | `string` | ✅ | 故事唯一标识（UUIDv4，大写 hex）。生成：`node -e "console.log(crypto.randomUUID().toUpperCase())"` |
| `format` | `string` | ✅ | `"SugarCube"`（由 `metaTwee` 固定） |
| `format-version` | `string` | ✅ | 本仓：`"2.37.3"`（由 `metaTwee` 固定） |
| `start` | `string` | ✅ | 起始段落名，≡ 清单 `entry` |
| `zoom` | `number` | — | 缩放（由 `metaTwee` 固定为 `1`） |

## 4. 手写注意

- 改**标题**或**起始段**：改 `data/meta.json`（再跑构建），**不要**改产物。
- **两处一致性是双向的**：`slug`（清单 ↔ `StoryIdentity`）· `start`（清单 `entry` ↔ `StoryData`）。任一处漂移即红。
- 入口件**必须排在 `files` 首位**（见 [`story-manifest.md`](story-manifest.md) §2）。
- 删源而留产物时，`#1185` 的守卫在构建期报"产物仍在，但它标记载明的源不在磁盘上"并点名两侧。
