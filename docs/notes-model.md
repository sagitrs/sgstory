# 笔记模型（线索/情报道具化 → 条件表驱动对话）

> **状态**：设计稿（**阶段 0**），未落任何代码。伞票见 [#422]。
> **目标**：让内容具备**可演进性**——新增线索/分支内容时，不再需要改段落里的手写 `<<if>>`，而是往一张表里加条目。
> **一句话**：把「知识」从散落的旗标收进**笔记**，把「分支」从段落内 `if` 搬进**数据表里的条件表达式**。

---

## 0. 为什么现在做

当前条件用量（实测）：`pc.ev.` **254 处** ／ `pc.world.` **72 处** ／ `pc.inv[...]` 55 处 ／ `pc.gear` 11 处。
其中**知识类**与**世界态类**混在同一个自由命名空间里（`ev` 57 键 / `world` 21 键），导致：

- 段落的可见内容由**段落内手写分支**决定 → 加一条线索要改多处段落，且**无法一眼看全**「谁在读它」；
- 门只能间接守住形状（`--state` 管域归属、`--truth` 管锚句、`--npc` 管动机），**没有人能回答**「这条线索一共有几处消费」；
- 新增内容时最贵的一步永远是「找到所有该并进去的分支」。

**非目标**（明确排除，避免范畴错误）：
- ❌ 不把「世界态」物品化（`flower_fed`／`goblin_spared`／`ending` 回答的是**发生过什么**，不是**你知道什么**）；
- ❌ 不做全自动组合枚举（组合爆炸）；
- ❌ 不删物品栏（持有物与知识是两件事）。

## 1. 三类存储 ＋ 一个条件语言

```
段落/选项内容  ←  select(条件语言)
                   ├── notes   笔记（新）：我知道什么          ← 本次重构的主角
                   ├── world   世界态（保留）：发生过什么
                   ├── items   物品栏（已有）：我拿着什么
                   └── state   数值/态度（保留）：星力、态度、回合…
```

**判定口诀**（唯一权威；`--notes` 门要能自动查，`#432` 复核后定稿）：

> **a.** 能写成「你知道了……」一句**玩家可复述**的话 → **知识（笔记）**
> **b.** 只是「发生过／已拥有」 → **世界态**
> **c.** **运行时**——既不可复述、也不改变世界结果。分两子类：
> **c1 交互记账**（「这一问／这一桌／这一处只给一次」的去重与首遇门）｜**c2 瞬态**（战斗台账、骰面快照、本次结果、本次差额提示）
> **d.** 一个键若**同时**承担两类语义 → **拆成两个键**，别让它两用。

**三类之外的两种形态**（`#432` 复核新增，都是「不落笔记」而不是「归第四类」）：

- **持有物投影**：一个键可用 `inv` 等价表达（例 `#432-B11`：`ev.coord ≡ inv["完整星图"]`）⇒ 不进笔记、不另立状态；
- **推定知识（derived）**：知识由**世界态蕴含**（例 `#432-B14`：`ev.below_seen`＝「下过地下即见过它」）⇒ 可收入笔记，但表内必须标 `derived`，让「笔记＝知识」与「笔记读世界态」两种语义在表上分得开。

**边界①（`#432`，口诀 c 的口径）**：c 的判据是「**不构成可复述知识，也不改变世界结果**」，**不是**「同一次渲染内」——`delivery_short`（同段自清）、`star_short`（`唤醒`→`结局` 跨段）、`threshold`、`errand_done`、`fog_thin`（跨翻转）都属 c。

**边界②（`#432`，`firstTime` 单列）**：`<<firstTime>>` 一键的共性＝「**呈现记账 ＋ 可能顺带承载知识/持有物**」（`tav_seen`／`wq_seen`／`banquet_intro`／`keeper_intro`／`observatory_intro`／`seer_intro`／`tower_top_intro`／`witch_intro`／`tower_gate_*`／`forge_*`／`cellar_*`）。默认归 `c1`，**但承载了知识/持有物的必须在表里另外声明**——`wq_seen` 的 `<<if _first>>` 块同时含身世知识与 `<<give "时光护符">>`，另给它一条知识笔记（`#432-B13`）；`tower_top_intro` 里守林人那句「守的从来不是悔恨」由 `keeper_why` 承载，不许被去重器吃掉。

**逐键判定（93 键）的唯一权威表在 `docs/notes-model-batches.md` §3**——本文件只写口诀与判据，不复制结果（避免两处漂移）。

**知识不是持有物**，所以给笔记一个**独立容器**（不进物品栏；UI 上就是「笔记/线索」页，与图鉴并列或并入图鉴）。

## 2. 数据形状（阶段 1 落地）

```js
Game.Notes = {
  entries: {
    'n_witch_hint': {
      title: '女巫指过的路',
      src:   '女巫小屋',                 // 来源（玩家视角的「从哪知道的」）
      body:  '她说，雾里让路的东西认护符。',
      tags:  ['一章', '地点'],
      era:   'present',                  // 时代归属（用于权威性判定）
      // 阶段 1：**读**现有旗标（笔记是视图，旗标仍是运行时真值）
      grant: (p) => !!p.world.witch_hint,
      // 阶段 3 之后：写点搬到 addNote，grant 退化为兼容读取
      prereq: [],                        // 顺序敏感：必须先拿到这些笔记
    },
    // …
  },
};
```

**薄封装**（唯一入口，便于将来换实现）：`Sg.notes.has(id)` / `add(id)` / `all()` / `missing(req[])`。

**顺序敏感是硬约束**：对话常常「先问 A 才问得出 B」→ 笔记带 `prereq`，选择器按 (`req` 满足 ∧ `prereq` 已达成) 取**首个匹配**（first-match wins），优先级显式写在表里。纯集合模型会丢掉叙事顺序。

## 3. 条件语言（阶段 2–4）

段落/选项只写**数据**，不写 `if`：

```js
// 例：老巫女的合龙门（#291 G3 / #404 已实测过「前提必须可溯源」）
{ id: 'witch_fire', p: '老巫女',
  label: '问她：缺的那一句话，是谁没说完？',
  req:     ['note:n_failure_cause', { any: ['note:n_seer_asked', 'note:n_coord'] }],
  exclude: [],
  premise: '缺的从来不是咒',              // ← 既有门 test/premise-source.mjs 直接沿用
  yields:  'notes:n_witch_fire_hint' }
```

语法保持**极小**：`req`（全部满足）／`any`（任一）／`exclude`（全部不满足）／`prereq`／`premise`／**`prio`（显式优先级，数字）**。

**优先级不靠表序（评审补充的硬约束）**：表里的行序＝隐式语义，最容易烂掉。因此每行写**显式 `prio`**，并由 `--notes` 门加一条**死规则检查**：

> 若存在 **`prio` 更高**的行，其 `req` 是本行 `req` 的**子集**、且作用域（段落/时代）相同 ⇒ 本行**永远不会被选中** ⇒ **红**。

这把「顺序」从表序约定变成**静态可查**（与「每条笔记都有分类与来源」是同一张表上的两个不变式）。

**表语法的已知边界（`#435`，2026-09-14 拍板；都属"行级声明表达不了"）**：

1. **授予依赖判定结果**（`天文台·典籍`：同一条 link 成功→`n_star_ledger`／失败→`n_ledger_hint`；`塔外花田·摘花`：成功`gives 月光花＋sets flower_taken`／失败`sets flower_sleep`）——行级 `yields`/`sets` 表达不了；不搬 ＋ 登记（要解需要"判定面"声明，另票）；
1b. **授予时机**（`书房·读日记` D9）：原 `Sg.notes.add` 在 `<<link>>` 体内（**点击时**），而表行授予恒在**渲染后** ⇒ 同一屏里**后面的块会提前出现**（guest 用 boot harness 实测）⇒ 不搬 ＋ 登记。
   三条边界（①分支内授予 ②多源路径选择 ③点击时 vs 渲染后）本质同一条：**表行授予＝行级 ＋ 渲染后**；
2. **多源笔记的路径选择**（`n_study_hint`＝`world.study_hint` ∨ `ev.study_found`；`n_hall_hint` 同理）——`sets` 不许写有笔记的键、`Sg.notes.add` 对多源 fail-loud ⇒ 不搬 ＋ 登记（要解需要 `setPath` 声明，另票）；
3. **数值/枚举条件**：**已扩**（`#568` 机制侧 `2c0ba99` ＋ `#624` 首批真实位点）——写法 `{ gte: ['键', 值] }`／`{ oneOf: ['键', [值…]] }`；键形与字符串键同一命名空间（`star.spent`／`keeper.state` 这类**第三命名空间**不进 `--state`）。已搬 4 处（`40-ch2` 的星力软限句与封印选项、`50-ch3`「地下宴会厅」的哨子选项与守林人提醒）。**仍表达不了**三类：① widget 内分支（表的作用域是段落）；② 操作数是**计算值**（`$pc.gold gte -priceOf(…)` ×4 ⇒ 需表达式面，另票）；③ 渲染期局部量打分（`_t`）。**判据侧的代价**：含算子的行**不参与死规则包含判定**（数值语义不能套布尔包含）——门会点名列出这些行，不静默跳过。
4. **检定＋后果机制块**（`<<damage>>`）——数值玩法量不进表（与 `#512`／`#519` 同向）。

**`prereq` 未达成的项要可回看**（评审补充）：选择器不显示它们，但笔记页要区分「**没问过**（未达成）／**问过了**（已记录）」——既避免「话题凭空消失」的困惑，也满足 A5「可回看不泄底」。**不引入脚本**——条件只做「是/否」，写点仍走既有词汇宏（`<<give>>`／`<<setflag>>`／将来的 `<<note>>`）。

## 4. 迁移五步（每步可独立合入、可回滚）

| 步 | 内容 | 出口判据（门） | 回滚点 |
|---|---|---|---|
| **1** | `Game.Notes` 表 ＋ `Sg.notes.*` 封装；**grant 读现有旗标**（零行为变化） | 全链绿；新增 `--notes` 门：笔记 ↔ 旗标一一对得上、`title/src/body` 非空 | 删表即回到今天 |
| **2** | 段落内 `<<if $pc.ev.X>>` → `<<if Sg.notes.has('n_X')>>`（**纯转发**） | **可见漂移必须为 0**（不是 #264 那种「仅 N 段且已登记」的旧口径）＋ **把 `scripts/ui-migration-diff.mjs` 接入 `scripts/test-plan.mjs`**（评审补充：否则「diff=0」会退化成口头承诺） | 单文件可逆 |
| **3** | 写点搬迁：`setflag X` → `Sg.notes.add('n_X')`（旗标降为兼容字段） | `--state` 域表更新；`saveload` 往返绿（笔记随档） | 保留双写一段时间 |
| **4** | 对话内容**按表组装**（选择器＋优先级），删段落内手写分支 | `premise-source`／`choice-keys`／`rules-claims`／**`--rules`（写侧：`text` 纯渲染＋`scope` 与调用点一致）**／**`--reads`（读侧：数据表/内容不经字面状态读）** 全绿；新增「笔记→文案」覆盖门 | 按段落逐个切 |
| **5** | 清理兼容层（删旗标）＋ 手册/README 更新 | 裸旗标计数归零门 | 兼容层保留到确认 |

### 4.1 阶段 2 的前置：**先让门认新形状**（`#433` 实测，共 5 个消费点）

改条件写法会**先让若干门红**——因为「谁读了旗标 X」这件事换了写法。**必须先扩展门，再改内容**；
顺序反了会被一堆**假红**挡住（我按「先量 16/22 个键的读点都只在一章」量到了这一步）。

| 消费点 | 它怎么发现读点 | 不扩展会怎样 | 扩展后走的口径（单一权威 `scripts/audit/lib/shared.mjs`） |
|---|---|---|---|
| `--state`（⓪u 状态契约） | 逐行扫读点 | 键被判「只有写」⇒ 红 | `noteReadKeys()` |
| D2 分类器（⓪q 选择后果） | 段落内 `<<if … $pc.ev.flag>>` | 键掉进「无任何桶」⇒ 红 | `noteRefs()` ＋ `notePaths()` |
| `--echoes`（⓪b 回声 D4） | `causeReg()` 自己一套旗标匹配 | 回声锚句「条件归属不符」⇒ 红 | `noteIdsForFlag()` |
| `test/integrity.mjs` 回指门 | 硬编码 `<<if $pc.ev.<flag>>` | 「你想起…」被判「没落在条件门内」⇒ 红 | `conditionReadsFlag()` |
| `--investment` G3（跨时代合龙门） | 条件里的旗标 → 时代域 | 「全仓找不到合龙门」⇒ 红 | `noteReadFlags()`（**按出现顺序**，好让报告文本逐字不变） |

> **教训**：这个清单**只能靠跑真实门**得到——批一以为只有 2 处，跑到第 3 处才补齐 4 处；批三又冒出第 5 处（G3，因为跨时代门在三章）。
> 由 `#433` 批一（PR #497）＋ 批三（PR #500 系列）落齐。**新增任何「按旗标判定」的门时，必须把本表补一行**。
> `#435` 阶段 4 再添两条例（都是**反向**的：不再"让门认新形状"，而是"钉住旧形状的残留"）：
> `--rules` 写侧（`text` 只许纯渲染 · `scope` 与 `<<rules>>` 调用点一致）与 `--reads`（表/内容不得字面状态读，
> 知识键带 14 条待搬基线）——它们判的是**源码文本**而非旗标，故不进上表。
>
> **`#435` 前置 0（另一条横切面）**：叙述搬进表后，**"这段话属于哪个段落"由归属决定**（行 `scope` 的 `#` 前）。
> ⇒ 凡判正文的门一律取单一权威 **`storyText()`**（内容段落 ∪ 表行 `text`），不再各自 `passageSrc.get(p)`；
> 口径与已接线的面见 `docs/dev-conventions.md` §11。
> 另一个坑：这类辅助函数**返回数组还是 Set 要统一**——`noteReadFlags()` 曾返回 `Set`，被 `.concat()` 当成单个元素 ⇒ 时代判定成 `unknown` ⇒ G3 假红；改成数组后还要求**按出现顺序**，否则报告文本重排、白重签一行 golden。

**节奏建议**：阶段 1–2 是纯机械迁移（可并行、风险最低），阶段 3 起才动**存档语义**（每步都必须跑 `saveload`＋`saveui`），阶段 4 才是真正的「内容重构」——**在没有阶段 1–3 的表与门之前，不要开始阶段 4**。

### 5.3 动态键已「看得见地登记」（`#432` §A-2 的门盲区，`#436-c①` **已修**）

**修法（`#436-c①`）**：看不见的**要看得见地登记**——故事侧在 `Game.State.dynamicKeys` 声明**族**（`{prefix, via, values}`），门据此
① **展开成具体键**并入键图 ⇒ 照常受四条判定管（域归属／歧义／有写有读／命名空间）；
② **未覆盖的动态写点 ⇒ 红**（防悄悄多出一族）；③ **声明了却没有对应写点 ⇒ 红**（反沉默：防僵尸声明）。

⇒ 门现在报 **93** 个状态键（＝ 87 静态 ＋ **6 动态**，与本节 §5.1 的口径一致），`cellar_` 已落 `tower` 域。

## 6. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 组合爆炸（N 笔记枚举变体） | **first-match wins** ＋ 显式优先级；不做自动组合 |
| 顺序敏感被丢 | 笔记带 `prereq`；选择器校验「req 满足但 prereq 未达成」时**不显示** |
| 存档/跨周目语义 | 区分「本周目知道」vs「玩家永久知道」（`Sg.Codex` 已有 `clues` vs `endings/finals` 先例） |
| 门跟着形状变 | **先让门认新形状，再改内容**；每步出口判据写死在上表 |
| 作者成本 | 阶段 1–2 纯机械；阶段 4 逐段落切，可长期共存（新旧形状混用期就是迁移期） |
| 「知识 vs 世界态」误判 | 93 键**逐条**判定已落定（`#432` 复核：作者侧清单 ＋ 非作者席位 14/14 confirm ＋ 半 A 11 行）⇒ 唯一权威表见 `docs/notes-model-batches.md` §3；`--notes` 门要求每条**都**有分类与来源，误判在表上可见 |
