# 如果由 writer 开发：UI 产品层渐进实施计划

References #1939

**状态：Draft，未开始运行时代码实现。** 本文提出后续 PR 的顺序和验收，不宣称下面的文件、命令或测试已全部存在。交互与跨仓契约见[设计规格](../specs/2026-10-03-ui-product-layer.md)。本次 PR 只新增这两份 Markdown。

## 1. 我会先交付什么

我会先做一条能真实点击的纵切：两个最小故事共用同一界面，一个只有体力，一个有体力和 MP；能显示正文、选择行动、追加结果、更新资源，能在延迟输出时保持阅读位置。先证明产品层可靠且可配置，再把巴别之井搬进去。

不从“大量改 CSS”或“一次重写所有输出函数”开始，也不为第一条纵切新装运行时框架。默认旧模式仍能构建和游玩。未启用新 profile 的故事不受影响；模式在挂载前确定，不在未完成的选择中热切换。

## 2. 分阶段开发与停止点

以下每阶段是工作包，落码时继续拆成小 PR；另开实现票并 `References #1939`，不能把本设计票当成所有功能已经实现的证明。

### M0：先取证，冻结最小契约

- 在明确的候选包上真实点击，记录操作、SugarCube 段落事件、正文/选项挂载、滚动位置与 `activeElement` 的时序。
- 分别复现新场景、同场景追加、局部刷新、回看、打开/关闭存档、读档/重开。把浏览器自己的滚动、测试驱动的定位与产品代码动作分开。
- 核对 `perform`、`choice`、面板 writer、RenderPort 和 LifecyclePort 的全部接缝；固定批次就绪、取消与恢复焦点的结果形态。
- 定义 UI 的只读模型、profile 校验和稳定语义键。领域模型仍是权威源，呈现不执行场景副作用。

**退出条件：** 复现证据与契约可审阅；无法复现的反馈明确记为未确认。尚无产品行为变化，随时可以停止。

### M1：做可运行的阅读纵切

- 写 profile 校验、资源映射、批次状态机的失败用例，再实现组件与控制器。
- 两个展示夹具分别配置 HP 与 HP+MP；不新增耗蓝数学，夹具只提供明确的资源读数和合法动作。
- 建立正文、行动、关键状态、辅助区的标准骨架；桌面与手机使用同一模型。
- 一批输出只完成一次；延迟内容就绪前不能定位到尚不存在的选项。用户回看时保持锚点，资源刷新不触发滚动。
- 字体与背景先使用系统回退字体和 CSS 渐变/纹理。正文仍由 SugarCube 的段落机制管理，不复制第二份正文。

**退出条件：** 两个夹具的真实浏览器路径可通过；同一组件在 MP 缺席和 MP=0 两种情况下有正确且不同的 DOM。新 UI 仅在夹具启用，巴别之井仍走旧模式。

### M2：收口公共输出与局部刷新

- 保持 `perform` 的链式语义、`choice` 正常选择结果和原有通知过滤行为；旧调用通过兼容桥进入同一个 writer。
- 先迁宿主落地实现，再让公共入口单向委托；不能形成 `perform → RenderPort → 同一 perform` 递归，也不能新旧出口各写一次。
- 接入会话有效性；导航、读档和重开会结束旧等待并禁止旧批次落屏。场景接缝必须消费取消，不能留下未处理 rejection。
- 将现有面板映射到受控区域，保留刷新计数、展开状态及语义焦点；不反复全量替换整个 UI 根节点。
- 核对重绘不重复领取奖励、不改变随机流、不再次运行 `onEnter`。

**退出条件：** 旧模式回归不退步，新模式每次输出/通知恰一次，取消等待确实结束。接缝不安全时停在夹具，不切换故事。

### M3：系统工具栏与存档、道具接缝

- 增加常驻快存、存档、设置入口；快存不消费正在等待的剧情选择，反馈不夺焦点。
- 对齐现有存档修复的角色声明与限制；所有支持的保存入口展示同一策略，执行层再次校验。
- 复用 [sgstory#1938](https://github.com/sagitrs/sgstory/issues/1938) / [sagitrs/sgstory-books#210](https://github.com/sagitrs/sgstory-books/issues/210)，不另写固定槽号或接管其排期。巴别之井桥接读取故事已有槽位常量。
- 道具先有可读详情、操作、预计效果与成本，再允许低风险快捷操作；战斗入口仍服从领域结算。
- 阅读偏好单独存储，规则设置若已有注册表则复用，二者不混淆。

**退出条件：** 从真正的侧栏/工具栏进入存档页面，保留槽保护有效，普通槽仍能写；拒绝操作零状态变更；快存与读档全链路可复核。

### M4：巴别之井主题与故事接入

- books 新增 profile 与只读模型桥接；只消费引擎公开界面与事实读数。
- 用同一套变量落实井壁、微光、温泉、营地主题；正文与操作有不同字体层级，字号可调。
- 渐进迁移探索、战斗、失败、存档四个画面；每个画面确认只有一个 writer/一套订阅。旧 footer 在旧模式继续有效。
- 若确需字体/图片资源包，单独做来源授权、体积、离线形态和失败 fallback；扩展构建清单另开小 PR。
- 引擎能力先落成一个可固定的 commit，再在 books 更新 pin 并以精确 pin 重建，不用“本机当前 main”替代发布输入。

**退出条件：** 桌面、窄屏、放大文字和键盘路径通过；资源加载失败仍可游玩；公开模型读数与最终结算一致。此阶段仍不代替 sagitrs/sgstory-books#197 的全维发布验收。

## 4. 测试设计：未来实施的验收矩阵

以下全部为**待实现/待验证**。单元桩和 jsdom 可验证结构与事件，不能证明浏览器的真实布局、滚动和中文字形。

| 编号 | 调用面与正例 | 负例/对照与失败条件 |
|---|---|---|
| UI-01 就绪 | 真实点击触发受控延迟输出；正文和当前行动挂载后才做本批定位 | 控制准备 Promise 未完成时观察，不得抢先定位；只读 ready 标记不足，还要核内容与事件顺序 |
| UI-02 尊重阅读 | 玩家滚到旧段，点击追加动作或更新状态；旧段锚点保持 | 回到末尾再追加才跟随；非末尾被强拉、仅 HP 刷新导致视口跳变即失败 |
| UI-03 取消隔离 | 真实点击离开/读档/重开后放行旧批次；旧等待结束且旧内容未出现 | 两个独立上下文相同组件 id 也不串；撤取消守卫须在指定断言失败 |
| UI-04 HUD 定制 | HP-only 无 MP 节点、无空布局、无 MP 读数调用；HP+MP 在零值时显示 0 | 改为硬编码蓝条或把零误判缺席须失败；非法描述不可静默变成 0 |
| UI-05 状态与焦点 | 动作提交后本批体力、背包和结果一致；展开抽屉/通知后局部刷新 | 焦点/展开丢失、兄弟面板误刷、重绘造成再次领奖或推进随机源即失败 |
| UI-06 保存安全 | 真点击常驻与内置保存入口；拒绝原因一致，保留槽受保护，手动槽可写 | 改故事保留槽位置后仍按声明保护；若允许覆盖，取消后存档不变；不能整面禁用冒充通过 |
| UI-07 视觉与降级 | 320/390px 窄屏和桌面，文字放大 200%，键盘完成主路径；背景/字体失败仍能操作 | 横向溢出、底栏遮正文、焦点不可见、缺资源阻塞正文即失败；真机与读屏另记覆盖情况 |
| UI-08 兼容与唯一出口 | 新旧模式各走选择、通知、重绘与存读档；输出与通知只发生一次 | collector 也只能收到一次；无 profile 不改变旧行为；重挂载后监听器不累加 |

每个实施 PR 附：被测 commit、故事 commit、引擎 pin、构建参数、浏览器版本、真实操作序列和证据文件。缺浏览器或关键用例未触发就明确失败/未覆盖，不把零用例写成通过。

核心守卫至少做一次有针对性的失效实验：撤掉取消检查、强制所有追加滚到底、固定 MP 节点、硬编码保留槽。先重建，确认改动进入产物，再证明上述相应断言确实变红。它们不是本 Draft 已完成的实验。

## 5. 验证入口与 CI 接线

现有入口以 [tests/README.md](../../../tests/README.md) 和 [test workflow](../../../.github/workflows/test.yml) 为准。产品实施后从对应引擎检出运行：

```bash
python3 build.py
node tests/unit/headless.mjs
node tests/e2e/old-house/run-baseline.mjs
node stories/babel/verify.mjs
```

这是现有回归入口，不足以验收新阅读行为。M1 新增后的**拟议入口**为：

```bash
python3 build.py tests/e2e/ui-profiles/hp-only
python3 build.py tests/e2e/ui-profiles/hp-mp
node tests/e2e/ui-profiles/run-browser.mjs
```

新增浏览器入口需明确 Chromium 可执行文件来源，使用隔离 profile，输出逐项结果、失败证据和非零退出码；等待有超时，临时文件落用户自己的 `~/tmp`，完成后关闭本次浏览器。不以固定 sleep 或人工修改游戏状态实现通过。

新增单元用例要确认进入构建 manifest 且执行数非零。真实浏览器入口由对应实现 PR 接到可达的 CI 调用面；如修改 workflow/测试基础设施，先取得 Tester 评审。不能提交一个无人调用的脚本后宣称 CI 已覆盖。当前 Draft 不新增测试或改 CI。

## 6. 回滚与完成判定

- 每阶段保持 legacy 路径；新 profile 只在指定夹具或候选故事启用。停用后用同一份有效存档重建旧界面，不迁移规则事实来迎合 UI。
- UI 变更不增加游戏存档字段；偏好存储独立且版本化，旧模式忽略不认识的 UI 偏好。
- books 候选包记录精确引擎 pin 与故事 commit。若需回滚，两者作为一对回到已验证组合，不单独回退其中一个。
- 尚未通过取消、保存安全或兼容检查时，不把新 UI 设为默认。美术完成不能抵消交互或状态错误。
- 设计合入只代表方向获采纳；功能完成须有实施 PR 和上述真实验收。0.0.2 是否发布仍由 [sagitrs/sgstory-books#197](https://github.com/sagitrs/sgstory-books/issues/197) 按原范围判断。

**当前已做：** 静态读源、相关票对账、两份方案文档。**当前未做：** 新 UI 原型、运行时代码、上述浏览器验收、实现子票、合入和发布。
