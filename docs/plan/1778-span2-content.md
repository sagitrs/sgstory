## 六、★门侧缺口（本笔发现，**修门归测试域**）

**3E 怪物的 HP/AC **不可判** —— 门的 `SRC_VAL_RES` 只认 5E 形**：
```
const SRC_VAL_RES = { HP: /\*\*HP\*\*\s+(\d+)/, AC: /\*\*AC\*\*\s+(\d+)/ };
```
即只匹配 5E 源的 `**HP** 11`／`**AC** 16`；而 **3E 源写作 `Hit Dice: 1d8+2 (6 hp)`／`Armor Class: 15`**
⇒ **抽不出** ⇒ 3E 怪物的 HP/AC **从不进 A 组比对**。

**本席实测证据**（本笔的突变探针）：
| 刀 | 突变 | 期望 | 实得 |
|---|---|---|---|
| M1（声称面） | 文件头 `Armor Class **16**` → `**17**`（代码不动） | 红 | **绿**（门不解析该声称） |
| M1b（用例名↔断言） | 用例名 `AC 16` → `17`，断言不动 | 红 | **红** ✓（第①级自洽支有效） |
| M1c（名/断言/代码**三处一致地错**） | 全改 17 | 红（A 组对源） | **绿**（**源侧抽不出 AC** ⇒ 无从比对） |
| M2（声明面） | 代码 `ac: 16` → `17`（声明面） | 红（单测守） | **红** ✓（单测 `AC 16：17 !== 16`） |

⇒ **净缺口**：3E 怪物的 **AC／HP** 只有「单测守声明面」一层；**门不守**（因源格式不匹配）。
本笔的六维（Str…Cha）**确实**被 A 组对源核（`sourceFormats3e 219 次`）⇒ 缺口**仅限 AC/HP 两个键**。
**建议**（测试域）：`SRC_VAL_RES` 增 3E 形两条（`/\|\s*Hit Dice:\s*\S+\s*\((\d+) hp\)/` 与
`/\|\s*Armor Class:\s*(\d+)/`）——**注意**：3E 的 `Armor Class:` 行还带 `touch`/`flat-footed` 数值，
正则须锚行首（本席实测源行形如 `  Armor Class:           16 (+1 size, +5 natural), touch 11, flat-footed 16`）。
