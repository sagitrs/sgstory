# 七名河教程所需的通用引擎能力设计

状态：**待评审设计，不是已实现接口或存档格式。** 本次只提交文档。需求：[sgstory #2021](https://github.com/sagitrs/sgstory/issues/2021)；故事需求：[sgstory-books #393](https://github.com/sagitrs/sgstory-books/issues/393)。

故事的完整事件、返程政策和界面设计见[七名河教程](https://github.com/sagitrs/sgstory-books/blob/0a2a0701/docs/plans/babel/optional/tutorial-seven-names/README.md)。该链接指向配对设计的合入提交 0a2a0701。本篇只承载可复用能力，不把七名河的世界编号、敌人、DC、脆弱范围或城镇政策写成引擎默认值。

## 1. 目标与非目标

支持故事交付最小闭环：正常进入首次教程，事件及真实战斗结算，查看只读地图，回城执行物品状态变化，存读后事实一致。引擎应提供可信的实例、转移、存档和提交基础；剧情及规则政策归故事。

不建立第二套战斗、背包、地图或存档系统，不新增战中存档；不实现20世界、随机地图生成、英雄任务、时代Boss。也不借此更换既有宿主架构或扩大此前地图交互需求。

| 责任 | 引擎 | 故事 |
|---|---|---|
| 物品 | 保存实例状态、判断堆叠兼容、转移及效果重算 | 决定哪些物品适用脆弱、稳定来源与展示词 |
| 返程 | 支持提交前校验、状态变更一致性和重复提交保护 | 决定机会范围、拒绝条件、回城落点及消费时点 |
| 遭遇 | 提供真实检定、战斗结果和物品交付基础 | 固定节点、候选数值、敌人、奖励与通过条件 |
| 保存 | 沿用序列化和域登记边界，兼容旧档 | 保存路线、节点结果、奖励、机会和完成事实 |
| 地图 | 复用已有场景／地图及资产构建能力 | 从权威进度生成只读图和等价文字，不用图驱动移动 |

## 2. 可复核基线

2026-10-06撰写本篇时，引擎远端main为`bad1d02a401732f0f11e9ea02ea7df2714288313`；故事main为`136651ccd3ef41460fde048092e08cd13496fa6e`，其[engine-ref](https://github.com/sagitrs/sgstory-books/blob/136651ccd3ef41460fde048092e08cd13496fa6e/.github/engine-ref.json)仍钉`c3c6366a5b6c867ef47fa8db6412beeddc418552`。故事不能默认拥有较新引擎main的能力。

以下是源码观察，不是运行验收：

- 主线[Item.toJSON／reviveItem](https://github.com/sagitrs/sgstory/blob/bad1d02a401732f0f11e9ea02ea7df2714288313/src/core/10-item.js)基础快照保留id、entityId、charges、equipped；还原具名字段，不是任意属性复制。故事当前pin的同名基础路径也没有通用脆弱载荷。
- [RPG.deposit](https://github.com/sagitrs/sgstory/blob/bad1d02a401732f0f11e9ea02ea7df2714288313/src/core/30-inventory.js)对可堆叠物按同id寻找合并目标。同款但生命周期状态不同的物品不能直接套此判据。
- 已有[交换契约](../arch/inventory-exchange.md)与[交换实现](../../src/core/32-exchange.js)强调暂存校验和实体身份；新增状态必须沿用它，不能靠故事到处包装入袋函数。
- 已有[存档域边界](../../src/core/80-save.js)，包括`RPG.save.declareDomain`；应先评估其可用性，不批准第二套保存格式。
- [场景](../../src/core/50-scene.js)、[地图](../../src/core/60-map.js)和[效果](../../src/core/17-effect.js)可复用。当前效果定义校验只接受`onTurnStart`／`onTurnEnd`，不可假定任意自造钩子已有。

故事engine-ref仍记录真实L2战中`FULL_PANEL_REDRAW_INVARIANTS`红账；图片故障测试绿不消解它。后续实现开工和评审须重新核对对应问题、受测两仓SHA和CI，本设计或旧L10结果不能放行它。

## 3. 实例状态与堆叠契约

**下述是能力要求，不冻结字段名、API签名或数据结构。** 实现前应在合法实现票中确认最小扩展，不新增无法复用的教程专用引擎字段。

每个实体或堆叠批次需要可序列化的状态载荷，能区分尚未脆弱、已脆弱，以及经故事规则认可的稳定来源。定义id、实体身份、状态和消耗次数必须分开；“稀有”“城镇来源”不能在引擎里自动变成稳定。

1. 创建、快照、还原、复制及移动均保留合法状态；不能只改活对象而读档丢失。未知或坏状态需按明确兼容策略拒绝／诊断，不能悄悄转换成更有利状态。
2. 堆叠兼容不仅比较id，还比较所有影响结算的状态。状态不同不得合并；相同状态是否合并及实体身份如何处理，须沿用现有批次约定并给出测试。
3. 非堆叠物逐件保留身份；批次拆分、部分转移和合并须明确身份规则，不把一个实体号复制给多件独立装备。
4. 奖励数量与charges分账。领取两份物品不等于把charges硬设为2；按真实注册定义和现有投递口换算。
5. 售卖、交易、寄存、取回、战利品及随身容器遍历必须同一套状态规则。留在城镇且未同行的物品是否参与跨界结算，由故事给出选择集合。
6. 移除装备须清理引用并重算能力与面板，不能留下不存在物品的加值。背包容量或交换失败时原袋、状态与实体身份不变。

存档域名称、物品状态的版本与默认值尚未冻结。旧档缺字段不等于“已稳定”；建议按此前无脆弱状态的旧物处理，何时首次附加由故事政策决定，不能载入即批量损毁。

## 4. 返程的一致提交

故事传入合法目标、当前探索身份、可消费的机会、适用携带物、稳定判定和本次进度变更。引擎提供或复用一个可靠提交边界；不是“物品删完后再尝试移动”的多处散装副作用。

建议流程：先校验当前状态及目标可达性；从提交前快照产生变更计划；再次确认快照未改变；统一提交物品变化、位置、效果、机会与进度；提交成功后再发布消息及刷新面板。预览与提交共用规则，预览取消不写状态。

| 情况 | 必须成立的结果 |
|---|---|
| 合法提交 | 全部变更对应同一提交前状态，结果可存读 |
| 目标不可达、战斗／死亡拒绝、机会耗尽 | 不移动、不扣机会、不改物品或完成状态 |
| 同一已提交请求重复调用 | 不重复损毁、附加状态、发奖或消费；返回已提交事实 |
| 校验后携带物／当前位置改变 | 拒绝旧预览或重算并重新确认，不套用陈旧列表 |
| 提交过程中失败 | 不留下半回城、半损毁的权威状态；明确恢复／失败策略 |
| 成功后界面绘制失败 | 已提交事实仍可读取，重绘不再执行领域结算 |

同一计划中先处理**提交前已脆弱且无豁免**的物品，再给原未脆弱的适用物附加状态；刚附加的物品不得在同一提交里消失。稳定物保持不变。引擎不根据提示语推断任何角色或同伴应消失。

重复提交保护的标识与保存位置、暂存深度、提交失败恢复方式仍需实现验证；本篇不声称已有数据库事务或通用撤销能力。应优先复用现有暂存校验思想，找出真实宿主同步点，而不是先许诺一个不存在的万能事务API。

## 5. 固定节点结果、保存与只读地图

故事需要区分战斗胜利、脱离成功、奖励完成、拒绝奖励、死亡与提前回城，不能把一切通过都记为整层战斗胜利。引擎真实战斗的胜利回调应能由故事绑定固定交付，避免同时触发旧随机掉落；如果现有扩展点足够，仅用既有接口，不必新增通用状态机。

奖励交付与“已经领取”标记须一致成立；投递失败不得先标领取，重复回调不得再投递。战前检定结果保存为事实，地图开关、刷新和读档不再次掷骰。属性修正、DC与修正值由故事配置，不能以教程需要为由暗改自然20或封顶结果。

存档中只保存可序列化的权威事实，不存SVG、DOM、模板或回调。尊重现有战中禁存；故事负责宿主真实`Save.slots`往返，引擎负责快照与还原契约，不用合成通知冒充宿主保存成功。

地图以已保存的位置、路线和节点结果为输入。显示可以重算，打开／关闭不改变权威进度、推进时间、消费资源或启动战斗。优先复用当前SVG单文件构建口；动态合成能力若不足再提最小扩展，不能把两张审稿快照当运行状态。坏图必须保留可用文字和操作。

## 6. 实现验收矩阵

这是后续实现的最低计划，**本PR未执行这些新功能验收**。

| 验收面 | 正向及反向用例 |
|---|---|
| 快照／还原 | 单件、带charges、装备及容器状态往返；旧档无字段、未知值、实体号不碰撞 |
| 堆叠／转移 | 同id稳定与脆弱分袋；部分转移、寄存取回、售卖；失败原袋原字节不变 |
| 跨界结算 | 原脆弱消失、新脆弱保留、稳定不变；装备移除后效果及引用同步 |
| 提交边界 | 合法／非法／耗尽、预览取消、旧预览、重复回调、故障注入及重绘重试 |
| 固定交付 | 成功一次、容量不足未标领取、双击不重复；脱离成功不走胜利／随机掉落 |
| 保存及地图 | 新事实往返、不重掷；地图反复开关无领域副作用，坏图文字仍可用 |
| 回归 | 既有背包、交换、寄存、存档、战斗；故事再覆盖L1–9、L10城内和L19 |

判据还须有能发现状态丢失、混栈和重复提交的负控，最后恢复并重新通过。新增测试工具应进既有`tests/`并按仓规登记，不随设计放进`docs/plans`。

## 7. 待定项与两仓顺序

开工前明确：状态载荷与堆叠兼容键；批次身份规则；旧档默认值；容器递归范围；可靠提交的宿主边界与恢复；现有战斗回调是否足够；动态SVG是否需引擎扩展。物品适用范围、稳定门槛、机会按层还是探索实例及旧卷轴政策由故事票裁定，不由引擎越权决定。

建议先用隔离分支验证是否必须扩展引擎。若必须，另开引擎实现PR，经当前头正式评审、真实CI及合入后，故事再更新明确的engine pin、重建并重新回归评审。若现有能力足够，说明验证依据，不为拆仓强行造接口。

本轮两份设计PR互相引用，**不要求先合入任一文档来运行另一份文档**。文档合入不等于运行依赖已经完成，也不授权代码实施、改存档或发布。
