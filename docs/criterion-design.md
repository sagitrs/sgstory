# 判据设计法则

> **读到即用**：写新判据前，先读**第三节那七条** ＋ **面③那张口径对照表**（那张表回答了最常见的一个误解："同一个文件里几种相反口径一定是有人写错了" —— 不是，**口径服从观测对象**）。
>
> 这一页不是"风格建议" —— 它记的是**今年真实翻过的车**。每条都有实例、都在代码注释里指得出。
> 读它的收益：**写新判据时不重犯**；看别人的判据时**知道该问什么**。

## 一、总法则

> **判据说的、判据看的、判据喂的，必须同指一件事。**

它有三个面，各有真实事故：

### 面① 读入参 vs 读环境

| 实例 | 病灶 |
|---|---|
| `readKey` 丢 `pc` | 从**环境**取当前角色，而不是用**调用方入参** → 换档/合成角色时判据判的是别人 |
| 写侧 `applyYields`/`applyGrants`/`applySets` 无视入参 | 同族：效果落到**当前档**而不是**被驱动的档** |
| `Game.Social?.asks` 环境回落 | 引擎在**契约不可得**时回落到环境 → "两宿主同源"这条主张被悄悄破坏 |

**问法**：这个判据/函数的输入，是**参数**还是**它自己摸到的全局**？两者不一致时，它相信谁？

### 面② 声称 vs 覆盖

| 实例 | 病灶 |
|---|---|
| `#806` 声称"静态＋动态 import 都挡"，实只挡静态 | 声称 > 覆盖 → **下一个人按声称去信它** |
| K6 ② 声称"壳不许写故事文件"，只扫两个文件 | 覆盖小于声称 |
| K6 ③ 声称"浏览器安全"，只挡 Node 侧 | 同一件事的另一半没人守 |
| L1 旧口径只扫 `cli＋host` | 同上：**覆盖小于声称** → 改成扫全部 `editor/**` 后**不再依赖路径形状** |

**问法**：判据的名字/报文里承诺了几件事？代码真的查了几件？**声称与代码不符，比漏一个形更坏** —— 漏形是"没守到"，声称错是"以为守到了"。

### 面③ 观测对象 vs 遮蔽口径

**这是最容易撞的一面** —— 因为**同一个文件里可以有多种相反设置，而且都对**：

| 判据 | 观测对象 | 遮蔽口径 | 为什么 |
|---|---|---|---|
| **L1** 原语写只许在 `lib/host/**` | **代码里的调用** | **遮字符串** | 字符串里写 `writeFileSync(…)` 只是**片段**（本门自证用例正是如此）→ 不遮会**自咬** |
| **L1′** 删除原语不许落 `stories/**` | **调用参数里的字符串** | **不遮** ＋ 查"调用位置在引号外" | 参数**就是**字符串 → 遮了就把**观测对象自己**遮掉；而"字符串里的提及"用 `outsideQuotes` 排除 |
| **③a** 内核不许 import 宿主模块 | **说明符**（`'node:fs'`） | **不遮** | 说明符住在字符串里 → 遮了什么都看不见 |
| **③b** 内核不许碰宿主全局 | **标识符用法** | **遮字符串** ＋ 只看用法（`名(`／`名.`） | 提及≠用法：core 会**合法地**在字符串与正则里提 `window.` |

**判法**：先写清"**这个判据要看的对象是什么**"，再选遮蔽口径 —— **口径服从观测对象**，不是"统一口径"。

## 二、由总法则推出的操作纪律

1. **判据的边界由理由定，不由"看起来像"定。**
   > **判据只判它该判的** —— 范围**窄**不是缺陷，**宽到理由之外才是**。
   - 例：L1 的理由是"故事文件的**写**只有一条路" → 把**删除**也做成路径无关 会连 `rmSync(tmpdir())`／`rmSync('build/generated')` 一起咬（门会被关掉）→ 删除另立 **L1′**，只判落到 `stories/**` 的。
2. **不假装覆盖：边界要写出来，并写理由。**
   - 例：L1′ 明记"**运行期拼路径的删除不在覆盖内**"（要收它得做数据流分析，成本高收益低）；K6 ③b 明记"引号未闭合（非法 JS）那形会漏"。
   - 边界**写出来**＝下一个人知道该不该信它；**不写**＝把"没守"伪装成"守住了"。
3. **新增/改动判据时，必须有一条只对"分支"敏感的用例。**
   - 因为：**多分支写出同一结果时，结果类判据全都沉默**。
   - 活标本：`--out=stories/mist-forest`（相对路径）没走进"包内"分支 → 对拍不报 逐字节不报 只有**分支断言**能抓。
4. **自证要双向。**必红（真用法 → 报）＋ **必不红**（字符串里提及／属性访问／通用全局／边界形 → 不报）。
   - 只有"必红"一半的自证 → 下一次扩表会**误报一片** → 门被关掉。
5. **登记物/签名只描述既成状态。**
   - 顺序恒为：**状态先变 → 再剪登记/白名单 → 再重签**；重启（rebase）时**重签提交丢弃**、落地后重签一次。
   - 理由：登记物是**记录**，不是**驱动** —— 让它先动＝让判据去迎合它。
6. **先落"不改变行为的加法"。**
   - 纯新增 → 再落会生效的块 → 最后删旧路径；动作按**行为可见性**排序（这样每步都能单独验证"没变行为"）。
7. **自证必须能红，且计入退出码。**
   - 自证红而主跑绿 → 门是**装饰**。
   -注意：这条最容易被当成形式 → **配上反例与读数**（当场验过，非声称）：
     ```
     # 把任意一条自证的期望改假（例：`.length === 1` ⇒ `.length === 2`）
     node editor/k6.mjs --selftest ; echo $?   # ⇒ 1  ← 非零 ✓（自证真的计入退出码）
     # 恢复后
     node editor/k6.mjs --selftest ; echo $?   # ⇒ 0  ← 36 例全过 ✓
     ```
   - **任何人都能在 10 秒内复核** —— 这条纪律的价值全在"能被复核"：改不掉红、就把门关掉。

8. **测量/比较之前，先对齐底材。**（写成可取用的形态：**症状 → 前置动作 → 器材纪律**）

**症状** —— 出现任一条 → 这次读数**不可能**成立，别急着信它：
- 同一文件两次读出**不同行数**（实例：107 行 vs 235 行）；
- 某个字段**整体为 `undefined`**（实例：取到的 `line` 全 `undefined` → 现象像是"改了看不出效果" → 白绕两轮）；
- **两个分支写出同一份字节，却不知道自己走了哪一支**（→ 行为对、分支错；对拍／逐字节／全套测试**全不报**）。

**前置动作**（三条，都可机械执行）：
1. **`git fetch` 后记 head SHA，并把 SHA 写进读数**（读数带 SHA → 虚警**当场可比** → 事后不必重新取证）。**最便宜、收益最大**。
2. **被测对象一律"新建 worktree 钉 SHA"**，不复用长期工作树（→ **就地改／就地读是唯一漏点**）。
3. **比较量先归一化**：路径先 `resolve`；分支先**断言分支**。
   -注意：顺带一条**本仓事实**：默认分支是 **`main`**，**不是 `master`** —— 用错名字会得到"分支不存在"这类**看起来是别的问题**。

**引用纪律（读数有时效）**：**引用任何读数之前，重读"状态"那一位** —— `gh pr view --json state` / `git rev-parse origin/main`。
> 实例（当场踩过）：一条"CI 全绿 · head `…`"**取时是对的**（当时确实全绿未合），**引时已陈旧**（合入发生在取数之后）→ 底材一动，读数就过期。
> → 所以"读数带 SHA"只解决**归属**，"引用前重读状态"才解决**时效**，两件都要。

**器材纪律**（把上面变成"**每次都能做、做了就有用**"的动作，不是"要小心"这种口号）：
> **凡就地读文件 → 先核 `git log -1` 与目标 SHA 一致**。

**同一骨架的三段**（与第 5、6 条合起来才闭环）：**动笔前对齐底材 → 落笔后回读 → 读之前再对齐**。

---

9. **读数须能证伪自己。**
   > **这条读数错了，哪个读数会先变红？答不出来 → 它不是读数，是声称。**

   **推论（让它可以执行）**：答案必须是**一个你能跑的读数**，且它应当**比被质疑的读数更早、更便宜地红** —— 否则答了也不管用。
   操作上两步：**(i) 答出是哪个读数 → (ii) 确认它存在且能跑**（**不存在就先补上** —— 这一步才是重点）。

   **为什么不是鸡汤**（四个实例全是实测）：
   | 场景 | 答出的"先红的那条" | 结果 |
   |---|---|---|
   | 注入类探针 | 需答"注入是否生效" → 发现**该读数当时不存在** | 补「打印 pattern 是否命中 ＋ grep 注入标记」才敢下结论 |
   | 归一化脚本坏过 | **已知红样本应当红**（正向对照） | 可跑 → 答案成立 |
   | `k4`／`lint-story` 的守卫 | **删掉守卫后，那条反例应当红** | 可跑 → 答案成立 |
   | **反例（声称档）** | 旧台账那格 `自证 ✅` 是**错误报文里的词**命中的 → 问"它错了哪个会先红" → **答不出** | 当场显形（随后补了真 3 例自证） |

   **它的用处在于"更早"**：不必跑、不必开工具，**自问一遍就能用**。


### 8b. **器具也会错 → "断言"是装备，"小心"不是**

> 一句话命题：**被测量的东西会错，测量它的东西也会错** —— 所以护法不能是"我更小心"，只能是**断言**。

三类（**每类都真的发生过**，各附一条可复现的形与**拦它的断言**）：

| 类别 | 实例 | 拦它的断言 |
|---|---|---|
| **(i) 动作静默没生效** | `git fetch <remote> <ref>:<local>` 对**已存在**的本地 ref **不报错也不更新**（于是拿旧 head 当新 head 用）；文本替换的目标串不符 → **空操作**却照打印"已落"；注入落进了**形参默认值** → 语法错，而 `grep` 命中的是**报错回显的源码行** | **回读你刚改的东西**：断言"注入真在文件里" ／`git show --stat HEAD` 看改动**真进了 commit** ／`git status --short` 看有无**未落**改动 |
| **(ii) 取样错位** | 重定向写到 `~/tmp/x` 却去读 `/tmp/x` → 读到**别的命令的陈旧文件**；`awk` 行窗口取到**错位的窗口** → 报出**假分叉**；`grep` 命中的是**报错回显**而不是文件内容 | **断言对象同一性**：目标 SHA == 权威 SHA ／从**你写的那条路径**读回 ／**两侧皆空守卫**（两侧都空 → 判"读数作废" 不是"相同"） |
| **(iii) 对齐/单位错** | `${H:0:8}`（8 位）与期望的 7 位比；把 `sha256sum`（**内容哈希**）叫作 "blob"（**git 对象 id**）；`prune` 排在 `rm` **之前**；器具自己的搜索串没做同样的空白归一 → `AssertionError` | **比之前先断言"同一把尺"**：类型/长度/口径先断言（最好与**权威来源**全等比对，而不是与自己算的截断值比） |

**三条护法（各自一行）**：
1. **(i) → 回读效果**（改完/写完，读回来确认；别信脚本的成功语）。
2. **(ii) → 断言对象同一性**（先证"我读的就是我写的/我读的就是那个 SHA"）。
3. **(iii) → 比前先对齐单位**（长度、类型、哈希口径**先对齐**再比）。

**为什么单列这一段**（而不是并入第 8 条）：第 8 条管"**底材**陈旧 → 读数假"；这一段管"**器具自身**出错 → 读数假"。两者症状同族（读数看着像结论），但**治理不同**：一条是"动笔前对齐底材"，一条是"给器具也配断言"。

## 二之二、判定线：**该不该上门，看假阳性率，不看重要性**

> **能不能写成一行、且不冤杀** —— 能 → 写成判据；不能 → 留**评审**。

理由：**门被关掉比没有门更糟**。假阳性一多，人就不信门 → 那道门连同它看守的东西一起失效。
→ 所以"这件事很重要"**不构成**上门的理由；"这件事**几乎没有解释余地**"才是。

**两个对照实例**（同一天出炉）：

| 候选判据 | 假阳性余地 | 裁定 |
|---|---|---|
|「`import editor/**` → **rc=0 ＋ 0 字节输出**」 | **零** —— import 期打印/退出**就是它要禁的东西本身** | **上门**（`test/` 里一个测例覆盖全部模块） |
|「同一能力只许一处实现」（按函数体形状判） | ≈**50%** —— 把"只在字面量上不同的兄弟函数"、把两条控制流同形但查不同表的判据 都判成重复 | **留评审**（负结果 ＋ 真发现一起记台账） |

**配套顺序纪律**（去重类改动的正确次序）：
> **发现重复 → 先对打语料证"同"，再删一份**。
> 反序的话，删掉的那份可能带着**未发现的差异** → 先量（差异语料 ＋ 逐字节对拍）再删。
> 例：量之前票面只能写"两份实现存在"；量了语义等价（如 14 例 0 分歧，或**改前/改后输出逐字节相同**）才敢写"纯重复、无行为风险"。

## 三、怎么用这一页

- 写**新判据**前：把"说的/看的/喂的"三句话各写一行，对不上就先改设计。
- 看**别人的判据**时问三问：①输入是参数还是环境 ②声称与覆盖是否一致 ③观测对象与遮蔽口径是否匹配。
- 撞到新的一面：**给它命名、写实例、留纸** —— 没名字的教训会被重犯。

**交叉引用**：`editor/k6.mjs`（L1／L1′／③b 的实现与注释即上面各条的实例）· `docs/engine-story-boundary.md`（引擎/故事边界）· `docs/superpowers/specs/editor-pivot.md`（编辑器转向）· `#794`（内核抽取／防双内核）。

## 四、术语表（门／判据／流程的**共同语言**）

**为什么有这一节**：这些词以前**散落**在 17／14／42 份文档里、无一处统一定义 ⇒ 代价今天就付过：
「自证 ✅」被读成"**断言真会红**" ✗（其实只量"信号出现在代码/字符串面"）／「未接线」与「临时下架」混说 ／「段/门/牙」混用 ✗。
**本节不是第二权威**：每条都**指回**权威处（校验函数／`REASONS`／门／文件）；表**只做索引与边界** ✓。

> **与台账图例的关系**：「自证」那一列的**权威说明**在生成器里（`scripts/report-gate-ledger.mjs` 的 `LEGEND`，随台账一起生成 ⇒ ✗ 手改不会生效）；本节**指回去**，✗ 不复制它的正文。

### 怎么读（每条四问）
```
① 是什么　② 怎么判（可机检的锚／可复跑命令）　③ **不测什么**（边界：它答不了哪个问题）　④ 权威在哪（读哪一处／跑哪一条）
```

### 4.1 结构层
| 术语 | ① 是什么 | ② 怎么判 | ③ **不测什么** | ④ 权威在哪 |
|---|---|---|---|---|
| **段（segment）** | 跑器里的一条执行单元 | `scripts/test-plan.mjs` 的 `SEGMENTS` 数组 | ✗ 不管"它有没有价值" | `test-plan.mjs`（`SEGMENTS`） |
| **门（gate）** | 一条**自己判红/绿**的检查（通常 ＝ 1～2 段：真跑段 ＋ 自证段） | 台账 `docs/gate-ledger.md` 的一行 | ✗ 不保证"它咬得住"（那要看**探针**） | `docs/gate-ledger.md`（生成物，✗ 不手改） |
| **牙（有刀的门）** | 有**最小变异**能让它**必红**的门 | 该门在 `scripts/probes.mjs` 里有条目 | ✗ 不代表"永不误报"（刀证明的是"能红"） | `scripts/probes.mjs`（每条含 `mutation`＋`expect`） |
| **面（scope）** | 判据判**哪些对象** | 判据里的枚举口径（如"有 `data/passages.json` 的故事"） | ✗ 不判"面外的对象是否正确"（**面外 ≠ 欠账**） | 各门自己的枚举处（如 `prose-vocabulary.mjs` 的改制面） |
| **档位（tier）** | 段在哪一档跑：`fast`（PR）／`full` | `tierOf(seg)`；`full` 段**必须**在 `FULL_REASONS` 里有理由 | ✗ 不代表"降频＝已处置"（`full` 可以只是**暂存**） | `test-plan.mjs`（`TIERS`／`FULL_REASONS`） |

### 4.2 判据质量层（**最容易误读的三个词**）
| 术语 | ① 是什么 | ② 怎么判 | ③ **不测什么** | ④ 权威在哪 |
|---|---|---|---|---|
| **自证（`--selftest`）** | "**信号出现在代码/字符串面**" | `hasSelfProof` 扫描（`t('🔴 反例：…')` 也算） | ★ **✗ 不测"断言真会红"** —— 它**不是**"判据有效"的证明 | `report-gate-ledger.mjs` 的 `LEGEND`（**权威**）＋各件 `--selftest` |
| **探针（刀）** | 一次**最小变异**，要求该门**必红并点名** | `node scripts/probe-gates.mjs --probe=fast` | ✗ 不做"空对象双绿"那一向（见下条） | `scripts/probes.mjs`＋`--probe=fast` |
| **两把尺** | 尺一＝**造刀**（能红吗）／尺二＝**弄空对象**（红的时候在判什么） | 尺一：探针；尺二：弄坏/弄空一个输入件跑一次，看**互否的格子是否同时为真** | ✗ 两者**不互相替代**（尺一漏"红得与对象无关"，尺二漏"从不红"） | 本节 ＋ `criterion-design.md` 各节 |
| **接线** | 该段是否进 `npm test` | 台账"接线"列 | ★ **✗ 不等于"门成立"**（接线只说明"它在跑"）；也 ✗ 不表示"已装进 CI 的某个档" | 台账 + `test-plan.mjs` |

### 4.3 状态层（表格里的三种"没有"）

|---|---|---|---|
| **三落法（活/史料/归档）** | 不是所有旧件都该"搬进 archive" | 判据＝① **引用面**（有几处引它）② **是否半活**（有的节仍在使用） | 无门（人读面）；落法三选一：**移入 `docs/archive/`** ／ **原地加历史标注** ／ **删除** ✓（`#1331` 实测：9 处引用＋`§2.1` 仍在用 ⇒ 选"原地加标注" ✓） |
| **删改同笔清引用** | 否则留**悬空引用**（下一轮红得莫名其妙）✗ | 用**判据自己的扫描面**复核（✗ 不用自己的 grep） | `md-format`：`引用的仓内路径**不存在** …` ⇒ 实测案例：把件搬进 `archive/` 却漏改一处引用（`#1327`）✓ |
| **生成物不手改** | 手改会在下次重生成时丢失，且掩盖真源 | 生成物带 `@generated`／声明"**由 X 生成**" | 台账类：`✗ 台账文件不存在 → 跑 npm run report:gates:update`／不同步 ⇒ `--check` 红 ✓ |
| **降频必须留痕** | 把段移出 PR 档＝**降低了看护**，必须有人签字 | `tier:'full'` ⇒ `FULL_REASONS[id]` 必须有理由 | `validateTiers`：`` `<id>` 标了 tier:'full' 但没写理由（加到 FULL_REASONS ✓ —— 降频必须留痕） `` ✓ |
| **挂起（临时下架）** | 对象在、样本暂缺 ⇒ 不该当"失败"，也不该当"通过" | `SUSPENDED[id]` 必须给 `why` ＋ `until` | 缺任一项 ⇒ 自证格红 ✓；且挂起条目**要写"why 何时失效"**（`why` 会过期 ✓ `#1333`） |
| **`missingSample`（欠账要写清）** | "迁到夹具"要机器可读地写出**缺哪个夹具** | `missingSample:` 值＝**缺引擎侧夹具：<形状>** 或 **缺可复跑命令：<命令＋期望读数>** | 值写不出／写了动作词／不可核对 ⇒ **机械判红** ✓（`#1315`：32 条里 38% 被这把尺筛出是归类错 ✓） |
| **阶段 ≠ 欠账** | 两者的**计数长得一样**，但"寿命与责任完全不同" | 门的**面**用**存在性**表达（如"有 `data/passages.json` 的故事"） | 混记 ⇒ 攒出**无人可还的账** ✗（无门；靠本节 ＋ 评审把关 ✓） |
