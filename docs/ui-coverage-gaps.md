## 未覆盖（如实登记）

| 项 | 原因 | 去向 |
|---|---|---|
| 手机实机 / 触屏手势 | 本环境只有 headless 浏览器与 jsdom，无实机与真手势 | 需人工试玩；本文件登记为「未做」 |
| 多周目 localStorage 粘性（图鉴/结局记录跨周目） | 路线都在干净 localStorage 下跑 | #271（已建票） |
| 对比度 / aria / 语义 | 呈现层迁移未含 a11y 审计 | #272（已建票，4 处 <AA ＋ 缺 lang/aria） |
| 纯审美判断（字体气质、间距美感） | 机器只能判「可读/可达/不溢出」 | 人工试玩 |
| 其它浏览器（Firefox/Safari）与 RTL | 只接 Chrome for Testing | 未建票；如需要可复用 CDP 驱动思路另接 |
| 战斗全谱（多轮/多种结局分支的版面） | 浏览器门只走「一手」 | 低风险：反馈块为同一模板，jsdom 侧覆盖全分支 |

## 新场景如何继续进入这些清单（机制）

1. **静态**：`test/integrity.mjs` 段落登记门——新增段落未写进 `docs/ui-inventory.md` 即红；
2. **渲染/交互**：`test/render-all.mjs` 与 `test/coverage.mjs` 自动纳入新段落（无需手工登记），未点过的链接须命中白名单规则；
3. **真浏览器**：`test/browser.mjs` 的场景列表是**显式白名单**（4 个代表场景）——若新增段落引入**新的交互形态**（新的共用组件），需要把该场景加进列表；仅新增同类段落则无需改动（模板等价类已覆盖）；
4. **存档**：`test/fixtures/saves/` 新增历史形状即自动进入 `rules.mjs`/`saveui.mjs` 两个矩阵。
