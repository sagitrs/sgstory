# 实现路线表（口径与出生规则）

来源：父票 `#1184` 流四（甲先行：行为路线表只读先出；乙：退役纪律）。本页只写**口径**，
不列第二份表——**真相在机器登记面** `scripts/lib/route-registry.mjs` 的 `ROUTES` 数组。

## 人怎么查表，机器怎么查表

人从本页进，读口径与出生规则；要看具体某条行为的路线，去 `scripts/lib/route-registry.mjs` 的 `ROUTES`。
机器（判据件 `test/route-registry.mjs`）也从那个数组进。入口不同，真相一处。

## 这张表登记什么

登记"同一件行为有多条实现路线"的地方。每条表项写清四件事：

1. **路线清单**：按优先级排列，每条写形态与"怎么判它命中"；
2. **兜底语义**：全不命中时会发生什么（这一条最容易被漏，漏了就会出现"改了不生效"）；
3. **退出条件**：旧路线什么时候可以退（退的时候要做什么，见下面的退役纪律）；
4. **票号**：这条级联是哪张票定下的。

## 出生规则（表即登记面）

表落成之后，**新增多路线行为必须同片带表项**（含路线清单、兜底语义、退出条件），不带即违例。
违例不靠人盯：判据件的**覆盖格**会抓——检测器认得的形态一旦出现在 `src/**` 而表里没有对应表项，当场红。

同片还要更新**反向核数**：判据件钉住"主干上检测到的现场数"（当前 5）。新增现场必须同片把这个数改掉；
不改则判据件红。这一条是防"检测器抽不到东西、覆盖格变成空转假绿"。

## 检测器认哪些形态（形态匹配，不是语义分析）

首版只覆盖交涉效果那一族，认的形态是"取契约钩子的取值行"：

```
const hook = window.Sg?.story?.socialHooks?.()?.[…]…;
```

形态清单写死在 `scripts/lib/route-registry.mjs` 的 `FORM_PATTERNS`（判据件与人都用它）。认不出的形态
**不算覆盖**，列在那份文件里的 `UNCOVERED`（**带来源**：哪次勘察发现的、为什么首版不做）。

## 退役纪律（乙）

本片不动退役。退役时的做法：把该表项标 `retired`，写清票号与证据（例如"故事侧 `apply` 已清零"），
并在同片把 `routes` 里对应那条去掉或标注。退役若只做一半（旧路线删了、表还挂着），**腐烂格**会报出来。

## 判据面三格加一格

| 格 | 量什么 |
|---|---|
| 覆盖 | 检测到的现场，每一处都在表里 |
| 完读 | 表项字段齐：路线至少两条、退出条件非空且非占位、指向的方法真的在同一文件里 |
| 腐烂 | 表里指的行为已不在（检测不到）即报 |
| 反向核 | 现场数等于钉死值（当前 5），防空转假绿 |
